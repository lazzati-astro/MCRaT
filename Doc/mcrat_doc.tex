\section{Introduction}
The Monte Carlo Radiation Transfer (MCRaT; pronounced \textit{Em-Cee-Rat}) code is a next generation radiation transfer code that can be used to analyze the radiation signature expected from astrophysical outflows. The code is written in C and uses the Message Passing Interface (MPI) library for inter-process communication, the Open Multi-Processor (OpenMP) library for intra-node communication, the GNU Scientific Library, and the HDF5 library for parallel I/O.

MCRaT injects photons into a hydro simulation, using the FLASH or the PLUTO codes, and individually propagates and compton scatters the photons through the fluid until the end of the simulation. This process of injection and propagating occurs for a user specified number of times until there are no more photons to be injected. Users can then construct light curves and spectra with the MCRaT calculated results. The hydro simulation used in this version of MCRaT must be in 2D, however, the photon propagation and scattering is done in 3D by assuming cylindrical symmetry.

The code was initially written in python by Dr.\ Davide Lazzati as a proof of concept. The code was then translated into C by Tyler Parsotan and made to use the OpenMP, MPI, HDF5, and GNU Scientific libraries. MCRaT is highly parallelized and is easy to set up and use.

There are also python files with documented functions to process the MCRaT output located at: \url{https://github.com/parsotat/ProcessMCRaT}.

In using MCRaT and the ProcessMCRaT codes, we ask that you cite the following papers: \cite{MCRaT, parsotan_mcrat, parsotan_var, parsotan_polarization}.

\section{Getting Started}
This section describes how to get the MCRaT code as well as the required libraries necessary to compile MCRaT. This section will also cover the necessary steps to run the compiled MCRaT code. 

\subsection{Required Libraries}
MCRaT requires a number of libraries in order to compile properly. These are:
\begin{itemize}
\item MPI
\item OpenMP
\item GNU Scientific Library (GSL)
\item HDF5
\end{itemize}

The MPI library can be an any implementation such as OpenMPI (\href{http://www.open-mpi.org/}{open-mpi.org}) or one that is specific to a given supercomputer. Following the steps to install the library should allow it to work properly for compiling MCRaT. The OpenMP library (\href{http://www.openmp.org/}{openmp.org}) is automatically included with Intel and GNU compilers. The GNU Scientific Library (GSL) can be downloaded from \href{https://www.gnu.org/software/gsl/}{gnu.org/software/gsl/}. Following the included instructions should install GSL in the default directory, allowing it to be found by the compiler. The HDF5 library can be found at \href{https://support.hdfgroup.org/HDF5/}{support.hdfgroup.org/HDF5/} where version 1.10 or greater should be downloaded and installed. The parallel portion of HDF5 needs to also be installed which is included in the instructions for installing HDF5.

\subsection{Downloading and Compiling MCRaT}
Once the required libraries have been installed, the current MCRaT code can be downloaded from \href{https://github.com/lazzati-astro/MCRaT/tree/master/HYBRID_PARALLEL_KN}{github.com/lazzati-astro/MCRaT/}. There is a Makefile which  makes compiling the code significantly easier. In the directory that all the MCRaT files were downloaded into, simply typing \texttt{make} will compile the MCRaT code into a binary file called \texttt{MCRAT}. Typing \texttt{make MERGE} will compile the included MCRaT post-processing code, which will be covered in later in this section, into a binary file called \texttt{MERGE}.

The Makefile has to be configured for a variety of specifics related to the user's system. The \texttt{CC} option in the makefile can be changed to the user's compiler of choice such as gcc or icc. The \texttt{HDF\_INSTALL} line is set to the directory that the HDF5 library is installed in. The \texttt{EXTLIB} line is set to the directories of any external libraries that the user may have. For example, if the GSL library cannot be found by the compiler, the user can put the directory of the library in this line of the Makefile in order to properly compile MCRaT. The \texttt{CFLAGS} feeds any compiler options to the compiler such as optimizations, and the switch to compile MCRaT with OpenMP capabilities, which is necessary to exploiting the hybrid parallelization available in the code. If the user is using gcc, the \texttt{-fopenmp} does not need to be changed, however, if the user is using icc, \texttt{-fopenmp} needs to be changed to \texttt{-qopenmp}. The \texttt{INCLUDE} line can be changed to include any \texttt{include/} directories to help the compiler, and the same for the \texttt{LIBSHDF} in relation to any shared libraries. The \texttt{LIB}, \texttt{DEPS}, and \texttt{OBJ} lines should not need to be changed. Once the lines in the Makefile appropriately reflect the users configurations, typing \texttt{make} and \texttt{make MERGE} should properly compile the MCRaT code as well as its post-processing code, \texttt{MERGE}.

\subsection{The mcrat\_input.h file}
Once compilation is successful, the user will need to decide where MCRaT's output will go. The user needs to make a directory within the directory that contains the hydro simulation frames. This subdirectory is where the parameter file for MCRaT must be placed. This is the same directory in which MCRaT will do all of its work, including making its own directories and output files within the aforementioned directories. Once this directory is created, the user must modify the \texttt{mcrat\_input.h} file in order for the code to know where to find all the hydro files and the MCRaT parameter file. The constant \texttt{FILEPATH} should be modified with the directory of the flash simulation files while the constant \texttt{FILEROOT} should contain the name of the hydro simulation files without any frame numbers. Since the FLASH and PLUTO-CHOMBO simulation files are typically hdf5 files, MCRaT not need the file extension explicitly. The constant \texttt{MC\_PATH} should be the name of the directory, located within the \texttt{FILEPATH} directory, that holds the MCRaT parameter file named \texttt{mc.par}. An example file structure, with the values for each variable in MCRaT, is shown below: \\

The other variable that can be changed in MCRaT is \texttt{SIMULATION\_TYPE} which should be set as \texttt{SCIENCE}, if using MCRaT for a production run, or \texttt{SPHERICAL\_OUTFLOW}/\texttt{CYLINDRICAL\_OUTFLOW}/\texttt{STRUCTURED\_SPHERICAL\_OUTFLOW} which is for testing MCRaT with these types of outflows (which will be covered in a later section), or \texttt{CUSTOM\_OUTFLOW} for imposing a user-defined analytic outflow (see Section \ref{custom_outflow}). Once all the variables have been appropriately changed, by replacing the strings appropriately in the \texttt{mcrat.h} file, the code needs to be recompiled.

Additionally, there are a number of switches that the user can specify to the program to tell it whether they want to consider the effects of polarization, with the \texttt{STOKES\_SWITCH}, and one that specifies whether the user wants MCRaT to save the comoving 4 momenta of each photon, with the \texttt{COMV\_SWITCH}. These switches can be set to \texttt{OFF}, which means do not save the comoving 4 momenta and/or save and consider the effects of polarization, or they can be set to \texttt{ON}, which tells the program to consider polarization and/or save the stokes parameter associated with each photon or save each photon's 4 momentum.

The \texttt{SIM\_SWITCH} tells MCRaT what hydro simulation is being used. The options are \texttt{FLASH} and \texttt{PLUTO\_CHOMBO}, for the FLASH hydrodynamic code and the PLUTO hydro code with CHOMBO AMR respectively. The switch \texttt{DIM\_SWITCH} tells MCRaT the dimensionality of the hydro simulation that is used. This switch can be set to \texttt{TWO}, for 2D, \texttt{TWO\_POINT\_FIVE}, for 2.5D, or \texttt{THREE}, for 3D. The geometry can also be specified through the \texttt{GEOMETRY} define statement. The options are \texttt{SPHERICAL}, \texttt{CARTESIAN}, \texttt{CYLINDRICAL}, and \texttt{POLAR}. The length, pressure, and density scales of the hydro simulation also has to be specified by setting the values of \texttt{HYDRO\_L\_SCALE}, \texttt{HYDRO\_P\_SCALE}, and \texttt{HYDRO\_D\_SCALE}, respectively, to the normalization that is used in the hydro simulation.

In order to enable the consideration of thermal synchrotron photons in the MCRaT simulation the \texttt{CYCLOSYNCHROTRON\_SWITCH} needs to be set to \texttt{ON}, otherwise this switch should be set to \texttt{OFF}. If it is set to be \texttt{ON}, the user needs to define other variables. One variable that needs to be defined is \texttt{CYCLOSYNCHROTRON\_REBIN\_E\_PERC} which provides MCRaT with an upper limit for the number of synchrotron photons to emit. This quantity is calculated as the percentage of the maximum number of photons the user wants injected (see the \texttt{[MCRaT Photon Block]} portion of the example mc.par file in section \ref{mc.par}). If \texttt{CYCLOSYNCHROTRON\_REBIN\_E\_PERC} is set to 0.5 and the value of the 17$^\textrm{th}$ line is 3000, the upper limit for the number of synchrotron emitted photons is 1500. This variable also defines the number of energy bins that MCRaT will create when it rebins the synchrotron photons, thus in the aforementioned example, the number of energy bins that the photons will be rebinned into is 1500 as well. MCRaT will also rebin the photons into spatial bins and the size of these bins are specified using the \texttt{CYCLOSYNCHROTRON\_REBIN\_ANG} variable which has units of degrees. In considering synchrotron emission, the user needs to specify how the magnetic field is calculated. This is done through the \texttt{B\_FIELD\_CALC} switch which can be set to: \texttt{INTERNAL\_E}, where the magnetic energy density is set equal to the internal energy of the outflow, \texttt{TOTAL\_E}, where the magnetic field is calculated from the total energy of the outflow, or \texttt{SIMULATION} where the code uses the magnitude of the magnetic field that is acquired from a simulation. If \texttt{B\_FIELD\_CALC} is set to \texttt{TOTAL\_E} or \texttt{INTERNAL\_E}, the user needs to set the \texttt{EPSILON\_B} switch, which represents the fraction of the total outflow energy that is in the magnetic field. More information about the implementation of thermal synchrotron emission in the algorithm of the code can be found in section \ref{algorithm}. More information regarding the physics of the implementation of thermal synchrotron emission and absorption can be found in section \ref{cyclo-synch}. MCRaT also provides a non-thermal synchrotron capability, enabled with \texttt{SYNCHROTRON\_SWITCH} ON together with a power-law \texttt{NONTHERMAL\_E\_DIST} and the associated electron-distribution and scattering-bias macros. Because this capability is substantial, its switches and their required companions are documented together in Section \ref{sec:operation}; the parameter table below lists them for completeness.

Another helpful switch is the \texttt{SAVE\_TYPE} switch, which tells MCRaT to include the photon type in the saved datasets.

\subsection{The \mcrat{} Parameter File} \label{mc.par}
\mcrat{} requires the user to provide information in the form of a parameter file named \texttt{mc.par} which should be placed in the appropriate directory, as is described in the previous section. An example \texttt{mc.par} file, named \texttt{sample\_mc.par} is included in the \mcrat{} github repository. An example with a description of each line, is as follows:

{\small
\begin{verbatim}
[Hydro/MHD Simulation Block]

5.        # Number of frames per second of hydro simulation (likely always the same)
3000	  # Last available hydro simulation frame  (get from the last file in the data folder)
0 5e12	  # Max r0 coordinate limits of hydro simulation
0 2.5e13  # Max r1 coordinate limit of hydro simulation
0 2e13	  # Max r2 coordinate limit of hydro simulation (if simulation is 3D)

[MCRaT Injection Angles Block]

0.                # The minimum off-axis angle to inject photons (in degrees)
6.                # The maximum off-axis angle to inject photons (in degrees)
3.			      # Number of angle bins to consider
200 200 200       # Frame at which photon injection starts for each angle bin
199 199 299       # Number of frames for which photons are injected for each angle bin
1e11 1.5e12 2e12  # The radius at which the photons are injected for each angle bin

[MCRaT Photon Block]

b		# Type of spectrum we inject with, w=wien b=blackbody, c=custom spectrum
1000		# Min number of photons
5000		# Max number of photons

[Initialization/Continuation Block]

i		# Initialize or continue simulation (i=initialize (delete all files) c=continue) 
\end{verbatim}
}

The format of the \texttt{mc.par} file must follow what is shown above with each block in its respective order and each block title separated by a blank line from the contents of the block. Furthermore, the coordinate limits for r2 must always be there, even if the hydro simulation that is being analyzed with \mcrat{} is in 2D. The entries for each line that takes multiple values, such as the coordinate limits, must have each value separated by a space. 

The first block provides information on the hydro/MHD simulation that \mcrat{} is analyzing. The first line denotes the number of hydro frames per second, or fps. The second line provides the file number of the last hydro simulation frame available in the analysis. The next three lines provide the lower and upper limits of the hydro coordinate. Even if the hydro simulation that is being analyzed is in 2D, the last line must still be there. In the example above, the r0 coordinate extends from 0 to 5e12 in the units provided by \texttt{HYDRO\_L\_SCALE} or, in the case of angles, the units used by the hydro simulation. The table below denotes what coordinates r0, r1, and r2 correspond to for each coordinate system and number of dimensions as well as their corresponding units. 

\begin{figure}[h!]
\centering
\begin{tabular}{|c|c|c|}
\hline
 & 2D & 3D \\
\hline
Coordinate System & (r0, r1, r2) & (r0, r1, r2) \\
\hline
Cartesian & (x,y,-) & (x,y,z) \\
\hline
Spherical & (r,$\theta$, -) & (r,$\theta$, $\phi$) \\
\hline
Polar & - & (r, $\phi$, z) \\
\hline
Cylindrical & (r,z) & - \\

\end{tabular}

The second block, called the \texttt{[MCRaT Injection Angles Block]}, tells \mcrat{} what angle ranges (in degrees) it should consider when injecting photons, as provided by the first two lines of the block, and what radii to inject photons for each angle range. The third line of this block denotes the number of angle ranges. In this example, we want \mcrat{} to inject photons from 0$\circ$-6$\circ$ and we want there to be 3 angle bins. For each angle bin, we provide the frame from which the photon injections will start, $\mathrm{f_{start}}$, the number of frames that we will inject photons into, df, and the radius where the photons will be injected in the frame, $R_\mathrm{inj}$. Thus, in the example provided, there have to be 3 numbers provided in each of the last 3 lines of the block. If we wanted N angle bins, then the next 3 lines should contain N numbers for each angle bin. Each number needs to be separated by a space.

These last 3 lines dictate what time in the simulation you begin injecting photons. This is calculated as 
\[
t_\mathrm{start}=\frac{\mathrm{f_{start}}}{\mathrm{fps}}-\frac{R_\mathrm{inj}}{c}
\]
Building on the above formula, the time in which photons stop being injected are calculated as
\[
t_\mathrm{end}=\frac{\mathrm{f_{start}}+\mathrm{df}}{\mathrm{fps}}-\frac{R_\mathrm{inj}}{c}
\]
These calculations are the same for photons injected at all angles. The number of angle bins and the number of frames that photons will be injected into (for each angle bin) are important for \mcrat{}'s parallelism. This will be covered in the next section. 

In the next block, labeled \texttt{[MCRaT Photon Block]}, we specify the initial condition of the \mcrat{} simulation and the number of photons that we want \mcrat{} to consider. The first line denotes whether we want the injected photons to be drawn from a blackbody or Wien spectrum, based on the optical depth being either $\gtrsim 10^3$ or $\sim 100$, respectively. A third option selects the user-defined custom spectrum (Section \ref{custom_spectrum}); see that section for the behaviour of \texttt{custom\_photon\_sampler}. The next two lines specify the minimum and maximum number of photons that \mcrat{} injects into a given frame, which helps to balance Poisson error from the Monte Carlo method with the run time of the \mcrat{} code. 

The final block allows the user to continue the \mcrat{} code from a previous point, if the value is set to ``c'', or it allows the user to initalize (by erasing the full working directory of \mcrat{}) or start a simulation by setting it to ``i''. \hl{\bf This is an important parameter to check to prevent accidentally erasing work that has already been done.}


\subsection{Understanding \mcrat{}'s Parallelism}
The first step that \mcrat{} takes in breaking up the problem is breaking it up into pieces based on the range of angles that photons will be injected into, which the user specifies in the \texttt{[MCRaT Injection Angles Block]} in the \texttt{mc.par} file. As the example \texttt{mc.par} above shows, \mcrat{} will break up the problem into 3 pieces initially. Then, for each angle range ($0^\circ-2^\circ$, $2^\circ-4^\circ$, etc.) the code will then break up the problem based upon how many times photons will be injected, which is 1 plus the values provided in the \texttt{mc.par} file; this is because the photons are injected in the frames $[\mathrm{f_{start}}, \mathrm{f_{start}}+1, ..., \mathrm{f_{start}}+\mathrm{df}-1, \mathrm{f_{start}}+\mathrm{df}]$, which gives us this n+1 behavior. These pieces of information are important for understanding how the processes are divided with \mcrat{}. An example will be given in the next section.

\subsection{Running \mcrat{}}
In this section we show how to run \mcrat{} and allocate the appropriate number of cores in order to optimize \mcrat{}'s parallelism. We will use the example \texttt{mc.par} file in Section \ref{mc.par} for this section. 

Running the \mcrat{} code is as simple as doing \texttt{mpiexec -np N ./MCRAT} where N is the total number of MPI processes that will be created. The OpenMP parallelism is controlled by setting the OpenMP environment variable \texttt{OMP\_NUM\_THREADS}. We recommended that \texttt{OMP\_NUM\_THREADS} be set to $1$ for a newly started \mcrat{} simulation, which essentially turns off the OpenMP parallelism. 

 The total number of MPI processes, $N$, is initially divided by the set of angles that photons will be injected into. For the example \texttt{mc.par}, there are $3$ sets of angles that will be considered which leads to the N MPI process initially being divided by 3. The $N_\theta=N/3$ MPI processes will then be used to inject photons in the user specified frames in parallel. The example \texttt{mc.par} file shows that for the first angle bin there will be $199+1$ photon injections, as was described in the last section. Thus, the number of frames that each MPI process will inject photons into becomes $\mathrm{f_{inj}}=(199+1)/N_\theta$. If we set $N=150$, $N_\theta=50$ and the number of frames that each MPI process will inject photons into becomes $4$. Alternatively, if we want each MPI process to only inject photons into one frame, $N_\theta=200$ which means that $N=600$. Calculating $N$, by following these examples, shows how the problem is broken up between angles and photon injections. If the number of MPI processes available for the user to use does not divide well into the size of the problem, in terms of angle ranges and frames in which photons are injected, \mcrat{} will prioritize breaking up the problem evenly based on the set of angles. Thus, $N$ should at least be evenly divisible by the number of angle ranges specified by the \texttt{mc.par}; Once $N_\theta$ is calculated, \mcrat{} will distribute the number of frames in which photons will be injected accordingly to calculate $\mathrm{f_{inj}}$.
 
 Another option, when dealing with a limited number of available cores, is running \mcrat{} on a small portion of the problem. For example instead of doing 3 sets of angles at $2^\circ$ intervals all at once, simply run 1 set of angles from $0^\circ-2^\circ$, and when that simulation is complete run the second set from $2^\circ-4^\circ$, etc. The increased parallelism in decreasing $\mathrm{f_{inj}}$ by using this method may speed up the simulation compared to running the whole problem at once. This is also advantageous due to the fact that as the MPI processes begin to complete their portion of the simulation, the user may restart \mcrat{} using only the appropriate number of MPI processes left that have calculations left to do. Thus, this feature lets a given \mcrat{} simulation (e.g. $0^\circ-2^\circ$) use less MPI processes and resources over time, allowing another full simulation (e.g. $2^\circ-4^\circ$) to start running using the rest of the available resources. We will go over this feature in a later section.
 
 \subsection{\mcrat{} Output Files}
 Once \mcrat{} is run, it will create subdirectories dedicated to the calculations and results of each angle range. Using the example \texttt{mc.par} file, the directory tree will now look like:

 Within each angle subdirectory, each MPI process, labeled process $i$, creates 3 files. The mc\_output\_$i$.log file prints exactly what the \mcrat{} code is doing for that given MPI process. This allows us to monitor the progress of the \mcrat{} simulation. This can be easily done by using Linux commands such as \texttt{less mc\_output\_$i$.log}. The mc\_proc\_$i$.h5 is a HDF5 file that contains all of the calculation results of the \mcrat{} MPI process. The mc\_chkpt\_$i$.dat file contains the necessary data for each MPI process to continue from the last point if \mcrat{} is interrupted for any reason. This is covered in the next section.
 
 When all of the MPI processes in a given angle subdirectory have completed their calculations, they will produce HDF5 files with the results of the calculations for each file in the simulation. The results start with the frame specified in the \texttt{[MCRaT Injection Angles Block]} of the \texttt{mc.par} file and go up to the frame specified in the next line of the \texttt{mc.par} file block. These files will be named \texttt{mcdata\_$f$.h5} where $f$ is the frame number of the hydrodynamic simulation.
 
 \subsection{Restarting \mcrat{}}
 If the \mcrat{} code gets interrupted by running out of allocated time on a cluster or any other type of issue, the code is easily continued. It may also use less MPI processes when it is restarted based on the number of MPI processes in the original simulation run that still have calculations to complete. 
 
 In order to ensure that the code knows to continue a \mcrat{} simulation, the last block of the \texttt{mc.par} file must be set to ``c''. \hl{\bf This is important to check since not changing this parameter means that all of the simulation progress will be erased and a completely new simulation will be started, thus nullifying the attempt to save time and resources by continuing a \mcrat{} simulation.} 
 
Once this parameter has been changed, the user needs to identify how many total MPI processes have completed their calculations. This is done by running"
 \begin{quotation}
\texttt{tail -n 1 dir\_with\_MCRaT\_parameter\_file/angle\_dir/mc\_output\_* |grep "completed" |wc -l}
 \end{quotation}
in each angle range directory created by \mcrat{}. Add all the printed values and subtract from the original number of MPI processes, $N$, that the \mcrat{} simulation was originally started with. This is the number that has to replace $N$ in the new run of \mcrat{}. From here, \mcrat{} automatically distributes the given number of processes among the MPI processes in each angle subdirectory that still need to run calculations.
 
 This feature of only continuing the \mcrat{} simulation with the necessary number of MPI processes means that as the simulation progresses, fewer resources will be used which is invaluable for running jobs in a pipeline type of fashion and for conserving resources such as SBU allocations.
 
 If a certain process is also taking a long time to conduct its simulation it is possible to modify the mc.par file to specify that the simulation should inject fewer photons, to speed up the calculation and force the process' simulation portion to restart. To force the restart, delete that process' mc\_chkpt file and it's  mc\_proc file. This is exactly what the \texttt{mcrat\_msp.sh} shell script does. 
 
 \subsubsection{Using The mcrat\_msp.sh Shell Script}
 The mcrat\_msp.sh shell script determines which \mcrat{} processes have a very large number of scatterings and allows the user to delete those process' mc\_chkpt and mc\_proc files, if the process' photons have undergone a number of scatterings greater than some user specified number of scatterings. This would then force a new restart for those processes with less injected photons. It also allows the user to refine the mc.par file to set a new number of injected photons for these same processes that will be restarted the next time the user starts mcrat with the 'c' flag (to continue a simulation). \hl{\bf This is important to change once \mcrat{} has been restarted and the photons injected. If it isn't, other processes, which don't have so many scatterings, will inject photons within the new range specified by the mc.par file (if applicable, which it should be on a relatively small cluster where the user can't assign one photon injection frame to each process). To do this, once the simulation restarts and is running smoothly, the user has to end it, modify the minimum and maximum range of injected photons to the original numbers, and restart the simulation once again. (We are currently working on a better way of implementing this feature.) The user must remember to reset the restart flag in the mc.par file to 'c' otherwise all the simulation data files will be erased and all progress lost.} Opening the mcrat\_msp.sh file in a text editor will bring up different flags for the shell script and give examples of how to properly use the function.
 
 \subsection{Using Hybrid-Parellelization}
 As was mentioned earlier, it is not advised to enable hybrid parallelization at the start of a new \mcrat{} simulation, especially if limited resource availability is an issue. This is due to the fact that the OpenMP threads may interfere with one another and neighboring MPI processes, thus slowing the overall code. To prevent this, set \texttt{OMP\_NUM\_THREADS} to $1$.
 
 If \mcrat{} is being used to continue a simulation, there is a good chance that some of the MPI processes have finished and the remaining MPI processes are running slower than the rest due to a variety of factors, which will be covered later. This is where hybrid parallelization helps to ensure that \mcrat{} completes its calculations is a reasonable amount of time. These MPI processes can be sped up by using the OpenMP threads. The number of threads per MPI process can be set with the \texttt{OMP\_NUM\_THREADS} parameter. Even in this case, it is important to make sure that threads are not interfering with one another and undermining any potential performance gain.
 
 \subsection{Post-Processing \mcrat{} Data}
 If the user is simply running running a simulation with one angle range under consideration, there is no post-pocessing to be done. The \mcrat{} produced \texttt{mcdata\_$f$.h5} files contain all the information for the photons (which will be covered in the next section).
 
 If not we need to be able to merge all the simulation results for photons injected in all angle ranges; following the example \texttt{mc.par} file, we need to merge the data in angles $0^\circ-2^\circ$, $2^\circ-4^\circ$, etc. This is done is with the MERGE code that is included with \mcrat{}. To run merge, the user simply types \texttt{mpiexec -np N ./MERGE}. In this case N needs to be a multiple of the number of subdirectories the \mcrat{} code has created and it has to be greater than or equal to the number of subdirectories; of course, the larger the number of MPI processes used, the less work each process has to do, making the post-processing code faster. In the example \texttt{mc.par} file there are 3 directories created, so $N$ has to be a multiple of 3 in this case. The minimum value of N can be $3$; however, since the MERGE code is also parallelized with OpenMPI, the larger the number of processes used, the less time it takes to merge all of the \mcrat{} data.  If $N=6$, 3 processes will be allocated to merge the data from the first half of the frames from 200 to 3000, as specified in the \texttt{mc.par} file, and the other 3 will merge the data from the last half of the range of frames. If $N=12$, the number of frames from 200 to 3000 will be divided into quarters and 3 processes will deal with the first quarter, while a second set of 3 processes will deal with the second quarter, so on and so forth. 
 
 The merged data is placed into another folder that the code creates named \texttt{ALL\_DATA/}. \newline
 
 \noindent The standard work flow for \mcrat{} is as follows:
 \begin{itemize}
 \item[1.] Compile the \mcrat{} and MERGE codes
 \item[2.] Write the \texttt{mc.par} file in the correct directory
 \item[3.] Run \mcrat{}
 \item[4.] Use MERGE to post-process the \mcrat{} results
 \end{itemize}
 
 This work flow can be practiced using a spherical or cylindrical outflow problem that is included in \mcrat{}. These simulations can be run using any hydro simulation because \mcrat{} reads in the data from the hydro simulation and over writes it (in memory, not in the hydro file) with the correct values assuming a spherical or cylindrical outflow.
 
 In order to run a spherical outflow simulation simply change the \texttt{SIMULATION\_TYPE} parameter in \texttt{mcrat\_input.h} file to \texttt{SPHERICAL\_OUTFLOW}. Then recompile the code and run it as we outlined previously. In order to run a cylindrical outflow simulation, change the \texttt{SIMULATION\_TYPE} parameter to \texttt{CYLINDRICAL\_OUTFLOW}. These test simulations allow the user to become acquainted with \mcrat{} and test that \mcrat{} produces the expected results for these type of outflows. A third option, the custom outflow (Section \ref{custom_outflow}), lets the user impose an arbitrary analytic outflow by the same overwrite-in-memory mechanism; this is selected with \texttt{SIMULATION\_TYPE CUSTOM\_OUTFLOW}.
 

\section{The \mcrat{} Code}
This section describes the algorithm and output of \mcrat{}. It will cover the steps that \mcrat{} takes to inject and scatter photons. A more in depth description of the physics is included later in this manual.

\subsection{Assumptions about the Hydro Simulation}
\mcrat{} has to make two important assumptions about the hydro simulation. These assumptions are that:
\begin{itemize}
\item[1.] The velocity in the hydro simulation is normalized by the speed of light, $c$. 
\item[2.] The pressure is radiation dominated. As such, we can calculate the temperature using $p=\frac{1}{3}aT^4$, where $a$ is the radiation density constant.
\end{itemize}

\subsection{Algorithm}\label{algorithm}

\mcrat{} first reads the data from the \texttt{mc.par} file and then appropriately divides the MPI processes based on the number of angle ranges, if starting a new simulation, or, for continuing a simulation, reads the mc\_chkpt file in each directory to determine which MPI processes still have work to complete and then distributes the MPI processes. 

Each MPI process is assigned a range of frames in which the process injects photons into and then propagates through all the hydro simulation frames until the last hydro simulation frame, which is specified in the \texttt{mc.par} file. The photons have a \texttt{photon} data structure that fully describes each photon. This includes the photon's lab frame 4-momenta, the x, y, and z coordinates of the photon, the Stokes parameters of the photon, the weight of the photon, the number of times the photon has scattered, and the index of the hydro fluid element that the photon is located within.

In order to inject the photons, \mcrat{} reads in the first hydro frame, that the photons will be injected into, and chooses hydro elements that have radii, $r$, such that $R_\mathrm{inj}-c/(2*\mathrm{fps}) < r < R_\mathrm{inj}+c/(2*\mathrm{fps})$, where $c$ is the speed of light, $R_\mathrm{inj}$ is the injection radius and $\mathrm{fps}$ is the hydro simulation frames per second, both specified in \texttt{mc.par}. These hydro elements also have to be within the angle range that the MPI process is injecting photons within. Thus, we choose a slab of hydro elements to inject photons into. The number of photons that would be expected from the $i^\mathrm{th}$ hydro element, $n_i$, is calculated using the energy density of the element and by assuming a weight for each \mcrat{} photon. This is further explained in Section \ref{inj}. Once the expected number of photons is calculated, the actual number is acquired by assuming that the photon injection is random, which means that we acquire the actual number of photons injected into the $i^\mathrm{th}$ hydro element, $N_i$ by randomly drawing from a Poisson distribution with a mean of $n_i$. The total number of photons that would be injected across all the chosen hydro elements becomes $N=\sum N_i$. If $N$ is within the minimum and maximum number of photons that the user wants, which is specified in the \texttt{mc.par} file, the calculation for the number of photons is complete. If not, then the code continues to recalculates $n_i$ using a new weight for each photon, then recalculates $N_i$ and $N$, and after rechecks so see if $N$ is within the user specified number of photons again. This loop is exited when $N$ falls within the user specified number of desired photons. If the code needs to inject more photons to meet this condition, it will adjust the weights to be smaller and vice versa.

Once $N$ and $N_i$ have been determined, the $N_i$ photons are randomly placed within the $i^\mathrm{th}$ hydro element, with a random azimuthal angle uniformly distributed between $0$ and $2\pi$ (since we assume cylindrical symmetry for the 2D hydro simulation), and they are given an energy based on the comoving temperature of the hydro element, thus the photons are injected in the comoving frame of the outflow. If the user specified that the photons should be injected with a Wien spectrum then the frequencies, $\nu$, are assigned to the $N_i$ photons by sampling from a Wien spectrum defined by the $i^\mathrm{th}$ fluid element's comoving temperature. The same thing is done with a Blackbody spectrum if the user specified that the photons should be injected as a Blackbody spectrum. This sampling is done by using the acceptance-rejection Monte Carlo sampling of the spectra. Alternatively, if the user has selected the custom spectrum, the photon energy (and optionally its direction and polarization) is instead assigned by the user-defined custom\_photon\_sampler routine described in Section \ref{custom_spectrum}; all other aspects of injection proceed identically.

For their 4-momenta, the photons are assigned a random azimuthal angle, $\phi$, from a uniform distribution between $0$ and $2\pi$, as well as a polar angle, which is calculated as $\theta=\arccos(2\xi-1)$, where $\xi$ is a random number drawn from a uniform distribution between 0 and 1. The $i^\mathrm{th}$ injected photon 4-momentum becomes:
\[
p^\mu_i=\frac{h\nu_i}{c}\begin{pmatrix}
1 \\ \sin(\theta_i) \cos(\phi_i) \\ \sin(\theta_i) \sin(\phi_i) \\ \cos(\theta_i)
\end{pmatrix}
\]

After the 4-momenta are set, the photons are boosted into the lab (observer) frame using the velocity of the fluid element that the photons are located within. The lab frame 4-momenta are saved to each photon's \texttt{photon} data structure, as well as the photon's position and weight. The number of scatterings is initialized to 0 and the stokes parameters are initialized to 0 except for s0 which is set to 1. These photons are also denoted as type 'i', since they are the original injected photons.

Once the photons have been injected into the simulation and their 4-momenta have been determined, the scattering process through the hydrodynamic (HD) simulation occurs. \mcrat{} reads in a HD simulation frame, starting from the frame in which the photons were initially injected into up until the last HD simulation frame available, and determines which HD fluid elements each photon is in. \mcrat{} then calculates the scattering path length of each photon. In order to reduce memory and optimize the code, \mcrat{} determines the minimum and maximum radii of the photons, $R_\mathrm{min}$ and $R_\mathrm{max}$ respectively, and selects a slab of hydro fluid elements with radii, $r_i$ such that 
\[
R_\mathrm{min}-\alpha\frac{c}{\mathrm{fps}} < r_i < R_\mathrm{max}+\alpha\frac{c}{\mathrm{fps}} 
\] 
where $\alpha$ is a multiplicative factor that can be increased to ensure that the number of chosen hydro elements is greater than 0. The code finds which fluid element each photon is located within, and saves the index to the \texttt{photon} data structure. This data field only gets updated if the photon propagates outside of the fluid element. If this happens, then the code finds and saves the index of the new fluid element that the photon is located within. Sometimes, the code is not able to find a fluid block that a given photon is located within. This may happen due to a photon propagating outside of the range of radii of the chosen slab of hydro element, and is very rare. To deal with this, we set the scattering path length, $l$, to an arbitrary large value to ensure that the photon doesn't scatter, which would inaccurately change its energy. If the fluid element is correctly identified, the scattering path length is calculated as  
\[
l=-\frac{m_p}{\rho\sigma_\mathrm{T}(1-\beta\cos\theta_{fp})}\ln\xi
\]
where we have inverted the exponential probability distribution for a photon scattering in a medium. Here, $\xi$ is a random number uniformly distributed between 0 and 1, $m_p$ is the proton mass, $\sigma_\mathrm{T}$ is the Thompson cross section, $\rho$ is the lab frame density of the hydro fluid element that the photon is located within, $\beta$ is the velocity of the fluid element normalized by the speed of light (this should be already done in the hydro code), and $\theta_{fp}$ is the angle between the fluid element's and the photon's velocity vectors. From $l$, the time for each photon to scatter is calculated as $t_\mathrm{s}=l/c$, where $c$ is the speed of light. The photon with the smallest $t_s$ is assumed to scatter first, however that is not necessarily true since we use the full Klein-Nishina cross section in the electron rest frame to actually determine if the scattering occurs. The positions of all the photons are advanced by the time for the photon of interest to scatter, $t_s$.

In determining whether a photon will scatter or not, we first boost the chosen photon with the smallest $t_s$ to the fluid rest frame and produce an electron by sampling the Maxwell-Boltzmann or Maxwell-Juttner distributions for non-relativistic and relativistic gases. The comoving temperature, $T_i'$, of the fluid element is used to distinguish between which distribution is used. If $T_i' \ge 1 \times 10^7$ K the Maxwell-Juttner distribution is used, otherwise the Maxwell-Boltzmann distribution is used. When the Maxwell-Boltzmann distribution is used we choose 3 random x, y and z velocities from gaussian distributions with a standard deviation of $k_BT_i'/m_e$, where $k_B$ is the Boltzmann constant and $m_e$ is the mass of the electron. The velocities are normalized by the speed of light and used to calculate the Lorentz factor of the electron in the fluid frame. To get the full 4-mometum of the electron, the azimuthal angle of the electron's direction fo travel is drawn from a uniform distribution between 0 and $2\pi$ and the relative polar angle (between the electron velocity vector and the incoming photon's velocity vector) is acquired by acceptance-rejection sampling the distribution $(1-\beta\cos(\theta))\sin(\theta) $. We then perform rotations based on the velocity vector of the photon that will scatter to ensure that the electron velocity is oriented appropriately relative to the photon's velocity.

Once the electron has been initialized, the photon and the electron are boosted into the electron rest frame. Then the photon velocity vector is rotated such that it is moving directly along the x-axis towards the stationary electron at the origin of the coordinate system. We then use the Klein Nishina (KN) cross section including the effects of polarization, $\sigma_\mathrm{KN}$, to determine if the photon will actually scatter. The ratio $\sigma_\mathrm{KN}/\sigma_T$ is calculated and a random number, $\xi$, from a uniform distribution between 0 and 1 is drawn. If $\xi >\sigma_\mathrm{KN}/\sigma_T $ the photon does not scatter, otherwise it does scatter with the electron. 

If the photon scatters with the electron, a random $\theta$ and $\phi$ are drawn from their respective distributions that are derived from the KN cross section including polarization. The photon's new 4-momentum and stokes parameters are calculated and then the scattered photon is rotated to its original orientation with respect to the previously stationary electron. The photon is then Lorentz boosted twice, back to the lab frame. The process of keeping track of the Stokes parameters and calculating them is covered in \autoref{pol}.

If the photon does not scatter, then the next photon with the second shortest time to scatter is chosen and the process to create an electron and determine if the photon will scatter repeats. This loop continues until a photon scatters or all of the photons have been determined to not scatter. 

While this loop is occurring, the photons in the simulation are being propagated incrementally by the change in scattering time for each photon until the time for the next hydro simulation frame is reached. The same thing occurs when a photon does scatter, the photons get propagated through space using the scattering time and the process of determining each photons' time to scatter, etc. repeats until the time corresponding to the next hydro frame is reached.

Once the time limit for the next hydro fluid frame is reached, \mcrat{} saves all the photons' information in the \texttt{photon} data structure into the HDF5 file under a group with the same HD frame number that the photons were being scattered in. Once the data is written, a checkpoint file is saved for \mcrat{} to be able to continue the simulation if it were interrupted. Then, the next simulation frame is loaded and the process of determining photons' time to scatter, actual probability of scattering and resulting scattered 4-momenta until the next HD simulation frame time is reached. This repeats until the last HD simulation frame is reached. 

If the user is taking thermal synchrotron photons under consideration, then the thermal synchrotron photons are emitted into the flow in the frame after the initial set of photons are injected into the flow. The emission is done in the comoving frame of the flow. The number of photons emitted is calculated and iterated over in the same manner as the injection of photons. In the thermal synchrotron case the number of photons emitted in the $i^\mathrm{th}$ fluid element is calculated by integrating the low energy tail of the blackbody spectrum divided by $h\nu$, corresponding to the temperature of that fluid element, from 10 Hz to the cyclotron frequency of that cell. Another difference is that the total number of photons is limited by the \texttt{CYCLOSYNCHROTRON\_REBIN\_E\_PERC} switch times the value of the 17$^\textrm{th}$ line in the \texttt{MCPAR} file. The last major difference is that the emitted synchrotron photons are set to have the energy corresponding to the cyclotron frequency of the $i^\mathrm{th}$ fluid element that they are placed in.

These synchrotron photons are placed at the center of their corresponding fluid elements. If, when \mcrat{} is calculating the scattering path length of each photon, one of these synchrotron photons is determined to scatter, it is placed at a random position within its cell, then another synchrotron photon is created to replace it in the pool of photons at the center of the fluid element. After, the scattering process occurs.

In order to keep the number of photons manageable, \mcrat{} checks the number of scattered synchrotron photons every 1000 scatterings. If the number is smaller than the 17$^\textrm{th}$ line in the \texttt{MCPAR} file (the maximum number of photons the user wants injected in each frame) then nothing happens, but if the number if larger then \mcrat{} rebins the photons. The rebinning is done in energy and in space with the number of energy bins, $N_E$, calculated as \texttt{CYCLOSYNCHROTRON\_REBIN\_E\_PERC}$\times N_\mathrm{max}$, where \texttt{CYCLOSYNCHROTRON\_REBIN\_E\_PERC} is a switch that the user sets in the \texttt{mcrat\_input.h} file and $N_\mathrm{max}$ is the value of the 17$^\textrm{th}$ line in the \texttt{MCPAR} file. The number of spatial bins, $N_\theta$, is calculated as $\Delta \theta/$\texttt{CYCLOSYNCHROTRON\_REBIN\_ANG}, where $\Delta \theta/$\texttt{CYCLOSYNCHROTRON\_REBIN\_ANG} is the angular difference between the largest photon location in theta and the smallest photon location in theta and \texttt{CYCLOSYNCHROTRON\_REBIN\_ANG} is is a switch that the user sets in the \texttt{mcrat\_input.h} file. $\Delta \theta/$\texttt{CYCLOSYNCHROTRON\_REBIN\_ANG} will most likely be the range of angles that the photons are injected into so that use can anticipate this value a priori. If $N_E\times N_\theta>N_\mathrm{max}$, then \mcrat{} will throw an error pointing this out. Otherwise the rebinning occurs by averaging photons' values within a given energy and spatial bin. The scattering and general steps of \mcrat{} continues and iterates until the time for the next hydro fluid frame is reached. Before the photons are saved, any photons that have energies that are smaller than the energy corresponding to the thermal synchrotron energy of the cell they are located in gets absorbed and becomes a null photon. 

If the MPI process has more photons to inject, then the process of injecting/emitting the photons into the next frame and propagating those photons through the hydro simulation repeats. If all of the MPI processes have finished injecting and propagating photons for the hydro simulation frames assigned to them, the code combines all of the photons' data from each MPI process into \texttt{mcdata\_$i$.h5} files where $i$ is the hydro simulation frame number. The output is covered in the next section.

\subsection{Saved Quantities} 

Each \mcrat{} MPI process outputs 3 files. These files are named \texttt{mc\_proc\_$i$.h5}, \texttt{mc\_chkpt\_$i$.dat}, and \texttt{mc\_output\_$i$.log} where $i$ is the number for the MPI process producing those files. As the end of the simulation, \mcrat{} produces the actual data files named \texttt{mcdata\_$f$.h5} where $f$ is the hydro simulation file frame.

The \texttt{mc\_chkpt\_$i$.dat} file is a binary file that contains the data from the MPI process that allows it to continue the simulation if \mcrat{} gets interrupted for any reason. This information is: the MPI process' range of hydro frames to inject photons into, the frame that the current set of photons were injected in, the frame in which the photons were recently scattered in, the current time of the \mcrat{} simulation, the number of photons that the code is keeping track of, and the \texttt{photon} data structure for each photon in the simulation.

The \texttt{mc\_proc\_$i$.h5} file is a HDF5 file that contains all the data for the photons that the $i^\mathrm{th}$ MPI process injects and propagates through the hydro simulation. The data is organized by the hydro simulation frame which constitutes a HDF5 group. Within the group, there are the following datasets, depending on if \texttt{STOKES\_SWITCH}, \texttt{COMV\_SWITCH} or \texttt{SAVE\_TYPE} ids are set to ON or OFF.
\begin{itemize}
\item PW - The photon weight for any photons that were injected into the frame. If there were no photons injected, then this data set does not exist.
\item P0 - the energy of the photons (in erg/c)
\item P1 - the magnitude of the photons' 4-momentum in the x direction (in erg/c)
\item P2 - the magnitude of the photons' 4-momentum in the y direction  (in erg/c)
\item P3 - the magnitude of the photons' 4-momentum in the z direction (in erg/c)
\item COMV\_P0 - the comoving energy of the photons (in erg/c)
\item COMV\_P1 - the magnitude of the photons' comoving 4-momentum in the x direction (in erg/c)
\item COMV\_P2 - the magnitude of the photons' comoving 4-momentum in the y direction  (in erg/c)
\item COMV\_P3 - the magnitude of the photons' comoving 4-momentum in the z direction (in erg/c)
\item R0 - the x position of the photons (in cm)
\item R1 - the y position of the photons (in cm)
\item R2 - the z position of the photons (in cm)
\item S0 - the normalized I Stokes parameter for the photons
\item S1 - the normalized Q Stokes parameter for the photons
\item S2 - the normalized U Stokes parameter for the photons
\item S3 - the normalized V Stokes parameter for the photons
\item NS - the cumulative number of scattering each photon has undergone
\item PT - the photon type of each photon (these are saved as ASCII decimal numbers that can be mapped to a character)
\end{itemize}

The photon types are 'i' (injected photons, including any injected via the custom spectrum sampler of Section \ref{custom_spectrum}), 's' (emitted synchrotron photons), 'p' (synchrotron pool photons), 'c' (previously-scattered cyclo-synchrotron photons carried across frames), 'k' (Comptonized photons), 'r' (rebinned photons), and 'N' (null photons).

These data sets include information for all of the photons after they were scattered through the given hydro simulation frame. The order of the data is based on the chronological order in which each set of photons were injected. For the example \texttt{mc.par} file in \autoref{mc.par}, if the user uses $N$ MPI processes such that each process injects photons into 2 frames, the \texttt{mc\_proc\_$0$.h5} file would look like:
\begin{figure}[h!]
 \dirtree{%
 .1 \texttt{mc\_proc\_0.h5}.
  .2 200.
  .3 PW.
  .3 P0.
  .3 $\colon$.
  .3 NS.
 .2 201.
   .3 PW.
   .3 P0.
   .3 $\colon$.
   .3 NS.
 .2 202. 
 	.3 P0.
    .3 $\colon$.
    .3 NS.
 } 
 \end{figure}
 
\newpage where all the datasets in group 200 would have only $n_{0}$ elements, where $n_{0}$ is the number of photons first injected into hydro frame 200. If we let $n_{1}$ be the number of photons injected in frame 201, the dataset PW in group 201 will have $n_{1}$ elements while the rest of the datasets will have $n_{0}$ elements, corresponding to the information for the photons first injected in frame 200 that are propagated through frame 201, \textit{followed by} $n_{1}$ elements for the newly injected photons in frame 201. 

The last file produced by the \mcrat{} MPI processes are named \texttt{mc\_output\_$i$.log}. These are files that output the progress of the given process, allowing the user to keep track of how far along \mcrat{} is in the radiation transfer simulation and how much more work the code has left to complete. This file contains the number of scatterings that the code completes in increments of 1000 scatterings as well as the average photon energy in units of ergs, the comoving temperature, in Kelvin, of the hydro fluid element that was used in the most recent scattering, and the most recent time step for a photon to scatter and the current time in the simulation. When all the scatterings are completed for a given frame, the code prints out the average cumulative number of scatterings that each photon has undergone, as well as the the maximum and minimum number of scatterings for the photons.The code also prints out the average radius of the \mcrat{} photons, the simulation time and the frames left to inject photons into and the last hydro simulation frame.

When the \mcrat{} MPI process has completed the Monte Carlo scattering portion of the code it will print: ``Process $i$ has completed the MC calculation.'' where $i$ is the ID of the MPI process. When all of the MPI processes are complete with the Monte Carlo scattering they will collectively produce the \texttt{mcdata\_$f$.h5} files which contain the merged data from each MPI process within a given angle range.

These \texttt{mcdata\_$f$.h5} files are formatted in the same way that the HDF5 groups are formatted in the \texttt{mc\_proc\_$i$.h5} files with the exception of the PW dataset being included in each frame, regardless of whether additional photons were injected into the simulation at that frame or not. 

\subsection{Post-processing Algorithm}
When the user has completed running \mcrat{} for each angle range that they are interested in, the data for every simulated photon needs to be merged. The MERGE code that is included with the download of \mcrat{} uses parallel HDF5 I/O to accomplish and speed up this post-processing. 

The code takes the MPI processes and distributes them evenly among the \mcrat{} produced angle subdirectories. If there are $n_\theta$ angle subdirectories, the MPI processes are grouped into sets of $n_\theta$, with each MPI process operating withing a given subdirectory. Then, the code distributes the hydro simulation frames that need to be created among the groups of $n_\theta$ MPI processes. It also counts how many processes were originally used by \mcrat{} in each directory so if \mcrat{} is independently run 3 different times for 3 different ranges of angles, but with each of the 3 runs using a different number of MPI processes, the post-processing code will still work.

These processes open the \texttt{mc\_proc\_$i$.h5} files and tally how many photons will be merged to produce the final \texttt{mcdata\_$f$.h5} file in the \texttt{ALL\_DATA} directory. Using this information, the code constantly ensures that any files created by MERGE files that were created, before the code was terminated for any reason, are not corrupted; thus the MERGE code can be stopped and started again without worrying about corrupting data. The code iterates over the photons injected from first to last in the \mcrat{} simulation, by reading the data from the \texttt{mc\_proc\_$i$.h5} files. These photon data are then collectively appended to the final \texttt{mcdata\_$f$.h5} file. 

\section{Physics Included in \mcrat{}}
This section describes the physics of the \mcrat{} code injecting photons and scattering them through the hydro simulation. We also go into the physics of emitting thermal synchrotron photons into the outflow and how we rebin these photons to ensure that the number of photons doesn't increase without bound.

\subsection{Background: Monte Carlo Radiation Transport}
\label{sec:background}
% ??????????????????????????????????????????????????????????????????????????????

\subsubsection{What is Monte Carlo radiation transport?}

In astrophysics, we are often interested in how radiation propagates through
a plasma: photons are emitted by electrons, scattered off other electrons,
and absorbed.  The exact solution to the radiative transfer equation in a
complex, multi-dimensional, relativistically moving medium is computationally
intractable.  Monte Carlo (MC) methods provide a practical alternative: rather
than solving a partial differential equation for the radiation field, we
simulate the trajectories of a large number of representative photon
\emph{packets} and accumulate statistics from their histories.

\subsubsection{Photon packets and Monte Carlo estimators}

A photon packet represents many physical photons. Its weight \(w_k\)
records the number of physical photons represented by packet \(k\).

For an extensive observable, such as photon number, emitted energy, or
a spectral-bin contribution, the Monte Carlo estimator has the generic
form
\begin{equation}
	\widehat{F}
	=
	\sum_k
	w_k\,f_k,
	\label{eq:estimator_extensive}
\end{equation}
where \(f_k\) is the contribution of one represented photon. Spectra,
luminosities, and light curves use this form together with the relevant
time-, solid-angle-, distance-, and bin-width normalizations.

A normalized weighted average is instead
\begin{equation}
	\widehat{\langle f\rangle}
	=
	\frac{\sum_k w_kf_k}
	{\sum_k w_k}.
	\label{eq:estimator_normalized}
\end{equation}
Equation~\eqref{eq:estimator_normalized} is appropriate only when a
normalized mean is intended; it is not the generic estimator for an
extensive radiative quantity.

\subsubsection{Continuous absorption and weight attenuation}

There are two philosophically different ways to handle absorption in a Monte
Carlo code:

\begin{enumerate}
	\item \textbf{Stochastic absorption}: a packet is either transmitted or
	destroyed at each interaction, determined by a random draw.  This is
	unbiased but can be very noisy when the survival probability is high
	(nearly transparent medium).
	
	\item \textbf{Continuous (deterministic) absorption}: the weight is
	reduced at every step by the survival probability $\exp(-d\tau)$, where
	$d\tau$ is the optical depth traversed.  The packet is never stochastically
	destroyed; instead it carries a continuously decreasing weight.  This is
	also unbiased and has lower variance, but produces packets with very small
	weights after traversing optically thick material.
\end{enumerate}

\mcrat{} uses continuous absorption for synchrotron self-absorption.  The
consequence is that after traversing an optically thick region, a packet's
weight may have fallen to a tiny fraction of its birth weight, making its
statistical contribution negligible while still consuming computational
resources.  The Russian roulette algorithm described in
Section~\ref{sec:roulette} addresses this problem.

\subsection{Injecting Photons} \label{inj}
The code selects HD fluid elements at a given radius and calculates the expected number of photons in each element as
\begin{equation} \label{n_density}
n_i=\frac{\xi T_i^{'3}\Gamma_i}{w}dV_i 
\end{equation} 
where $\xi$, the number density coefficient which is used to calculate the number density of photons as $n_\gamma=\xi T^{'3}$, is 20.29 for a Blackbody spectrum or 8.44 for a Wien spectrum, $T'_i$ is the comoving temperature of the fluid element, $\Gamma_i$ is the Lorentz factor of the element, $w$ is the weighting factor of each injected photon, and $dV_i$ is the volume of the fluid element. 
 
The comoving temperature is calculated as
\begin{equation}
T'_i=\big( \frac{3p_i}{a} \big)^\frac{1}{4}
\end{equation}
where $p_i$ is the pressure of the fluid element, and $a$ is the radiation density constant.
 
If the HD simulations used are 2D axis-symmetric, we assume cylindrical symmetry and calculate $dV_i=2\pi x_idA_i$ where $x_i$ is the distance of the fluid element from the y-axis of the simulation and $dA_i$ is the area of the element. 
 
Once the number of photons is calculated, we draw a random number from a Poisson distribution using $n_i$ as the average value in order to get the actual number of photons that will be injected into the $i^\text{th}$ HD element, $N_i$. The weight, $w$, for a given set of injected photons can be adjusted accordingly in order to inject more or less photons into the simulation; this allows us to conserve energy and increase photon statistics for time resolved spectra. This weight is essentially how many real photons each \mcrat{} photon represents.

The total number of photons that would be injected across all the chosen hydro elements becomes $N=\sum N_i$. If $N$ is within the minimum and maximum number of photons that the user wants, which is specified in the \texttt{mc.par} file, the calculation for the number of photons is complete. If not, then the code continues to recalculates $n_i$ using a new weight for each iteration, then recalculates $N_i$ and $N$, and after rechecks to see if $N$ is within the user specified number of photons again. This loop is exited when $N$ falls within the user specified number of desired photons. If the code needs to inject more photons to meet this condition, it will adjust the weights to be smaller and vice versa.

Once $N$ and $N_i$ have been determined, the $N_i$ photons are placed at the center of the $i^\mathrm{th}$ hydro element, with a random azimuthal angle uniformly distributed between $0$ and $2\pi$ (since we assume cylindrical symmetry for the 2D hydro simulation), and they are given an energy based on the comoving temperature of the hydro element, thus the photons are injected in the comoving frame of the outflow. If the user specified that the photons should be injected with a Wien spectrum then the frequencies, $\nu_i$, are assigned to the $N_i$ photons by sampling from a Wien spectrum defined by the $i^\mathrm{th}$ fluid element's comoving temperature. The same thing is done with a Blackbody spectrum if the user specified that the photons should be injected as a Blackbody spectrum. This sampling is done by using the acceptance-rejection Monte Carlo sampling of the spectra.

For their 4-momenta, the photons are assigned a random azimuthal angle, $\phi$, from a uniform distribution between $0$ and $2\pi$, as well as a polar angle, which is calculated as $\theta=\arccos(2\xi-1)$, where $\xi$ is a random number drawn from a uniform distribution. The $i^\mathrm{th}$ injected photon 4-momentum becomes:
\[
p^\mu_i=\frac{h\nu_i}{c}\begin{pmatrix}
1 \\ \sin(\theta_i) \cos(\phi_i) \\ \sin(\theta_i) \sin(\phi_i) \\ \cos(\theta_i)
\end{pmatrix}
\]

After the 4-momenta are set, the photons are boosted into the lab frame using the velocity of the fluid element that the photons are located within. The lab frame 4-momenta are saved to each photon's \texttt{photon} data structure, as well as the photon's position and weight. The number of scatterings is initialized to 0 and the stokes parameters are initialized to 0 except for s0 which is set to 1.

Alternatively, if the user has selected the custom spectrum, the photon energy (and optionally its direction and polarization) is instead assigned by the user-defined custom\_photon\_sampler routine described in Section \ref{custom_spectrum}; all other aspects of injection proceed identically.


\subsection{Scattering Photons} \label{scatt}
%The general algorithm and the physics for scattering photons has been covered in Section \ref{algorithm}.

In order to scatter the photons, we first need to determine the distance that each photon will propagate before scattering. Thus we calculate each photon's mean free path and choose a random number that will distribute it according to an exponential distribution. We calculate the distance each photon will propagate before scattering as:
\[
l=-\frac{m_p}{\rho\sigma_\mathrm{T}(1-\beta\cos\theta_{fp})}\ln\xi
\]
where, $\xi$ is a random number uniformly distributed between 0 and 1, $m_p$ is the proton mass, $\sigma_\mathrm{T}$ is the Thompson cross section, $\rho$ is the lab frame density of the hydro fluid element that the photon is located within, $\beta$ is the velocity of the fluid element normalized by the speed of light (this should be already done in the hydro code), and $\theta_{fp}$ is the angle between the fluid element's and the photon's velocity vectors. From $l$, the time for each photon to scatter is calculates as $t_\mathrm{s}=l/c$, where $c$ is the speed of light. The photon with the smallest $t_s$ is assumed to scatter first, however that is not necessarily true since we use the full Klein-Nishina cross section in the electron rest frame to actually determine if the scattering occurs. The positions of all the photons are advanced by the time for the photon of interest to scatter, $t_s$.

In determining whether a photon will scatter or not, we first boost the chosen photon with the smallest $t_s$ to the fluid rest frame and produce an electron by sampling the Maxwell-Boltzmann or Maxwell-Juttner distributions for non-relativistic and relativistic gases. The comoving temperature, $T_i'$, of the fluid element is used to distinguish between which distribution is used. If $T_i' \ge 1 \times 10^7$ K the Maxwell-Juttner distribution is used, otherwise the Maxwell-Boltzmann distribution is used. When the Maxwell-Boltzmann distribution is used we choose 3 random x, y and z velocities from gaussian distributions with a standard deviation of $k_BT_i'/m_e$, where $k_B$ is the Boltzmann constant and $m_e$ is the mass of the electron. The velocities are normalized by the speed of light and used to calculate the Lorentz factor of the electron in the fluid frame. To get the full 4-mometum of the electron, the azimuthal angle of the electron's direction of travel is drawn from a uniform distribution between 0 and $2\pi$ and the polar angle is acquired by acceptance-rejection sampling of the polar angle distribution $(1-\beta\cos(\theta))\sin(\theta) $. We then perform rotations based on the velocity vector of the photon that will scatter to ensure that the electron velocity is oriented relative to the photon's velocity.

Once the electron has been initialized, the photon and the electron are boosted into the electron rest frame. Then, the photon velocity vector is rotated such that it is directly along the x-axis with the stationary electron at the origin of the coordinate system. We then use the Klein Nishina (KN) cross section, $\sigma_\mathrm{KN}$, to determine if the photon will actually scatter.  Using $\sigma_{\mathrm{T}}$ as the Thomson cross section, the ratio $\sigma_\mathrm{KN}/\sigma_T$ is calculated and a random number, $\xi$, from a uniform distribution between 0 and 1 is drawn. If $\xi >\sigma_\mathrm{KN}/\sigma_T $ the photon does not scatter, otherwise it does scatter with the electron. 

If $\xi \le \sigma_{\mathrm{KN}}/\sigma_{\mathrm{T}}$ then we sample the differential KN cross section to determine the angles, $\theta_{\mathrm{sc}}$ and $\phi_{\mathrm{sc}}$, that the photon will be scattered into. The differential cross section given by \cite{lundman2014polarization} is
\begin{equation}
\frac{\mathrm{d} \sigma_{\mathrm{KN}}}{\mathrm{d} \Omega} (\theta_{\mathrm{sc}}, \phi_{\mathrm{sc}}) =\frac{r_{0}^{2}}{2}\left(\frac{\epsilon}{\epsilon_{0}}\right)^{2} \times 
\left\{\frac{\epsilon_{0}}{\epsilon}+\frac{\epsilon}{\epsilon_{0}} - \sin ^{2} \theta_{\mathrm{sc}}\left(1- q \cos 2 \phi_{\mathrm{sc}}+u \sin 2 \phi_{\mathrm{sc}}\right)\right\} \label{KN_diff_cross_section_scatt}
\end{equation}
where $r_{0}$ is the classical electron radius, $\epsilon_{0}$ is the incoming photon energy scaled by the electron rest mass, $\epsilon=\epsilon_{0}/(1+\epsilon_{0}[1-\cos \theta_{\mathrm{sc}}])$ is the scattered photons energy scaled by the electron rest mass, and $q$ and $u$ are the stokes parameters discussed further in Section \ref{pol}. The outgoing photon's $\theta_{\mathrm{sc}}$ is acquired by rejection sampling the differential cross section integrated over $\phi_{\mathrm{sc}}$ following the method outlined by \cite{sample_kn_theta} for maximum efficiency. We acquire $\phi_{\mathrm{sc}}$ by choosing a random uniformly distributed value between [0, 2$\pi$] when $q=u=0$, otherwise we apply a rejection sampling method to the differential KN cross section. {The case of $q=u=0$ removes the KN cross section's  dependence on $\phi_{\mathrm{sc}}$, which allows us to choose a value between [0, 2$\pi$].}

We outline our method of sampling Equation \ref{KN_diff_cross_section_scatt} to acquire $\phi_{\mathrm{sc}}$ when the incoming photon is polarized. The azimuthal angle that gives the maximum of the KN differential cross section, $\phi_{\mathrm{m}}$, can be solved as
\begin{equation}
\phi_{\mathrm{m}}=\frac{1}{2} | \arctan \big( \frac{-u}{q} \big) |
\end{equation}
We then plug $\phi_{\mathrm{m}}$ and the previously acquired $\theta_{\mathrm{sc}}$ into the KN differential cross section to get the normalization for the rejection sampling method, $\frac{\mathrm{d} \sigma_{\mathrm{KN}}}{\mathrm{d} \Omega} (\theta_{\mathrm{sc}}, \phi_{\mathrm{m}})$. We proceed as follows:
\begin{itemize}
\item[(1)] Draw a random number $\xi$ uniformly distributed between 0 and 1
\item[(2)] Draw a random $\phi_{\mathrm{sc}}$ uniformly distributed between 0 and $2\pi$
\item[(3)] Calculate $\frac{\mathrm{d} \sigma_{\mathrm{KN}}}{\mathrm{d} \Omega} (\theta_{\mathrm{sc}}, \phi_{\mathrm{sc}})$
\item[(4)] Determine if $\xi \le  [\frac{\mathrm{d} \sigma_{\mathrm{KN}}}{\mathrm{d} \Omega} (\theta_{\mathrm{sc}}, \phi_{\mathrm{sc}})][\frac{\mathrm{d} \sigma_{\mathrm{KN}}}{\mathrm{d} \Omega} (\theta_{\mathrm{sc}}, \phi_{\mathrm{m}})]^{-1}$
\item[(5)] If the above condition is met, accept the value of $\phi_{\mathrm{sc}}$, otherwise repeat the sampling
\end{itemize}  

The photon's new 4-momentum and stokes parameters are calculated and then the scattered photon is rotated to its original orientation with respect to the previously stationary electron. The photon is then Lorentz boosted twice, back to the lab frame. 

If the photon does not scatter, then the next photon with the second shortest time to scatter is chosen and the process to create an electron and determine if the photon will scatter repeats. This loop continues until a photon scatters or all of the photons have been determined to not scatter.


\subsection{Polarization}\label{pol}
The Stokes parameters are a vector, $S=(I, Q, U, V)$ that holds information about the polarization of electromagnetic radiation. $I$ is the intensity of the electromagnetic radiation, $Q$ and $U$ describe the orientation of the polarization ellipse, and $V$ describes the ratio of the principal axis of the polarization ellipse \citep{Rybiki_Lightman}. {We follow the convention set by \cite{McMaster:1961aa} and  \cite{lundman2014polarization}
where $Q=+1$ is oriented with the y-axis of the Stokes plane and $Q=-1$ is oriented with the x-axis of the Stokes plane. The $+U$ axis is rotated $45^\circ$ clockwise with respect to the $+Q$ axis and the  $-U$ axis is rotated $45^\circ$ clockwise with respect to the $-Q$ axis. }Furthermore, we normalize the Stokes parameters such that $I=1$ at all times giving us $s=(1, Q/I, U/I, V/I)=(1,q,u,v)$. In the code, it is stored as $s=(S0, S1, S2, S3)$. In our simulations, we only consider linear polarization which means that we ignore any contribution by $v$ (S0). This is appropriate since we assume that electron spins, which directly affect $v$, are isotropically distributed.

In \mcrat{} all photons are initialized to have no polarization; thus, we set $s=(1,0,0,0)$. Each photon becomes $100$\% polarized from the very first scattering that it undergoes, which does not bias the results. 

In order to deal with polarization, we follow the prescription given by \cite{lundman2014polarization}. We lorentz boost the photons' 4 momenta from the lab frame to the fluid frame, then from the fluid frame to the electron rest frame. In the electron rest frame we conduct our scattering using the full Klein Nishina (KN) cross section and then scatter the Stokes parameters using Fanno's Matrix. Afterwards, we deboost the photons from the electron rest frame and the fluid rest frame back to the lab frame. 

{In the lab frame, the Stokes plane is oriented such that the $+Q$ axis is pointing in the $-\hat{\phi}$ direction and the $-Q$ axis is pointing in the $-\hat{\theta}$ direction. The $+U$ axis is rotated $45^\circ$ clockwise with respect to the $+Q$ axis and the  $-U$ axis is rotated $45^\circ$ clockwise with respect to the $-Q$ axis. $\chi$ is measured clockwise from the $+Q$ axis towards the $+U$ axis. $\hat{\phi}$ and $\hat{\theta}$ are the orthonormal azimuthal and polar unit vectors in a spherical coordinate system where the radial unit vector is parallel to the photon's momentum vector.} 

Each boost to another reference frame entails rotating the Stokes plane using the Muller rotation matrix \citep{McMaster:1961aa} given by
\begin{equation}
\mathbf{M}[\phi]=\left(\begin{array}{cccc}{1} & {0} & {0} & {0} \\ {0} & {\cos 2 \phi} & {-\sin 2 \phi} & {0} \\ {0} & {\sin 2 \phi} & {\cos 2 \phi} & {0} \\ {0} & {0} & {0} & {1}\end{array}\right)
\end{equation}
where the angle of rotation, $\phi$, corresponds to the rotation that orients the y-axis of the Stokes plane perpendicular to the photon three momentum and the velocity vector of the frame that the photon will be boosted into. The equation for $\phi$ is given in Appendix B of \cite{lundman2014polarization}. After each boost, we rotate the Stokes plane again to ensure that the y-axis of the Stokes plane is perpendicular to the plane formed by the reference frame's z-axis and the photon's three momentum.

We conduct a scattering of the photon's 4 momenta as outlined in section \ref{scatt}. Lorentz boosting to all the proper frames and sampling the KN cross section. 

Once the scattering is completed, and still in the electron rest frame after undoing all of the rotations that placed the photon along the x axis moving towards the electron at the origin of the coordinate system, we conduct the scattering of the Stokes parameters. First, we use the Muller matrix to rotate the Stokes plane such that the Stokes plane's y-axis is perpendicular to the plane formed by the incoming and outgoing photon three momenta \citep{McMaster:1961aa, lundman2014polarization}. Then, we use Fanno's matrix, $T[\theta_{\mathrm{sc}},\epsilon_{0}, \epsilon]$, \citep{McMaster:1961aa} to determine the resulting polarization, $\tilde{s}=T[\theta_{\mathrm{sc}},\epsilon_{0}, \epsilon]s$. Fanno's matrix is 
\begin{equation}
T[\theta_{\mathrm{sc}},\epsilon_{0}, \epsilon]=  \left(\begin{array}{lll}{1+\cos ^{2} \theta_{\mathrm{sc}}+\left(\epsilon_{0}-\epsilon \right)\left(1-\cos \theta_{\mathrm{sc}}\right)} & {\sin ^{2} \theta_{\mathrm{sc}}} & {0} \\ {\sin ^{2} \theta_{\mathrm{sc}}} & {1+\cos ^{2} \theta_{\mathrm{sc}}} & {0} \\ {0} & {0} & {2 \cos \theta_{\mathrm{sc}}}\end{array}\right)
\end{equation}
where, similar to \cite{krawczynski2011polarization},  we have excluded the factors in front since they cancel out when we normalize the scattered Stokes parameters by $I$ as mentioned above. We have also excluded the fourth row and column of the matrix since we only consider linear polarization. In this case, $\theta_{\mathrm{sc}}$ is acquired by calculating the angle between the photon's original incoming 3 momentum and the new outgoing 3 momentum. We calculate this as:
\begin{equation}
\theta_{\mathrm{sc}}=\arccos(\overrightarrow{p_\mathrm{in}} \cdot \overrightarrow{p_\mathrm{out}})
\end{equation}

Once the new stokes parameters are acquired, they are normalized by dividing by $S0$. Then, the stokes parameters are rotated to ensure that the y-axis of the Stokes plane is perpendicular to the plane formed by the electron rest frame's z-axis and the outgoing photon's 3 momentum. After the photon is deboosted back to the lab frame and the stokes parameters are rotated for each lorentz boost.

\subsection{Cyclo-synchrotron Radiation}\label{cyclo-synch}
\subsubsection{Emitting Cyclo-synchrotron (CS) Photons}
The emission of the cyclo-synchrotron (CS) photons is similar to injecting photons into the outflow. We iteratively calculate the number of photons to emit as synchrotron photons in the frame and assign them random 4 momenta with an energy corresponding to the local cyclotron frequency. We consider the source of CS photons to be constant in time so we emit a constant number and if any synchrotron photon gets upscattered, we replace it with another synchrotron photon. 

These photons are emitted into a region that the original injected photons are passing through so it accounts for the CS photons that would be upscattered in the flow during the time of interest of the original injected photons.

The maximum number of photons that are emitted, $N_{e,max}$, are calculated as the percentage of the maximum number of photons the user wants injected (see line 17 of the example mc.par file in section \ref{mc.par}). For example, if \texttt{CYCLOSYNCHROTRON\_REBIN\_E\_PERC} is set to 0.5 and the value of the 17$^\textrm{th}$ line is 3000, the upper limit for the number of synchrotron emitted photons is 1500. The number density of CS photons, $n_{s,i}$, in a given cell is acquired by integrating the blackbody photon number spectrum up to the cyclotron frequency, $\nu_B$. We calculate the number density as
\begin{equation}
n_{s,i}=\int\limits_{0}^{\nu_B}\frac{u_\nu}{h \nu}d\nu\frac{dV_i}{w}=\int\limits_{0}^{\nu_B}\frac{8\pi \nu^2 }{c^3 (e^\frac{h\nu}{kT_i'}-1 )}d\nu\frac{dV_i}{w}
\end{equation}
 where w is the weight of each CS photon, $dV_i$ is the volume of the HD cell, $T_i$ is the temperature of the same cell, h is Planck's constant and 
\begin{equation}
\nu_B=\frac{eB}{2\pi m_e c}
\end{equation}
where $e$ is the electron charge and $B$ is the magnetic field within the cell. Once $n_{s,i}$ is calculated, we draw a random number from a Poisson distribution with a mean of $n_{s,i}$ to acquire the total actual number of photons that are emitted into the cell. We get the total number of emitted photons, $N_e$, by summing over each cell's $n_{s,i}$. If $N_e > N_{e,max}$, then the $w$ is made larger and then the aforementioned calculations are made. If $N_e \le N_{e,max}$ then the code proceeds to assign the CS photons a random 4 momentum and assigns them to be at the center of their respective hydrodynamic cell.

When a CS photon gets scattered, it is placed randomly within its HD cell and the scattering proceeds as it normally would. Then another CS photon gets added to the pool of photons at the center of their respective HD cell with the proper $\nu_B$.

\subsubsection{Calculating B}
\mcrat{} provides 2 ways to calculate the magnetic field in the outflow, in order to calculate $\nu_B$. It either uses the internal energy fo the flow to calculate B, when the \texttt{B\_FIELD\_CALC} switch is set to \texttt{INTERNAL\_E}, or it uses the total energy of the outflow to calculate B, when the \texttt{B\_FIELD\_CALC} switch is set to \texttt{TOTAL\_E}.
\begin{itemize}
\item Total Energy

For a given plasma, the luminosity from matter and radiation can be written as $L=4\pi(\rho c^2+4p)\Gamma^2cr^2$, where c is the speed of light, $\rho$ is the plasma density, $p$ is the pressure, $\Gamma$ is the bulk Lorentz factor, and $r$ is the radius of the plasma away from its point of origin. The luminosity due to the magnetic field is $L_B=4\pi(B^2/8\pi)\Gamma^2cr^2$ where B is the magnetic field of the plasma. The fraction of energy between the magnetic outflow luminosity and the total outflow luminosity can be written as
\begin{equation}
\epsilon_{B}=\frac{L_B}{L}=\frac{B^2}{8\pi(\rho c^2+4p)}
\end{equation}
If the user supplies $\epsilon_{B}$ to \mcrat{} via the \texttt{EPSILON\_B} parameter then the code uses the above formula to solve for the magnetic field in each HD cell.

\item Internal Energy

In the internal energy case, the magnetic field energy density is equated to the electron thermal kinetic energy.
\begin{equation}
\frac{B^2}{8\pi}=\frac{3}{2}nkT'\epsilon_{B}
\end{equation}
where n is the number density of electrons, k is the boltzmann constant and T is the plasma temperature.
\end{itemize}

\mcrat{} can also read in the magnetic field from a magneto-hydrodynamic simulation and use the magnitude of the magnetic field in calculating $\nu_B$. This option is used when \texttt{B\_FIELD\_CALC} is set to \texttt{SIMULATION}.

\subsubsection{Rebinning The Scattered CS Photons}
The \mcrat{} code spatially rebins the CS photons in order to keep the number of photons that it needs to track down to a reasonable amount, which helps decrease computational time. In order to rebin the photons, \mcrat{} finds the photon with the smallest position in the polar direction, $\theta_\mathrm{min}$,  and the photon with the largest position in the polar direction, $\theta_\mathrm{max}$. These typically correspond to the values that were specified in the \texttt{mc.par} file that is read in by \mcrat{}. Then the size of each spatial bin, $\Delta \theta$ is set by the user through the \texttt{CYCLOSYNCHROTRON\_REBIN\_ANG} parameter in the \texttt{mcrat\_input.h} file. The number of spatial bins, $N_\theta$ is then is determined as
\begin{equation}
N_\theta=\frac{\theta_\mathrm{max}-\theta_\mathrm{min}}{\Delta \theta}
\end{equation}

The photons are also binned into energy bins, where the size of the energy bins, $\Delta E$ is determined as 
\begin{equation}
\Delta E=\frac{\log(E_\mathrm{max})-\log(E_\mathrm{min})}{N_E}
\end{equation}
where $E_\mathrm{max}$ and $E_\mathrm{min}$ are the minimum and maximum energies of the CS photons and $N_E$ is the number of energy bins acquired by multiplying the \texttt{CYCLOSYNCHROTRON\_REBIN\_E\_PERC} value times the value of the 17$^\textrm{th}$ line of the \texttt{mc.par} file, $N_{17}$.

To ensure that the rebinning is efficient, \mcrat{} checks that $N_\theta N_E<N_{17}$. If it is not, the the code throws an error. The user can then change either parameter to ensure that the aforementioned condition is met.

When rebinning the photons in polar angle and energy, the following values of photons that fall within a given energy and $\theta$ bin are averaged and then assigned to a new rebinned photon (the quantities for this rebinned photon are represented with a tilde). For a given energy bin $i$ and $\theta$ bin $j$, the new rebinned photon would have the following four momentum  
\[
\tilde{p}^\mu_{i,j}=\frac{<E>}{c}\begin{pmatrix}
1 \\ \sin(<\theta>) \cos(<\phi>) \\ \sin(<\theta>) \sin(<\phi>) \\ \cos(<\theta>)
\end{pmatrix}
\]
where $\theta$ and $\phi$ are the directional angles of the 4 momentum and the $<\cdots>$ denote weighted averages of the various quantities over the photons that fall within bin $(i,j)$. The stokes parameters for the rebinned photon becomes $\tilde{s}=(1,<q>,<u>,<v>)$. The photon weight becomes $\tilde{w}=\sum w_{i,j}$. The position vector of the rebinned photon becomes
 \[
 \overrightarrow{\tilde{r}}_{i,j}=<r>\begin{pmatrix}
  \sin(<\theta_p>) \cos(<\phi>-<\Delta \tilde{\phi_p}>) \\ \sin(<\theta_p>) \sin(<\phi>-<\Delta \tilde{\phi_p}>) \\ \cos(<\theta_p>)
 \end{pmatrix}
 \]
 where $<r>$ is the average radius of the photons that lie in bin $(i,j)$, $<\theta_p>$ is the average polar angle of the photons with the given bins and , for these same photons, $<\Delta \tilde{\phi_p}>$ is the average displacement angle taken across each photon's 4-momentum azimuthal angle, $\phi$, and its positional azimuthal angle, $\phi_p$, that is $\Delta \tilde{\phi_p}= \phi-\phi_p$. This consideration of the displacement in the positional and 4-momentum azimuthal angles is necessary to ensure that the rebinned photons are still in appropriate equilibrium with the flow. 


\subsubsection{Absorption of CS Photons}
At the end of each HD frame, \mcrat{} proceeds to absorb any photons that have a frequency  $\nu \le \nu_B$ of the HD cell that they are located within. As a result, all of the CS photons that were emitted and never upscattered become absorbed and any photons that have been scattered but still satisfy  $\nu \le \nu_B$ are also absorbed.


\subsection{Non-Thermal Synchrotron Emission, Self-Absorption, and Scattering Bias}
\label{sec:nonthermal_synch}
The preceding section described the \emph{thermal} cyclo-synchrotron
treatment (Section~\ref{cyclo-synch}), which is enabled by the
\texttt{CYCLOSYNCHROTRON\_SWITCH} and implemented in
\texttt{mc\_cyclosynch.c}; there, photons are emitted at the local
cyclotron frequency, rebinned, and absorbed below $\nu_B$. This section
describes a distinct, more detailed \emph{non-thermal} synchrotron
capability, enabled by the \texttt{SYNCHROTRON\_SWITCH} together with a
power-law \texttt{NONTHERMAL\_E\_DIST} and implemented in
\texttt{mc\_synchrotron.c}, which models emission, self-absorption, and
biased Compton scattering for a power-law electron population by sampling
a universal, precomputed frequency CDF.

\begin{implementationnote}
	The thermal cyclo-synchrotron path (Section~\ref{cyclo-synch}) and the
	non-thermal synchrotron path described here are \emph{mutually
		exclusive}: \mcrat{} will refuse to build if both
	\texttt{CYCLOSYNCHROTRON\_SWITCH} and \texttt{SYNCHROTRON\_SWITCH} are
	enabled simultaneously. The two paths use different source modules
	(\texttt{mc\_cyclosynch.c} versus \texttt{mc\_synchrotron.c}) and
	different emission prescriptions (emission at $\nu_B$ versus sampling of
	the universal photon-number CDF). Both perform periodic Russian-roulette
	and rebinning operations that share the ``every 1000 scatterings''
	cadence referenced in Section~\ref{algorithm}, but they act on different
	photon populations; the cadence statements in the two sections therefore
	describe analogous but independent machinery and are not in conflict.
\end{implementationnote}

Before working through the detailed physics, Section~\ref{sec:background}
gives a brief, self-contained primer on Monte Carlo radiation transport
for readers new to the method.


\subsubsection{Roadmap: the life cycle of a synchrotron packet}
\label{sec:roadmap}

Before working through the detailed physics in the remainder of this
section, it is useful to have a bird's-eye view of everything that
happens to a single synchrotron photon packet. Section numbers point
to where each step is described in detail.

\begin{enumerate}[leftmargin=2em]
	\item \textbf{Emission} (Section~\ref{sec:emission}): a cell with
	non-thermal electrons and $B>0$ emits a Poisson-distributed number
	of packets per hydro frame, with a frequency sampled from a
	universal, precomputed CDF and an isotropic-in-intent (but see the
	known defect in Section~\ref{sec:kinematics}) comoving direction.
	
	\item \textbf{Transport} (Section~\ref{sec:frame}): the packet's
	4-momentum is Lorentz-boosted to the lab frame and it is
	propagated in straight lines between scattering/absorption events.
	
	\item \textbf{Continuous self-absorption} (Section~\ref{sec:ssa}):
	at every transport sub-step, the packet's weight is multiplied by
	$\exp(-d\tau_{\nuf}^{(a)})$, where $d\tau_{\nuf}^{(a)}$ includes
	the full relativistic frame correction $\Gamma(1-\beta\cos\theta)$.
	
	\item \textbf{Biased Compton scattering} (Section~\ref{sec:bias}):
	the mean free path to the next scattering is drawn using an
	artificially enhanced (``biased'') optical depth so that rare,
	high-energy non-thermal electron subgroups are adequately sampled;
	the packet is split into a scattered and an unscattered component
	with weights corrected to preserve unbiasedness.
	
	\item \textbf{Russian roulette} (Section~\ref{sec:roulette}): every
	1000 scatterings, and once more at the end of each \emph{eligible
		intermediate} hydro frame (the pass is skipped for a packet batch's
	initial scattering frame and for the final hydro frame; see
	Section~\ref{sec:callchain}), packets whose weight has fallen far
	below the population median
	
	\item \textbf{Rebinning and output}: surviving packets are merged
	if the photon list approaches capacity (Section~\ref{sec:rebin}),
	and their weighted contribution to spectra, light curves, or
	images is ultimately accumulated via the estimator
	\eqref{eq:estimator_extensive}.
\end{enumerate}



\subsubsection{Enabling and Initializing the Module}
\label{sec:operation}

The nonthermal synchrotron module is controlled primarily through
compile-time settings in \code{mcrat\_input.h}. A complete rebuild is
required after changing these macros.

\paragraph{Required switches}

At minimum, enable the synchrotron module and select one supported
nonthermal electron distribution:
\begin{verbatim}
	#define SYNCHROTRON_SWITCH ON
	
	/* Choose exactly one of these distributions. */
	#define NONTHERMAL_E_DIST POWERLAW
	/* or:
	#define NONTHERMAL_E_DIST BROKENPOWERLAW
	*/
\end{verbatim}

For a single power law, specify
\begin{verbatim}
	#define POWERLAW_INDEX ...
	#define GAMMA_MIN ...
	#define GAMMA_MAX ...
\end{verbatim}

For a broken power law, specify
\begin{verbatim}
	#define POWERLAW_INDEX_1 ...
	#define POWERLAW_INDEX_2 ...
	#define GAMMA_MIN ...
	#define GAMMA_BREAK ...
	#define GAMMA_MAX ...
\end{verbatim}

The nonthermal scattering implementation requires tabulated cross
sections and scattering bias:
\begin{verbatim}
	#define TAU_CALCULATION TABLE
	#define SCATTERING_BIAS_SWITCH ON
\end{verbatim}

The magnetic field must be obtained either from the hydro simulation or
from one of \mcrat{}'s parameterized prescriptions:
\begin{verbatim}
	#define B_FIELD_CALC SIMULATION
	/* or INTERNAL_E / TOTAL_E with the corresponding EPSILON_B setting */
\end{verbatim}

Useful optional settings include
\begin{verbatim}
	#define NONTHERMAL_CONVERSION_FACTOR ...
	#define SCATTERING_BIAS_SCALING ...
	#define RR_WEIGHT_FRACTION ...
	#define N_GAMMA ...
\end{verbatim}

\paragraph{Required parameter ordering and runtime validation}

The compile-time checks verify primarily that the required macros exist;
they do not validate every numerical relationship needed by the physics.
Before a production run, the user should verify
\begin{equation}
	1
	\le
	\gamma_{\min}
	<
	\gamma_{\max},
\end{equation}
and, for a broken power law,
\begin{equation}
	\gamma_{\min}
	<
	\gamma_{\mathrm{br}}
	<
	\gamma_{\max}.
\end{equation}
For the physical applications described in this guide, the power-law
indices should normally satisfy
\begin{equation}
	p>1,
	\qquad
	p_1>1,
	\qquad
	p_2>1,
\end{equation}
unless the corresponding logarithmic normalization limits are explicitly
intended and tested.

The following quantities must also be finite and positive:
\begin{equation}
	\mathrm{fps},
	\qquad
	B,
	\qquad
	V_i,
	\qquad
	n_{e,\mathrm{nth}},
	\qquad
	w_0.
\end{equation}
The requested packet interval should satisfy
\begin{equation}
	0
	\le
	N_{\min}
	\le
	N_{\max}.
\end{equation}

\begin{knownissue}
	The current \code{photonEmitSynch} weight-tuning loop has no explicit
	iteration bound and no early exit for a zero or non-finite total physical
	emission rate. A configuration with
	\begin{equation}
		\sum_iW_i
		\le
		0
	\end{equation}
	and a positive \code{min\_photons} has no feasible solution. Such a
	configuration can cause the tuning loop to fail to converge. Production
	runs should therefore validate the total emission rate before entering
	the loop.
\end{knownissue}

\paragraph{Initialization order}

The main program initializes the required shared tables before photon
transport:
\begin{enumerate}
	\item \code{initalizeHotCrossSection} loads or creates the thermal
	and nonthermal scattering tables.
	\item \code{initSynchTables} constructs \(F(x)\), \(G_a(x;p)\), the
	legacy inverse CDFs, and the universal
	\(\tilde{\nu}\) photon-number CDF.
	\item \code{initGlobalThreadRNG} creates one random-number generator
	per OpenMP thread.
\end{enumerate}

These initialization routines must complete before any call to
\code{photonEmitSynch}, \code{synchAlphaNu}, or
\code{calculateOpticalDepthSSA}.

At shutdown, the associated resources are released by
\code{cleanupInterpolationData}, \code{freeGlobalThreadRNG}, and
\code{freeSynchTables}.

\paragraph{Runtime sequence}

For each hydro frame, \mcrat{}:
\begin{enumerate}
	\item reads the hydrodynamic cell data;
	\item calculates the nonthermal electron density;
	\item emits synchrotron packets in the selected shell;
	\item finds the containing hydro cell for every live packet;
	\item computes scattering and absorption opacities;
	\item advances all packets to the next event or frame boundary;
	\item applies continuous SSA attenuation during every propagation
	step;
	\item performs biased Compton scattering when selected;
	\item periodically applies Russian roulette and rebinning;
	\item writes packet data and a restart checkpoint.
\end{enumerate}

\begin{implementationnote}
	The universal synchrotron tables depend on compile-time electron
	parameters such as \(p\), \(\gamma_{\min}\), \(\gamma_{\max}\), and
	\(\gamma_{\mathrm{br}}\). Changing any of these values requires rebuilding
	the executable and reconstructing the tables.
\end{implementationnote}

\subsubsection{Non-Thermal Electron Distribution}
\label{sec:electrons}
% ??????????????????????????????????????????????????????????????????????????????

Synchrotron radiation is produced by relativistic electrons spiralling around
magnetic field lines.  The electron distribution in each fluid cell is
specified as a power law in the Lorentz factor $\gamma$ (the ratio of the
electron's total energy to its rest-mass energy $m_e c^2$).

\paragraph{Single power law}
\label{sec:spl}

The simplest model is a single power law:
\begin{equation}
	N(\gamma) = A\,\gamma^{-p}, \qquad \gmin \le \gamma \le \gmax,
	\label{eq:spl}
\end{equation}
where $N(\gamma)\,d\gamma$ is the number of non-thermal electrons per unit
volume with Lorentz factors between $\gamma$ and $\gamma + d\gamma$.  The normalisation constant $A$ is fixed by requiring
$\int_{\gmin}^{\gmax} N(\gamma)\,d\gamma = \nenth$:
\begin{equation}
	A = \nenth\,A_{\rm norm}, \qquad
	A_{\rm norm} \equiv \frac{1-p}{\gmax^{1-p} - \gmin^{1-p}}, \qquad p \ne 1.
	\label{eq:spl_norm}
\end{equation}

\begin{keyresult}
	Notation: throughout the rest of this document (e.g.\ Eq.~\eqref{eq:Kphys}
	and Section~\ref{sec:emissivity}), $A_{\rm norm}$ always denotes the
	\emph{dimensionless}, $\nenth$-independent piece of the normalisation
	defined here, i.e.\ $N(\gamma) = \nenth\,A_{\rm norm}\,\gamma^{-p}$. The
	code function \code{powerLawNorm} (\code{electron.c}) takes no $\nenth$
	argument and returns $A_{\rm norm}$, \emph{not} the full,
	$\nenth$-dependent $A$ above; the $\nenth$ factor is applied separately
	by every caller (e.g.\ \code{n\_e\_nth} in \code{synchAlphaNu}, or
	$\nenth^{(i)}$ in $W_i$, Eq.~\eqref{eq:W_cell}).
\end{keyresult}

The power-law index $p > 1$ is a compile-time constant set by the user via
\code{POWERLAW\_INDEX}.

\paragraph{Broken power law}
\label{sec:bpl}

A more physically motivated model allows the slope of the distribution to
change at a break Lorentz factor $\gbr$:
\begin{equation}
	N(\gamma) = A \begin{cases}
		\gamma^{-p_1}, & \gmin \le \gamma \le \gbr, \\[4pt]
		\gbr^{\,p_2 - p_1}\,\gamma^{-p_2}, & \gbr < \gamma \le \gmax.
	\end{cases}
	\label{eq:bpl}
\end{equation}
The dimensionless normalization is obtained from
\begin{equation}
	\int_{\gmin}^{\gmax}
	A_{\rm norm}^{(\mathrm{br})}f_{\rm br}(\gamma)\,d\gamma
	=
	1,
\end{equation}
where $f_{\rm br}(\gamma)$ denotes the two unnormalised segments in
Eq.~\eqref{eq:bpl}. For $p_1\ne1$ and $p_2\ne1$,
\begin{equation}
	A_{\rm norm}^{(\mathrm{br})}
	=
	\left[
	\frac{
		\gbr^{1-p_1}-\gmin^{1-p_1}
	}{
		1-p_1
	}
	+
	\gbr^{p_2-p_1}
	\frac{
		\gmax^{1-p_2}-\gbr^{1-p_2}
	}{
		1-p_2
	}
	\right]^{-1}.
	\label{eq:bpl_norm}
\end{equation}
The full density-dependent coefficient is
\begin{equation}
	A
	=
	\nenth A_{\rm norm}^{(\mathrm{br})}.
\end{equation}
The logarithmic limiting forms implemented by
\code{brokenPowerLawNorm} must be used when either power-law index is
equal, or sufficiently close, to unity.
The factor $\gbr^{p_2-p_1}$ ensures the distribution is continuous at
$\gamma = \gbr$ \citep[\raikou{} Eqs.~A4--A5]{kawashima2023}. Writing $A = \nenth\,A_{\rm norm}^{\rm (br)}$ analogously to the single
power-law case, it is the dimensionless piece $A_{\rm norm}^{\rm (br)}$
that is computed by \code{brokenPowerLawNorm} in \code{electron.c};
like \code{powerLawNorm}, this function takes no $\nenth$ argument.

\paragraph{Determining the total nonthermal electron number density}
\label{sec:nth_dens}

For a custom outflow, the user may assign
$n_{e,\mathrm{nth}}$ directly. In that case the custom-outflow
implementation is responsible for populating
\code{hydro\_data->nonthermal\_dens} consistently in every cell.

Otherwise, \mcrat{} derives the nonthermal electron density from the local
magnetic energy density. The magnetic field may be read from an MHD
simulation or inferred from a parameterized fraction of the internal or
total energy density, depending on \code{B\_FIELD\_CALC}.

Let $f_e=\code{NONTHERMAL\_CONVERSION\_FACTOR}$ be the fraction of the
magnetic energy density assigned to the nonthermal electron population.
\mcrat{} imposes
\begin{equation}
	n_{e,\mathrm{nth}}
	\langle\gamma\rangle m_ec^2
	=
	f_e\frac{B^2}{8\pi}.
	\label{eq:nth_energy}
\end{equation}
The mean Lorentz factor is
\begin{equation}
	\langle\gamma\rangle
	=
	\frac{1}{n_{e,\mathrm{nth}}}
	\int_{\gmin}^{\gmax}
	\gamma N(\gamma)\,d\gamma
	=
	\int_{\gmin}^{\gmax}
	\gamma A_{\rm norm}f(\gamma)\,d\gamma,
	\label{eq:mean_gamma}
\end{equation}
where $A_{\rm norm}f(\gamma)$ is normalized to unit integral.

Solving Eq.~\eqref{eq:nth_energy} gives
\begin{equation}
	n_{e,\mathrm{nth}}
	=
	\frac{
		f_e B^2/(8\pi)
	}{
		\langle\gamma\rangle m_ec^2
	}.
	\label{eq:nth_dens}
\end{equation}

In addition to the electron-energy assignment in
Eq.~\eqref{eq:nth_energy}, the current implementation applies a more
stringent baryonic-loading constraint. Assuming one proton is associated
with each accelerated electron, it requires
\begin{equation}
	n_{e,\mathrm{nth}}m_pc^2
	<
	\frac{B^2}{8\pi}.
	\label{eq:baryonic_loading}
\end{equation}
Combining Eqs.~\eqref{eq:nth_energy} and
\eqref{eq:baryonic_loading} gives
\begin{equation}
	f_e
	<
	\langle\gamma\rangle\frac{m_e}{m_p}.
	\label{eq:fe_constraint}
\end{equation}
This is the condition checked by
\code{calculateNonthermalElectronDens}. Because $m_p\gg m_e$, it is
more restrictive than requiring the nonthermal electron energy alone
to remain below the magnetic energy density.

\begin{implementationnote}
	The current source always applies the baryonic form
	Eq.~\eqref{eq:fe_constraint}; it does not select $m_e$ or $m_p$ from a
	runtime composition setting. For a purely leptonic or pair-dominated
	outflow, the custom-outflow capability may be used to provide
	$n_{e,\mathrm{nth}}$ directly, or the source guard must be generalized
	to include an explicit composition model.
\end{implementationnote}

\subsubsection{Universal Spectral Tables}
\label{sec:tables}
% ??????????????????????????????????????????????????????????????????????????????

Many of the integrals that appear in synchrotron physics depend only on a
dimensionless frequency ratio $x$, not on the specific values of $B$ or
$\nu_f$ in a given cell.  \mcrat{} exploits this by precomputing two
universal functions once at startup and storing them as spline-interpolated
lookup tables, avoiding expensive numerical integration at every transport
step.

\paragraph{\texorpdfstring{$F(x)$}{F(x)} ? single-electron synchrotron
	spectrum}
\label{sec:Fx}

The power radiated by a single relativistic electron in a magnetic field at
a frequency characterised by the dimensionless ratio $x$ is proportional to
\citep[\raikou{} Eq.~B13; R\&L79 Eq.~6.31]{kawashima2023,rybicki1979}:
\begin{equation}
	F(x) = x \int_x^{\infty} K_{5/3}(\xi)\,d\xi,
	\label{eq:Fx}
\end{equation}
where $K_{5/3}$ is the modified Bessel function of order $5/3$.  The
argument $x$ is the ratio of the photon frequency to the characteristic
frequency of an electron with Lorentz factor $\gamma$:
\begin{equation}
	x = \frac{\nuf}{\gamma^2\,\nuc}, \qquad
	\nuc = \frac{3\,e\,B}{4\pi\,m_e\,c},
	\label{eq:xdef}
\end{equation}
where $\nuc$ is the pitch-angle--averaged critical frequency
\citep[R\&L79 Eq.~6.17c, pitch-angle averaged]{rybicki1979}. Note that
\raikou{} Eq.~B7 gives the distinct \emph{thermal} characteristic
frequency $\nu_s\propto\Theta_e^2\sin\theta_B$ and is not the quantity
used here; the non-thermal $\nuc=3eB/(4\pi m_ec)$ adopted by \mcrat{}
is the standard Rybicki--Lightman form.

$F(x)$ peaks near $x \approx 0.3$ and decays exponentially for $x \gg 1$,
so most synchrotron emission comes from electrons whose critical frequency
matches the photon frequency.  The function is tabulated on a log-spaced
grid of \code{SYNCH\_N\_X} points over
$x \in [\code{SYNCH\_X\_MIN}, \code{SYNCH\_X\_MAX}]$ using GSL adaptive
quadrature. In the current \code{mc\_synchrotron.h} these default to
\code{SYNCH\_N\_X}$=2000$, \code{SYNCH\_X\_MIN}$=10^{-5}$, and
\code{SYNCH\_X\_MAX}$=50$; a reader changing these macros should treat the
numerical bounds here as illustrative of the defaults only.

\paragraph{\texorpdfstring{$G_a(x;\,p)$}{Ga(x,p)} ? absorption spectral
	integral}
\label{sec:Ga}

The self-absorption coefficient involves a second universal function
\citep[\raikou{} Eq.~C3]{kawashima2023}:
\begin{equation}
	G_a(x;\,p) = \int_x^{\infty} z^{(p-2)/2}\,F(z)\,dz,
	\label{eq:Ga}
\end{equation}
which is the integral of $F(z)$ weighted by $z^{(p-2)/2}$ from $x$ to
infinity.  For a single power law one table is built at the index $p$; for a
broken power law two tables are built at $p_1$ and $p_2$ respectively.

\begin{keyresult}
	Both $F(x)$ and $G_a(x;p)$ are evaluated at runtime not by simple
	clamping at the table boundaries $[\code{SYNCH\_X\_MIN},
	\code{SYNCH\_X\_MAX}]$, but by an \emph{analytic continuation} below
	$x_0\equiv\code{SYNCH\_X\_MIN}$. This continuation uses the physical
	low-frequency asymptote of the single-electron spectrum
	\citep[R\&L79 Eq.~6.31b]{rybicki1979},
	\begin{equation}
		F(x) \sim F(x_0)\,(x/x_0)^{1/3}, \qquad x \ll x_0,
		\label{eq:F_asymptote}
	\end{equation}
	implemented in \code{evalF}. For $x<x_0$, split the definition of
	$G_a$ at the lower table boundary,
	\begin{equation}
		G_a(x;p)
		=
		G_a(x_0;p)
		+
		\int_x^{x_0} z^{(p-2)/2}F(z)\,dz,
	\end{equation}
	and substitute the asymptote \eqref{eq:F_asymptote} into the added
	segment:
	\begin{equation}
		G_a(x;p)-G_a(x_0;p)
		\simeq
		\frac{F(x_0)}{x_0^{1/3}}
		\int_x^{x_0} z^{(p-2)/2+1/3}\,dz
		=
		\frac{F(x_0)}{x_0^{1/3}\,q}
		\Bigl(x_0^{\,q}-x^{\,q}\Bigr),
		\qquad
		q \equiv \frac{p-2}{2}+\frac13+1=\frac{p}{2}+\frac13,
		\label{eq:Ga_extension}
	\end{equation}
	where the final $+1$ in the exponent arises because integrating
	$z^{a}$ produces $z^{a+1}/(a+1)$. For $x<x_0$ this gives
	\begin{equation}
		G_a(x;p) = G_a(x_0;p)
		+ \frac{F(x_0)}{x_0^{1/3}\,q}\Bigl(x_0^{\,q} - x^{\,q}\Bigr),
		\qquad q = \frac{p}{2}+\frac13,
		\qquad x < x_0.
	\end{equation}
	This is implemented by \code{evalGa\_p} (the evaluator actually
	called by \code{synchAlphaNu}), which computes exactly
	\code{q = 0.5 * p + (1.0/3.0)}, matching the derivation above. Since
	$q>0$ for all physical $p>1$, $x^q\to0$ as $x\to0$, so $G_a(x;p)$
	grows smoothly and remains finite as $x\to0$ rather than being held
	flat at its tabulated boundary value. This is what allows
	$\alpha_{\nuf}^{(f)}$ to exhibit the correct soft SSA turnover at low
	$\nuf$ (rather than an artificially flattened one) whenever
	$x_{\min}=\nuf/(\gmax^2\nuc)$ falls below \code{SYNCH\_X\_MIN} ? a
	realistic occurrence for high-$B$, low-frequency cells. In this
	finite-electron-bound regime the continuation also recovers the
	expected index-independent scaling
	\begin{equation}
		\alpha_{\nuf}^{(f)}
		\;\propto\;
		\left(\frac{\nuf}{\nuc}\right)^{-(p+4)/2}
		\,x_{\max}^{\,q}
		\;\propto\;
		\nuf^{-(p+4)/2}\,\nuf^{\,q}
		\;=\;
		\nuf^{-(p+4)/2 + p/2 + 1/3}
		\;=\;
		\nuf^{-5/3},
		\label{eq:alpha_low_frequency}
	\end{equation}
	where $q=p/2+1/3$ from Eq.~\eqref{eq:Ga_extension} and the explicit
	$p$-dependence cancels, leaving the index-independent exponent $-5/3$.
\end{keyresult}

\paragraph{Thread Safety and Per-Thread Accelerators}
\label{sec:thread}

Several of the precomputed tables in \mcrat{} ? the synchrotron universal
spectral tables (Section~\ref{sec:tables}) and the hot cross section tables
(Section~\ref{sec:hot_xsection}) ? are evaluated at runtime via GSL spline
interpolation.  GSL spline evaluation requires a \code{gsl\_interp\_accel}
object, which caches the most recently used interval index to accelerate
repeated lookups via bisection.  These accelerator objects are \emph{not}
thread-safe: if two OpenMP threads share a single accelerator and call
\code{gsl\_spline\_eval} (or \code{gsl\_spline2d\_eval}) concurrently, the
cached state is corrupted, producing incorrect interpolated values or a
segmentation fault.

\mcrat{} resolves this by allocating one independent set of accelerator
objects per OpenMP thread at initialisation time.  Two patterns are used,
one for each table family:

\paragraph{Synchrotron tables (\texttt{SynchThreadAccel}).}
The struct \code{SynchThreadAccel} holds a complete set of
\code{gsl\_interp\_accel} pointers for every \emph{spline-based}
lookup in the synchrotron universal tables: the $F(x)$ spline, the
$G_a(x)$ spline (or splines, for the broken power law), and the
inverse single-electron-$x$ CDF spline and inverse pitch-angle CDF
spline used by \code{synchSampleX} and \code{synchSampleAlpha}
respectively. The latter two samplers draw a single-electron emission
angle/frequency directly from $F(x)$ and are retained primarily for
use by the cyclosynchrotron module (\code{mc\_cyclosynch.c}); they are
\emph{not} called along the stratified non-thermal emission path
described in Section~\ref{sec:strata} of this document.

\begin{keyresult}
	The stratified frequency sampler \code{sampleSynchFrequency}, which
	\emph{is} the sampler used by \code{emitCellPackets} in the emission
	path documented in Section~\ref{sec:strata}, does \emph{not} use any
	GSL spline or any \code{SynchThreadAccel} field. It performs a manual
	binary search directly on the raw universal-CDF arrays
	\code{nu\_cdf\_u}/\code{nu\_cdf\_log\_nu\_tilde} built by
	\code{buildUniversalNuCDF}, followed by linear interpolation between
	the two bracketing points. Because this search operates on plain
	arrays rather than a \code{gsl\_spline} object, it requires no
	accelerator at all and is trivially thread-safe without any
	per-thread state.
\end{keyresult}

One \code{SynchThreadAccel} is allocated per
thread in a file-scope array \code{synch\_thread\_accels} during
\code{initSynchTables}. The helper function \code{getSynchAccel} returns
a pointer to the accelerator for the calling thread:
\begin{verbatim}
	static SynchThreadAccel *getSynchAccel(void)
	{
		int thread_id = 0;
		#if defined(_OPENMP)
		thread_id = omp_get_thread_num();
		#endif
		if (thread_id >= synch_num_threads_allocated)
		thread_id = 0;
		return &synch_thread_accels[thread_id];
	}
\end{verbatim}
Every call to \code{gsl\_spline\_eval} or \code{gsl\_spline2d\_eval} on a
synchrotron table (i.e.\ evaluations of $F(x)$, $G_a(x)$, or the
legacy single-electron $x$/pitch-angle inverse CDFs) passes
\code{getSynchAccel()->...} as the accelerator argument, ensuring no
two threads share state.

\paragraph{Hot cross-section tables (\texttt{ThreadLocalAccel}).}
On MPI rank zero, \code{initalizeHotCrossSectionInterp} constructs the
thermal and nonthermal interpolation splines and initializes one
\code{ThreadLocalAccel} structure per OpenMP thread.

Non-root MPI ranks reconstruct the interpolation splines after
\code{broadcastInterpolationData}. In the current source they do not
subsequently call \code{initThreadLocalAccelerators}. Their interpolation
functions therefore use the safe fallback path, which allocates temporary
accelerators for an out-of-range or unavailable thread-local slot. This
fallback is thread-safe, but it is slower than persistent per-thread
accelerators.

For consistent performance on every MPI rank,
\code{initThreadLocalAccelerators(omp\_get\_max\_threads())} should be
called after the interpolation structures have been constructed on each
rank.

\paragraph{Global RNG pool (\texttt{global\_thread\_rng}).}
The same per-thread pattern is applied to the GSL random number generators.
\code{initGlobalThreadRNG} allocates one \code{gsl\_rng} per thread,
seeding each from the master RNG.  All functions that require random numbers
inside a parallel region retrieve their thread-local generator via
\code{global\_thread\_rng[omp\_get\_thread\_num()]}, avoiding contention
on a shared generator.

\begin{keyresult}
	All shared read-only state (spline coefficients, table data) is accessed
	concurrently by multiple threads without locks, since GSL spline evaluation
	is read-only with respect to the spline object itself.  All mutable
	per-evaluation state (accelerator caches, RNG state) is strictly private to
	each thread via the per-thread allocation described above.  No
	\code{\#pragma omp critical} sections are required for table lookups or
	random number generation.
\end{keyresult}

\subsubsection{Photon Emission}
\label{sec:emission}
% ??????????????????????????????????????????????????????????????????????????????

New synchrotron photon packets are injected into the simulation at each hydro
frame by \code{photonEmitSynch} (\code{mc\_synchrotron.c}).  The procedure
proceeds in four stages, corresponding to
Sections~\ref{sec:emissivity}--\ref{sec:kinematics} below: (1) computing the
physical photon production rate and Poisson-drawing packet counts per cell
(\S\ref{sec:emissivity}--\ref{sec:packet_count}); (2) sampling a
dimensionless frequency from the universal, stratified photon-number CDF
(\S\ref{sec:strata}); (3) filling in the packet's comoving 4-momentum,
Lorentz boost, birth position, and Stokes parameters
(\S\ref{sec:kinematics}); and (4) appending the resulting packets to
\code{photon\_list} for transport.

\paragraph{Physical photon emission rate and cell weights}
\label{sec:emissivity}

The starting point for non-thermal synchrotron emission is the
pitch-angle?averaged single-electron spectrum \(F(x)\) introduced in
Section~\ref{sec:Fx}. 

For a power-law electron distribution written as
\begin{equation}
	N(\gamma)
	=
	\nenth A_{\rm norm}\gamma^{-p},
	\qquad
	\gmin\le\gamma\le\gmax,
\end{equation}
the pitch-angle-averaged synchrotron energy emissivity in the fluid
frame has the schematic form
\begin{equation}
	j_{\nuf}^{(f)}
	\propto
	\nenth A_{\rm norm}B
	\int_{\gmin}^{\gmax}
	\gamma^{1-p}
	F\!\left(\frac{\nuf}{\gamma^2\nuc}\right)
	d\ln\gamma .
	\label{eq:jnu_schematic}
\end{equation}
where \(\nuc = 3 e B/(4\pi m_e c)\) is the pitch-angle?averaged critical
frequency. Here $A_{\rm norm}$ is dimensionless. The full normalization introduced
in Section~\ref{sec:spl} is
$A=\nenth A_{\rm norm}$ and must not be multiplied by $\nenth$ a
second time. The exact prefactors and detailed form of the integral are
spelled out in \raikou{}; here we focus on how \mcrat{} turns this
emissivity into a \emph{photon-number} production rate that can be used
for Monte Carlo emission.

The \emph{photon-number} emissivity ? the rate at which photons of
frequency \(\nuf\) are produced per unit volume, per unit frequency ? is
obtained by dividing by the energy per photon \(h\nuf\):
\begin{equation}
	\dot{n}_{\nuf}^{(f)}
	= \frac{j_{\nuf}^{(f)}}{h\nuf}
	\quad
	\bigl[\mathrm{photons\ cm^{-3}\ s^{-1}\ Hz^{-1}}\bigr].
	\label{eq:ndot_nu}
\end{equation}
\mcrat{} uses the fact that the spectrum depends only on the
dimensionless ratio \(\nuth = \nuf/\nuc\) and the power-law index \(p\),
so the \emph{shape} of the photon-number emissivity can be precomputed
once and reused in all cells.

The total number of photons produced per unit time in cell \(i\),
integrated over all frequencies, is
\begin{equation}
	\dot{N}_i
	= V_i \int_0^\infty \dot{n}_{\nuf}^{(f)}\,d\nuf
	= \frac{V_i}{h}
	\int_0^\infty \frac{j_{\nuf}^{(f)}}{\nuf}\,d\nuf,
	\label{eq:Ndot_total}
\end{equation}
where \(V_i\) is the cell volume. After substituting
Eq.~\eqref{eq:jnu_schematic} and changing variables to
\(\nuth = \nuf/\nuc\), the cell-dependent factors separate cleanly and
the photon production rate per simulation frame
\(\Delta t_{\rm fps} = 1/\text{fps}\) can be written as
\begin{equation}
	\Lambda_i \equiv W_i
	= K_{\rm phys}\,\nenth^{(i)}\,B_i\,V_i
	\quad
	\bigl[\mathrm{photons\ frame^{-1}}\bigr].
\end{equation}
Here \(K_{\rm phys}\) is a cell-independent emission-rate prefactor
evaluated once per call to \code{photonEmitSynch}. It depends on the
compile-time electron-distribution parameters, the universal table
normalisation constructed at startup, and the current value of
\code{hydro\_data->fps}:
\begin{equation}
	K_{\rm phys}
	=
	\frac{\sqrt{3}\,e^3}{m_e c^2 h}\,
	A_{\rm norm}\,
	\ln(10)^2\,
	\nu_{\rm cdf\_norm}\,
	\Delta t_{\rm fps},
	\qquad
	\Delta t_{\rm fps}
	\equiv
	\frac{1}{\mathrm{fps}}.
	\label{eq:Kphys}
\end{equation}

The absence of an additional factor of \(1/2\) reflects the convention
used by the updated implementation: the single-electron synchrotron
spectral power is pitch-angle averaged and integrated over emission
solid angle. In this convention,
\begin{equation}
	P_{\nu_f}(\gamma)
	=
	\frac{\sqrt{3}\,e^3B}{m_ec^2}
	F\!\left(\frac{\nu_f}{\gamma^2\nu_c}\right),
	\label{eq:single_electron_power}
\end{equation}
and the cell photon-production rate follows directly from integrating
\(P_{\nu_f}/(h\nu_f)\) over photon frequency and the electron
distribution.

The remaining factors in Eq.~\eqref{eq:Kphys} have the following
origins:
\begin{itemize}
	\item \(A_{\rm norm}\) is the dimensionless electron-distribution
	normalisation, defined by
	\(N(\gamma)=n_{e,\mathrm{nth}}A_{\rm norm}f(\gamma)\).
	\item \(\nu_{\rm cdf\_norm}\) is the unnormalised numerical
	double integral over \(\log_{10}\tilde{\nu}\) and
	\(\log_{10}\gamma\), constructed by
	\code{buildUniversalNuCDF}.
	\item The factor \(\ln(10)^2\) converts both base-10 logarithmic
	integration measures to natural-logarithmic measures.
	\item \(\Delta t_{\rm fps}=1/\mathrm{fps}\) converts photons per
	second to photons per simulation frame.
\end{itemize}

The resulting physical photon count emitted by cell \(i\) during one
simulation frame is
\begin{equation}
	W_i
	=
	K_{\rm phys}\,
	n_{e,\mathrm{nth}}^{(i)}\,
	B_i\,
	V_i
	\qquad
	[\mathrm{photons\ frame^{-1}}].
	\label{eq:W_cell}
\end{equation}

The implementation evaluates the absolute photon-production rate without
an arbitrary proportionality constant. Its numerical value is determined
by the adopted pitch-angle/solid-angle convention and by the finite
$\tilde{\nu}$ and $\gamma$ integration grids used to construct
\code{nu\_cdf\_norm}. Convergence should therefore be checked with respect
to \code{SYNCH\_N\_NU}, \code{SYNCH\_N\_GAMMA\_INT}, and the table
boundaries.

\begin{keyresult}
	$K_{\rm phys}$'s final factor converts a rate in photons\,s$^{-1}$ to a
	rate in photons\,frame$^{-1}$. This requires \emph{dividing} by
	\code{fps}, i.e.\ multiplying by $\Delta t_{\rm fps} = 1/\mathrm{fps}$,
	as written in Eq.~\eqref{eq:Kphys} above and exactly as computed by
	\texttt{photonEmitSynch} (\texttt{K\_phys \ldots\ / hydro\_data->fps}).
\end{keyresult}

\begin{keyresult}
	\(W_i = K_{\rm phys}\,\nenth^{(i)}\,B_i\,V_i\) is the \emph{expected physical
		photon count} emitted by cell \(i\) \emph{per simulation frame}
	[photons\,frame$^{-1}$] --- i.e.\ the per-second production rate already
	multiplied by the frame duration $\Delta t_{\rm fps}=1/\mathrm{fps}$ --- not
	a mere proportionality constant. We reserve the word ``rate'' for
	per-second quantities and ``count'' for the per-frame $W_i$.
	
	Note that \(W_i\) scales \emph{linearly} with
	\(B\), not \(B^2\): one power of \(\nuc \propto B\) in the numerator of
	\(j_{\nuf}^{(f)}\) is cancelled by one power of \(\nuf \propto \nuc\) in
	the denominator of \(j_{\nuf}^{(f)}/(h\nuf)\).
\end{keyresult}

Each photon packet in \mcrat{} carries a weight \(w_0\)
[photons\,packet\(^{-1}\)] representing the number of real photons it
stands in for. Since \(W_i\) already has units of
photons\,frame\(^{-1}\), the expected number of packets drawn from cell
\(i\) is simply
\begin{equation}
	\lambda_i = \frac{W_i}{w_0}
	\quad
	\bigl[\text{packets frame}^{-1}\bigr].
	\label{eq:lambda}
\end{equation}
No additional fps factor is needed elsewhere in the emission procedure.
A Poisson draw with mean \(\lambda_i\) gives the actual packet count
\(n_i\) for cell \(i\); the combination of Eqs.~\eqref{eq:W_cell} and
\eqref{eq:lambda} guarantees that the \emph{expected} total weight
carried by all packets from cell \(i\) equals the physical number of
photons \(\Lambda_i\) emitted per frame.

\paragraph{Universal photon-number emissivity}
\label{sec:photon_number_emissivity}

The implementation is most transparently derived from the
pitch-angle-averaged, solid-angle-integrated single-electron spectral
power,
\begin{equation}
	P_{\nu_f}(\gamma)
	=
	\frac{\sqrt{3}\,e^3B}{m_ec^2}
	F\!\left(\frac{\nu_f}{\gamma^2\nu_c}\right),
	\qquad
	\nu_c
	=
	\frac{3eB}{4\pi m_ec}.
	\label{eq:Pnu_electron}
\end{equation}
This convention is the one used to construct the updated physical
prefactor in \code{photonEmitSynch}.

For any normalized nonthermal electron distribution written as
\begin{equation}
	N(\gamma)
	=
	n_{e,\mathrm{nth}}A_{\rm norm}f(\gamma),
	\qquad
	\int_{\gamma_{\min}}^{\gamma_{\max}}
	A_{\rm norm}f(\gamma)\,d\gamma
	=
	1,
	\label{eq:general_electron_distribution}
\end{equation}
the energy emitted per unit volume, time, and frequency is
\begin{equation}
	\mathcal{P}_{\nu_f}
	=
	n_{e,\mathrm{nth}}A_{\rm norm}
	\frac{\sqrt{3}\,e^3B}{m_ec^2}
	\int_{\gamma_{\min}}^{\gamma_{\max}}
	f(\gamma)
	F\!\left(\frac{\nu_f}{\gamma^2\nu_c}\right)
	d\gamma .
	\label{eq:energy_emissivity_general}
\end{equation}

The photon-number emissivity per unit linear frequency is obtained by
dividing by the photon energy:
\begin{equation}
	\dot n_{\nu_f}
	=
	\frac{\mathcal{P}_{\nu_f}}{h\nu_f}.
	\label{eq:number_emissivity_linear}
\end{equation}
The explicit factor \(1/\nu_f\) disappears only when the integration is
written in logarithmic frequency:
\begin{equation}
	\dot n_{\nu_f}\,d\nu_f
	=
	\frac{\mathcal{P}_{\nu_f}}{h}\,d\ln\nu_f.
	\label{eq:number_emissivity_log}
\end{equation}

Define the dimensionless frequency
\begin{equation}
	\tilde{\nu}
	\equiv
	\frac{\nu_f}{\nu_c}.
	\label{eq:nu_tilde}
\end{equation}
Since \(d\ln\nu_f=d\ln\tilde{\nu}\), all magnetic-field dependence
separates from the dimensionless spectral shape.

For a single power law,
\begin{equation}
	f(\gamma)=\gamma^{-p},
\end{equation}
and the dimensionless photon-number kernel per unit
\(\ln\tilde{\nu}\) is
\begin{equation}
	\Phi(\tilde{\nu})
	=
	\int_{\ln\gamma_{\min}}^{\ln\gamma_{\max}}
	\gamma^{1-p}
	F\!\left(\frac{\tilde{\nu}}{\gamma^2}\right)
	d\ln\gamma .
	\label{eq:single_pl_kernel}
\end{equation}

For a broken power law,
\begin{equation}
	f(\gamma)
	=
	\begin{cases}
		\gamma^{-p_1},
		& \gamma_{\min}\le\gamma\le\gamma_{\mathrm{br}},\\[4pt]
		C_{\mathrm{cont}}\gamma^{-p_2},
		& \gamma_{\mathrm{br}}<\gamma\le\gamma_{\max},
	\end{cases}
	\qquad
	C_{\mathrm{cont}}
	=
	\gamma_{\mathrm{br}}^{p_2-p_1},
	\label{eq:bpl_kernel_definition}
\end{equation}
the corresponding kernel is
\begin{align}
	\Phi_{\mathrm{br}}(\tilde{\nu})
	={}&
	\int_{\ln\gamma_{\min}}^{\ln\gamma_{\mathrm{br}}}
	\gamma^{1-p_1}
	F\!\left(\frac{\tilde{\nu}}{\gamma^2}\right)
	d\ln\gamma
	\nonumber\\
	&+
	C_{\mathrm{cont}}
	\int_{\ln\gamma_{\mathrm{br}}}^{\ln\gamma_{\max}}
	\gamma^{1-p_2}
	F\!\left(\frac{\tilde{\nu}}{\gamma^2}\right)
	d\ln\gamma .
	\label{eq:broken_pl_kernel}
\end{align}

The code evaluates the appropriate kernel numerically on a
\(\log_{10}\tilde{\nu}\)--\(\log_{10}\gamma\) grid. Its unnormalised
double integral is stored as \code{nu\_cdf\_norm}. Therefore,
\begin{equation}
	\int d\ln\tilde{\nu}\,\Phi(\tilde{\nu})
	=
	\ln(10)^2\,\nu_{\mathrm{cdf\_norm}},
	\label{eq:cdf_norm_conversion}
\end{equation}
with the same relation applying to the broken-power-law kernel.

The photon production rate from cell \(i\) during one hydro frame is
then
\begin{equation}
	W_i
	=
	K_{\rm phys}
	n_{e,\mathrm{nth}}^{(i)}
	B_iV_i,
\end{equation}
where \(K_{\rm phys}\) is given by Eq.~\eqref{eq:Kphys}.

\begin{implementationnote}
	The analytic functions \(G(x;p)\) used in closed-form presentations of
	the power-law synchrotron emissivity are useful for comparison with
	\raikou{}, but they are not evaluated by the \mcrat{} emission path.
	\mcrat{} constructs the photon-number kernel directly from \(F(x)\) in
	\code{buildUniversalNuCDF}. This avoids ambiguity between per-solid-angle
	and solid-angle-integrated emissivity conventions.
\end{implementationnote}


\paragraph{Packet weight, weight-tuning loop, and Poisson draw}
\label{sec:packet_count}

Each photon packet carries a weight $w_0$ [photons\,packet$^{-1}$] that
represents the number of real photons it stands in for.  Because $W_i$ is
already the physical photon production rate per frame \eqref{eq:W_cell},
the expected number of packets drawn from cell $i$ is given by
Eq.~\eqref{eq:lambda}, repeated here for convenience:
$$
\lambda_i = \frac{W_i}{w_0}
\quad [\text{packets frame}^{-1}].
$$
No additional fps factor is needed anywhere in the emission procedure.

Because $w_0$ is a free parameter, it is adjusted iteratively before the
Poisson draw so that the total expected packet count lies within
user-specified bounds $[N_{\min},\, N_{\max}]$:
\begin{equation}
	N_{\min} \;\le\; \sum_i \frac{W_i}{w_0} \;\le\; N_{\max}.
	\label{eq:weight_tune}
\end{equation}
The loop multiplies $w_0$ by 10 when $\sum_i\lambda_i > N_{\max}$ and by
0.5 when $\sum_i\lambda_i < N_{\min}$, until \eqref{eq:weight_tune} is
satisfied.  The converged value is stored as \code{ph\_weight\_adjusted}.

Once $w_0$ has converged, the actual packet count per cell is drawn from a
Poisson distribution:
\begin{equation}
	n_i \;\sim\; \mathrm{Poisson}\!\left(\frac{W_i}{w_0}\right),
	\label{eq:poisson}
\end{equation}
The Poisson draw produces the Monte Carlo fluctuation associated with the
finite number of sampled packets. Because
$\mathbb{E}[n_iw_0]=W_i$, the emitted photon-number estimator is unbiased.
This packet-count variance should not automatically be identified with
the physical photon shot noise of the source, because one packet represents
many physical photons.
The total number of packets to fill is $N_{\rm tot} = \sum_i n_i$.

\paragraph{Degenerate emission fallbacks.}
Two edge cases in \code{emitCellPackets} are handled without contributing
physical weight to the simulation:
\begin{itemize}
	\item \textbf{Nonpositive magnetic field.}
	\code{emitCellPackets} contains a local fallback that would assign
	zero weight and a placeholder frequency if called with
	$B_{\rm cell}\le0$. In the normal emission path, however, such a cell has
	$W_i=0$ and normally draws no packets. If all active cells have zero
	physical emission while \code{min\_photons} is positive, the preceding
	weight-tuning loop has no feasible solution and may fail to converge.
	Users must therefore ensure that cells counted as active have finite,
	positive $B$ and finite, positive $W_i$.
	
	A source-level guard should test
	\begin{equation}
		W_{\rm total}
		=
		\sum_iW_i
	\end{equation}
	before entering the tuning loop and return without emission when
	$W_{\rm total}\le0$.
	
	\item If a stratum $k$ has zero probability mass, $p_k = 0$
	\eqref{eq:pk} (i.e.\ the universal CDF has no support in that
	frequency range), the packets allocated to that stratum are instead
	emitted as zero-weight packets at the stratum's log-frequency
	midpoint, $\nuth = 10^{(\log\nuth^{\min,k}+\log\nuth^{\max,k})/2}$,
	converted to a physical comoving frequency via
	$\nuf = \nuth\,\nuc(B_{\rm cell})$ exactly as in the normal sampling
	path (Section~\ref{sec:strata}), rather than being silently dropped.
	This preserves the exact packet count $n_i$ requested by the Poisson
	draw \eqref{eq:poisson}.
\end{itemize}

\paragraph{Photon-number CDF and stratified frequency sampling}
\label{sec:strata}

For emission, we need to sample photon frequencies according to the
\emph{photon-number} spectrum, i.e. proportional to
\(j_{\nuf}^{(f)}/(h\nuf)\), not to the energy spectrum \(j_{\nuf}^{(f)}\)
alone. In log-frequency space this photon-number spectrum can be written
schematically as
\begin{equation}
	\mathrm{pdf}(\nuth)
	\;\propto\;
	\int_{\gmin}^{\gmax}
	\gamma^{1-p}\,
	F\!\left(\frac{\nuth}{\gamma^2}\right)\,d\ln\gamma,
	\label{eq:pdf_nu}
\end{equation}
where \(\nuth = \nuf/\nuc\). The factor \(\gamma^{1-p}\) comes from
combining the electron power law \(N(\gamma)\propto\gamma^{-p}\), the
single-electron spectrum \(F\), and the kinematic Jacobian that relates
photon frequency to electron Lorentz factor in the pitch-angle?averaged
formalism.

\mcrat{} exploits the fact that Eq.~\eqref{eq:pdf_nu} depends only on
\(\nuth\), \(p\), and the electron distribution parameters, not on the
cell?s magnetic field \(B\) or volume \(V_i\). At startup,
\texttt{buildUniversalNuCDF} evaluates Eq.~\eqref{eq:pdf_nu} on a grid
of \(\log_{10}\nuth\) values and constructs a single, universal CDF
\(\mathrm{CDF}(\nuth)\) and its normalisation \texttt{nu\_cdf\_norm}.
This CDF encodes the photon-number emissivity shape in
dimensionless frequency and is reused in every cell.

To improve sampling of the spectral tails, the log-frequency axis is
divided into \(K = \code{SYNCH\_N\_STRATA}\) equal intervals
(\emph{strata}). Let \(\nuth^{\min,k}\) and \(\nuth^{\max,k}\) be the
edges of stratum \(k\), and define its probability mass
\begin{equation}
	p_k
	= \mathrm{CDF}(\nuth^{\max,k}) - \mathrm{CDF}(\nuth^{\min,k}),
	\qquad k = 0,\ldots,K-1.
	\label{eq:pk}
\end{equation}
These \(p_k\) are computed once from the universal CDF and stored in
\texttt{tables->strata\_p\_k[k]}.

For a given cell with \(n_i\) packets, \texttt{emitCellPackets} divides
the packets as equally as possible across strata (with any remainder
distributed to the lowest-indexed strata). Each packet in stratum \(k\)
is assigned an importance weight
\begin{equation}
	w_k = w_0\,p_k\,K,
	\label{eq:wk}
\end{equation}
where \(w_0\) is the baseline packet weight and \(K\) is the number of
strata. The factor \(p_k K\) corrects for the forced equal allocation
across strata: although we emit roughly \(n_i/K\) packets per stratum,
each packet in stratum \(k\) is up-weighted by \(p_k K\) so that the
\emph{weighted} spectrum matches the true photon-number CDF.

Within each stratum, \texttt{sampleSynchFrequency} draws a uniform
variate
\(u \sim \mathcal{U}(\mathrm{CDF}(\nuth^{\min,k}),\mathrm{CDF}(\nuth^{\max,k}))\),
inverts the universal CDF to obtain \(\log_{10}\nuth\), and then
rescales by the cell?s critical frequency \(\nuc(B_i)\) to get the
physical comoving frequency \(\nuf = \nuth\,\nuc(B_i)\).

\begin{knownissue}
	The importance weight
	\begin{equation}
		w_k
		=
		w_0p_kK
	\end{equation}
	is exact when every stratum receives the same packet count, for example
	when \(n_i\) is divisible by the number of strata \(K\). The current
	implementation distributes the integer remainder to the lowest-indexed
	strata:
	\begin{equation}
		n_k
		=
		\left\lfloor\frac{n_i}{K}\right\rfloor
		+
		\mathbf{1}_{k<n_i\bmod K}.
	\end{equation}
	Consequently, the emitted cell weight is
	\begin{equation}
		W_{\rm MC}
		=
		w_0K\sum_k n_kp_k,
	\end{equation}
	which is not generally identical to \(n_iw_0\).
	
	If \(n_i<K\), some strata receive no packets. Any nonzero probability
	mass in those unsampled strata cannot be recovered by importance
	weighting. The present scheme should therefore be described as an
	approximately weight-corrected stratification when the packet allocation
	is nearly equal and all relevant strata are populated.
	
	For exact cell-level weight conservation in every populated stratum,
	one may instead use
	\begin{equation}
		w_k
		=
		w_0\frac{n_ip_k}{n_k},
	\end{equation}
	provided every stratum with \(p_k>0\) has \(n_k>0\).
\end{knownissue}

\paragraph{Single-photon kinematics (\texttt{synchFillPhoton})}
\label{sec:kinematics}

Once \(\nuf\) and \(w_k\) are determined, \code{synchFillPhoton} fills
the full photon-packet state:

\begin{enumerate}[leftmargin=2em]
	\item \textbf{Comoving 4-momentum.}
	The comoving-frame photon energy-momentum magnitude is
	\(|\mathbf{p}| = h\nuf/c\). An emission direction
	\((\theta_{\rm ph}, \phi_{\rm ph})\) is sampled by calling
	\code{samplePhotonTheta} and \code{samplePhotonPhi}. The azimuthal
	angle \(\phi_{\rm ph}\) is drawn uniformly from \([0,2\pi)\). The
	polar angle \(\theta_{\rm ph}\) is drawn from a distribution
	\begin{equation}
		f(\mu) \propto \tfrac{1}{2}\bigl(1 + \beta\,\mu\bigr),
		\qquad \mu = \cos\theta_{\rm ph},
	\end{equation}
	where \(\beta = v/c\) is the magnitude of the cell?s fluid velocity
	and the proportionality constant ensures proper normalisation over
	\(\mu\in[-1,1]\). 
	This distribution slightly favours emission along
	the fluid velocity when \(\beta>0\); it is motivated by earlier work
	on anisotropic injection in hot flows. 
	The helper \code{samplePhotonTheta} is intended to draw
	$f(\mu)=\tfrac12(1+\beta\mu)$. As documented below, the current call
	order and direction construction do not reliably realize this
	distribution relative to the local fluid velocity.
	A purely isotropic emission
	model in the fluid frame would instead use
	\(f(\mu) = \tfrac{1}{2}\) (uniform in \(\cos\theta_{\rm ph}\)).
	
	In the current implementation, this mild anisotropy is applied even
	for synchrotron emission. It is therefore important to remember that
	while the \emph{microphysics} (pitch-angle?averaged emissivity and
	absorption) assumes an isotropic electron distribution, the
	\emph{emission} direction sampling in \code{synchFillPhoton} is slightly
	biased with respect to the fluid velocity.
	
	\item \textbf{Lorentz boost.}
	The comoving 4-momentum
	\(p^{\mu}_{\rm comv} = (h\nuf/c)(1,\hat{\mathbf{n}}_{\rm comv})\) is
	boosted to the lab frame using the exact Lorentz transformation for
	a fluid element with velocity \(\mathbf{v}_{\rm fluid}\). The same
	fluid velocity that enters the angular sampling is used in the
	boost, ensuring consistent kinematics between emission and
	transport.
	
	\item \textbf{Birth position.}
	The code samples each native hydro coordinate uniformly across the
	coordinate bounds of the emitting cell and then converts the sampled
	point to \mcrat{} Cartesian coordinates. This is exactly uniform in physical
	volume for Cartesian cells. In curvilinear coordinates it is uniform in
	the coordinate variables, not generally in the physical volume element;
	see the known issue below.
	
	\item \textbf{Stokes parameters.}
	The packet is born unpolarised, with Stokes vector
	\((i, q, u, v) = (1, 0, 0, 0)\). Synchrotron polarisation
	is not yet modelled.
	
	\item \textbf{Bookkeeping.}
	The packet type is set to \code{SYNCH\_PHOTON}; the flag
	\code{recalc\_properties} is set to 1 so that scattering and
	absorption opacities are computed on the first transport step; and
	\code{absorption\_opacity} is initialised to zero.
\end{enumerate}

\begin{knownissue}
	For spherical, cylindrical, and polar grids, uniform sampling of the
	native coordinates does not produce a uniform physical-volume
	distribution because the volume element contains a coordinate Jacobian.
	
	For example, a spherical cell has
	\begin{equation}
		dV
		=
		r^2\sin\theta\,dr\,d\theta\,d\phi.
	\end{equation}
	Exact uniform-volume sampling would require
	\begin{align}
		r
		&=
		\left[
		r_{\min}^3
		+
		u_r\left(r_{\max}^3-r_{\min}^3\right)
		\right]^{1/3},\\
		\cos\theta
		&=
		\cos\theta_{\min}
		+
		u_\theta
		\left(
		\cos\theta_{\max}-\cos\theta_{\min}
		\right),\\
		\phi
		&=
		\phi_{\min}
		+
		u_\phi
		\left(\phi_{\max}-\phi_{\min}\right),
	\end{align}
	with independent uniform variates
	$u_r,u_\theta,u_\phi\sim\mathcal{U}(0,1)$.
	
	The current coordinate-uniform sampling is an approximation whose error
	decreases for sufficiently small cells. It should not be described as
	exactly uniform in physical volume for curvilinear geometries.
\end{knownissue}

\begin{knownissue}
	In earlier code revisions, \code{synchFillPhoton} (\code{mc\_synchrotron.c})
	and the legacy blackbody/Wien photon-injection routine
	\code{photonInjection} (\code{mclib.c}) both called
	\code{samplePhotonTheta(boost,\ldots)} before \code{boost} had been
	populated by \code{hydroVectorToCartesian}, so that the polar angle
	was sampled using an undefined value of the fluid speed
	$\beta=\|\code{boost}\|$. \textbf{This use-before-initialization
		defect has been fixed}: both functions now call
	\code{hydroVectorToCartesian} to populate the local fluid-velocity
	vector \emph{before} the corresponding call to
	\code{samplePhotonTheta}, so $\beta$ is now a well-defined, correctly
	computed quantity at the point of sampling.
	
	A second, independent limitation remains in the current code.
	\code{samplePhotonTheta} uses only the \emph{magnitude}
	$\beta=\|\code{boost}\|$ of the supplied velocity, not its direction.
	The direction subsequently constructed as
	\begin{equation}
		\hat{\mathbf n}_{\rm comv}
		=
		\left(
		\sin\theta\cos\phi,\,
		\sin\theta\sin\phi,\,
		\cos\theta
		\right)
	\end{equation}
	is expressed relative to the code's Cartesian $z$-axis, not relative
	to $\hat{\mathbf v}_{\rm fluid}$. Consequently, even with $\beta$ now
	correctly defined, the sampled direction does not generally realize
	the intended distribution $f(\mu)=\tfrac12(1+\beta\mu)$ with
	$\mu=\hat{\mathbf n}_{\rm comv}\cdot\hat{\mathbf v}_{\rm fluid}$,
	except in the degenerate case where the local fluid velocity happens
	to be aligned with the $z$-axis. Fully realizing the intended
	anisotropic distribution would additionally require rotating the
	sampled direction into an orthonormal basis whose polar axis is the
	local fluid-velocity direction. Alternatively, if strictly isotropic
	emission in the fluid frame is intended (as assumed by the
	pitch-angle-averaged microphysics of
	Section~\ref{sec:assumptions}), \code{samplePhotonTheta} should
	instead sample $\mu=\cos\theta_{\rm ph}\sim\mathcal U(-1,1)$
	independently of $\beta$.
\end{knownissue}

\begin{keyresult}
	The synchrotron microphysics in \mcrat{} (emissivity and self-absorption)
	assumes a pitch-angle?averaged, isotropic electron population in the
	fluid frame. The current emission-angle sampler introduces a mild
	anisotropy tied to the fluid velocity via \(f(\mu)\propto 1+\beta\mu\).
	If strictly isotropic emission in the fluid frame is desired, the
	implementation of \code{samplePhotonTheta} should be modified to sample
	\(\cos\theta_{\rm ph}\) uniformly in \([-1,1]\) instead.
\end{keyresult}

\paragraph{Modelling assumptions for synchrotron emission}
\label{sec:assumptions}

For clarity, we summarize the main physical assumptions underlying the
synchrotron emission and absorption implementation in \mcrat{}:

\begin{itemize}
	\item \textbf{Pitch-angle?averaged, isotropic electrons.}
	The non-thermal electron distribution in each cell depends only on
	Lorentz factor \(\gamma\) and is assumed isotropic in pitch angle.
	All synchrotron emissivity and absorption formulas are taken in
	their pitch-angle?averaged, angle-integrated form.
	
	\item \textbf{Photon-number, not energy, sampling.}
	Emission is sampled from the photon-number spectrum
	\(j_{\nuf}^{(f)}/(h\nuf)\) in log-frequency space, using a universal
	CDF over \(\nuth = \nuf/\nuc\). Packet weights represent real photon
	counts.
	
	\item \textbf{Mild anisotropy tied to fluid velocity (partially
		implemented).} The angular sampler \code{samplePhotonTheta} is
	intended to draw $f(\mu)\propto1+\beta\mu$ relative to the fluid
	velocity. The use-before-initialization defect that previously
	left $\beta$ undefined at the point of sampling has been fixed
	(Section~\ref{sec:kinematics}): \code{boost} is now populated
	before \code{samplePhotonTheta} is called. However, the sampler
	still does not rotate the sampled direction into a basis aligned
	with the fluid-velocity direction, so the intended
	$\beta$-weighted anisotropy relative to $\hat{\mathbf
		v}_{\rm fluid}$ is still not reliably realized; see
	Section~\ref{sec:kinematics} for the remaining defect and the
	corresponding fix needed.
	
	\item \textbf{Continuous self-absorption.}
	Synchrotron self-absorption is treated via continuous weight
	attenuation with the full relativistic frame correction
	\(\Gamma(1-\beta\cos\theta)\) applied to the comoving absorption
	coefficient. SSA acts only during transport, not at packet birth.
	
	\item \textbf{Importance sampling and bias correction.}
	Scattering events are biased to improve sampling in optically thin
	regions and rare non-thermal electron subgroups. Packet weights are
	split and corrected so that all observables remain statistically
	unbiased \textbf{provided every per-subgroup bias satisfies
		$b_k\ge1$}. As detailed in the erratum in
	Section~\ref{sec:nonthermal_bias}, the $\max(1,\ldots)$ floor that
	enforces $b_k\ge1$ is currently disabled in
	\code{calculateNonthermalScatteringBias}, so this unbiasedness
	guarantee does not strictly hold for the default runtime behaviour
	as shipped; it holds exactly once the floor is restored, or in any
	cell/subgroup combination where $\tau_k \le b_{\rm ref}\,\tau_{\rm ref}$
	so that the unclamped ratio $b_{\rm ref}\tau_{\rm ref}/\tau_k$
	already exceeds unity.
\end{itemize}

\paragraph{Built-in emission bookkeeping diagnostics}
\label{sec:selfvalidation}

After creating a batch of synchrotron packets,
\code{photonEmitSynch} prints two bookkeeping diagnostics.

\paragraph{Packet-weight consistency.}
The code compares
\begin{equation}
	W_{\rm packets}
	=
	\sum_i w_i
\end{equation}
with
\begin{equation}
	W_{\rm nominal}
	=
	N_{\rm tot}w_0^{(\mathrm{adj})}.
\end{equation}
For exactly equal stratum allocation these quantities agree by
construction. With the current integer-remainder allocation, a finite
deterministic discrepancy can remain; it is not purely Monte Carlo
noise. A large discrepancy nevertheless remains useful for detecting
packet-allocation or importance-weighting failures.

\paragraph{Energy-bookkeeping consistency.}
The emitted comoving energy is
\begin{equation}
	E_{\rm emitted}
	=
	\sum_i w_i h\nu_{f,i}.
\end{equation}
The comparison quantity printed as \code{P\_analytic} uses the physical
photon-number rate together with the emission-weighted mean photon energy
estimated from the same emitted packet batch:
\begin{equation}
	P_{\rm analytic}
	=
	\frac{
		\left(\sum_jW_j\right)
		\langle h\nu_f\rangle_{\rm sampled}
	}{
		V_{\rm total}\Delta t_{\rm fps}
	}.
\end{equation}
This is a useful internal bookkeeping check, but it is not an independent
analytic validation of the synchrotron spectral kernel or of the absolute
power normalization, because
\(\langle h\nu_f\rangle_{\rm sampled}\) is derived from the same packet
sample used to compute \(E_{\rm emitted}\).

\subsubsection{Synchrotron Self-Absorption}
\label{sec:ssa}
% ??????????????????????????????????????????????????????????????????????????????

Synchrotron self-absorption (SSA) occurs when synchrotron photons are
reabsorbed by the same electron population that emitted them.  It is
important at low frequencies (below the SSA turnover frequency) where the
plasma is optically thick to its own synchrotron radiation.  In \mcrat{},
SSA is treated via continuous weight attenuation rather than stochastic
absorption (see Section~\ref{sec:background}).

\paragraph{Absorption coefficient}
\label{sec:alpha}

For a nonthermal electron distribution, the SSA absorption coefficient is
obtained from the generalized detailed-balance relation between emission
and absorption in continuum electron states, rather than from the thermal
Kirchhoff relation alone \citep{rybicki1979,kawashima2023}. Physically,
$\alpha_{\nuf}^{(f)}$ is the inverse absorption mean free path at comoving
frequency $\nuf$.

\paragraph{Single power law \citep[\raikou{} Eq.~C2]{kawashima2023}.}
\begin{equation}
	\alpha_{\nuf}^{(f)} =
	\frac{(p-1)(p+2)\,\nenth\,e^2}
	{4\sqrt{3}\,m_e\,c\,(\gmin^{1-p} - \gmax^{1-p})\,\nuc}
	\left(\frac{\nuf}{\nuc}\right)^{-(p+4)/2}
	\bigl[G_a(x_{\min}) - G_a(x_{\max})\bigr],
	\label{eq:alpha_spl}
\end{equation}
where
\begin{equation}
	x_{\min} = \frac{\nuf}{\gmin^2\,\nuc}, \qquad
	x_{\max} = \frac{\nuf}{\gmax^2\,\nuc}.
	\label{eq:x_limits_spl}
\end{equation}
Because $G_a(x)=\int_x^\infty z^{(p-2)/2}F(z)\,dz$ is a monotonically
\emph{decreasing} function of $x$ and $x_{\min} < x_{\max}$, the bracket
in Eq.~\eqref{eq:alpha_spl} is negative which cancels out the negative from $(\gmin^{1-p} - \gmax^{1-p})$, as required for a physical
absorption coefficient. This is the operand order used by
\code{synchAlphaNu}:
\begin{verbatim}
	double delta_Ga = evalGa_p(x_min, tables->Ga_spline, p)
	- evalGa_p(x_max, tables->Ga_spline, p);
\end{verbatim}

The implementation uses the single-power-law expression obtained by
reducing the broken-power-law absorption coefficient
\citep[\raikou{} Eq.~C4]{kawashima2023} to a common index
$p_1=p_2=p$. This form is also straightforward to compare with standard
nonthermal synchrotron-absorption derivations
\citep[e.g.][]{dexter2012}.

The expression adopted in Eq.~\eqref{eq:alpha_spl} has dimensions of
inverse length in Gaussian cgs units. We therefore do not use
\raikou{} Eq.~C2 verbatim when establishing the normalization; instead,
we use the dimensionally explicit limiting form of Eq.~C4. Any apparent
difference with Eq.~C2 may involve a typographical or convention-related
rearrangement of powers of $\nu_c$, so comparisons must use the complete
definitions of $x$, $F(x)$, and $G_a(x;p)$ rather than the displayed
prefactor alone.

\paragraph{Broken power law \citep[\raikou{} Eq.~C4]{kawashima2023}.}
The two power-law segments contribute independently:
\begin{equation}
	\alpha_{\nuf}^{(f)}
	=
	\frac{A_{\rm norm}^{(\mathrm{br})}\,\nenth\,e^2}
	{4\sqrt{3}\,m_e c\,\nuc}
	\Biggl[
	(p_1+2)
	\left(\frac{\nuf}{\nuc}\right)^{-(p_1+4)/2}
	\Delta G_{a,p_1}
	+
	(p_2+2)\gbr^{p_2-p_1}
	\left(\frac{\nuf}{\nuc}\right)^{-(p_2+4)/2}
	\Delta G_{a,p_2}
	\Biggr],
	\label{eq:alpha_bpl}
\end{equation}
where
\begin{align}
	\Delta G_{a,p_1} &= G_a(x_{\rm br};\,p_1) - G_a(x_{\min};\,p_1), \\
	\Delta G_{a,p_2} &= G_a(x_{\max};\,p_2) - G_a(x_{\rm br};\,p_2), \\
	x_{\rm br}       &= \frac{\nuf}{\gbr^2\,\nuc}.
\end{align}
As in the single power-law case, each $\Delta G$ subtracts the value of
$G_a$ at the \emph{larger} $x$ argument from its value at the
\emph{smaller} $x$ argument (recalling $x_{\min} < x_{\rm br} <
x_{\max}$), matching \code{synchAlphaNu}:
\begin{verbatim}
	double delta_Ga_p1 = evalGa_p(x_br,  tables->Ga_spline_p1, p1)
	- evalGa_p(x_max, tables->Ga_spline_p1, p1);
	
	double delta_Ga_p2 = evalGa_p(x_min, tables->Ga_spline_p2, p2)
	- evalGa_p(x_br,  tables->Ga_spline_p2, p2);
\end{verbatim}

\begin{keyresult}
	Both $x_{\min}$ and $x_{\rm br}$ (and, for high-$B$ cells, even
	$x_{\max}$) can fall below \code{SYNCH\_X\_MIN} for realistic
	parameter choices. In these cases \code{synchAlphaNu} does not clamp
	$G_a$ at the tabulated boundary; instead it relies on the analytic
	low-$x$ continuation of $G_a(x;p)$ described in
	Section~\ref{sec:Ga}, Eq.~\eqref{eq:Ga_extension}, evaluated by
	\code{evalGa\_p}. This continuation is what produces the physically
	correct soft SSA turnover in $\alpha_{\nuf}^{(f)}$ at low $\nuf$; a
	naive clamped evaluator (such as \code{evalGa}, which exists in the
	code but is not used by \code{synchAlphaNu}) would instead flatten
	$\alpha_{\nuf}^{(f)}$ artificially once any $x$ argument reaches the
	table boundary. In the regime where both finite-electron integration boundaries satisfy
	$x<x_0$, the corrected continuation gives
	$\alpha_{\nuf}^{(f)}\propto\nuf^{-5/3}$, as derived in
	Eq.~\eqref{eq:alpha_low_frequency}.
\end{keyresult}

\begin{keyresult}
	A natural pitfall is to reverse the operand order in $\Delta G_a$
	(writing $G_a(x_{\max})-G_a(x_{\min})$ instead of
	$G_a(x_{\min})-G_a(x_{\max})$). Because $G_a$ is monotonically
	decreasing in $x$, that ordering would evaluate to a negative
	absorption coefficient. Equations~\eqref{eq:alpha_spl}--\eqref{eq:alpha_bpl}
	give the code-consistent ordering used by \code{synchAlphaNu}.
\end{keyresult}

\begin{keyresult}
	$G_a(x;\,p)$ depends only on the dimensionless argument $x$ and the
	power-law index $p$, not on $B$ or $\nuf$ individually.  A single
	precomputed 1D table therefore serves all cells in the simulation, with
	the physical prefactors (which do depend on $B$, $\nenth$, and $\nuf$)
	evaluated analytically at runtime.  This is what makes the table approach
	computationally efficient.
\end{keyresult}

This is implemented in \code{synchAlphaNu} (\code{mc\_synchrotron.c}).

\paragraph{Relativistic frame correction}
\label{sec:frame}

Photon transport in \mcrat{} is performed in the lab frame, while
$\alpha_{\nuf}^{(f)}$ is defined in the fluid rest frame.  Connecting
the two requires the relativistic radiative transfer equation for a
moving medium.

Following \citet{abramowicz1991}, the optical depth element along a ray
in the lab frame for a fluid element moving with bulk Lorentz factor
$\Gamma$ is:
\begin{equation}
	d\tau_{\nuf}^{(a)}
	= \Gamma\left(1 - \beta\cos\theta\right)
	\alpha_{\nuf}^{(f)}\!\left(\nenth^{(\mathrm{comv})}\right)
	\,dl,
	\label{eq:dtau}
\end{equation}
where $dl$ is the lab-frame path length element, $\beta = v/c$ is the
fluid speed, $\theta$ is the angle between the photon direction and the
fluid velocity in the lab frame, and $\alpha_{\nuf}^{(f)}$ is evaluated
using the \emph{comoving-frame} electron number density
$\nenth^{(\mathrm{comv})}$ as stored in \code{hydro\_data->nonthermal\_dens}.

To understand where the factor $\Gamma(1-\beta\cos\theta)$ comes from
physically: the $(1-\beta\cos\theta)$ term is a Doppler factor that
accounts for the fact that the photon sees a different frequency in the
fluid frame than in the lab frame; the $\Gamma$ factor accounts for the
Lorentz contraction of path lengths between frames.

In \mcrat{}, the full factor $\Gamma(1-\beta\cos\theta)$ is assembled
inside \code{calculateOpticalDepthSSA} in two steps:

\begin{enumerate}[leftmargin=2em]
	\item \textbf{The $(1-\beta\cos\theta)$ factor} is the
	\emph{fluid factor} computed in \code{calculateOpticalDepth} from
	the dot product of the lab-frame fluid velocity and photon direction:
	\begin{equation}
		\mathrm{fluid\_factor}
		= 1 - \beta\,\hat{\mathbf{v}}\cdot\hat{\mathbf{n}}
		= 1 - \beta\cos\theta,
		\label{eq:fluid_factor_code}
	\end{equation}
	which is passed into \code{calculateOpticalDepthSSA} as a parameter.
	
	\item \textbf{The $\Gamma$ factor} is read directly from the local
	fluid Lorentz factor stored in the hydro data frame,
	\code{gamma = (hydro\_data->gamma)[cell\_idx]}, and multiplied onto
	the absorption coefficient explicitly inside
	\code{calculateOpticalDepthSSA}:
	\begin{equation}
		\code{ph->absorption\_opacity}
		= \Gamma
		\times \mathrm{fluid\_factor}
		\times \alpha_{\nuf}^{(f)}\!\left(n_{e,\mathrm{nth}}^{(\mathrm{comv})}\right).
		\label{eq:abs_od_stored}
	\end{equation}
	This choice ? multiplying $\Gamma$ onto the absorption
	\emph{coefficient} rather than onto the comoving electron density ?
	follows the frame-transformation argument of \citet{abramowicz1991}
	and is applied at exactly the same point in the code as the
	scattering-opacity frame correction, keeping all frame-correction
	arithmetic in one place.
\end{enumerate}

\begin{keyresult}
	Edge case: if the local fluid element is static ($\beta=0$), the
	direction $\hat{\mathbf{v}}$ in Eq.~\eqref{eq:fluid_factor_code} is
	undefined (a zero vector has no direction). \code{calculateOpticalDepth}
	handles this explicitly: rather than computing the dot product
	$\hat{\mathbf{v}}\cdot\hat{\mathbf{n}}$ from an undefined unit vector,
	the code sets \code{fluid\_factor}$\,=1$ directly whenever $\beta=0$,
	which is the correct limit of Eq.~\eqref{eq:fluid_factor_code} as
	$\beta\to0$ regardless of $\hat{\mathbf{n}}$. Both the scattering
	opacity and the SSA absorption coefficient therefore reduce smoothly
	to their fluid-rest-frame values in a static medium.
\end{keyresult}

The value stored in \code{ph->absorption\_opacity} is therefore the
\emph{complete} \citet{abramowicz1991}-corrected absorption coefficient.
For cross-referencing convenience elsewhere in this document we denote
this stored quantity explicitly as:
\begin{equation}
	\code{ph->absorption\_opacity}
	= \underbrace{\Gamma}_{\text{step 2}}
	\times
	\underbrace{\mathrm{fluid\_factor}}_{\text{step 1, Eq.~\eqref{eq:fluid_factor_code}}}
	\times \alpha_{\nuf}^{(f)}\!\left(n_{e,\mathrm{nth}}^{(\mathrm{comv})}\right),
	\label{eq:abs_od_full}
\end{equation}
which is algebraically identical to Eq.~\eqref{eq:abs_od_stored} above.

\begin{keyresult}
	The lab-frame conversion of the non-thermal electron density,
	\begin{equation}
		n_{e,\mathrm{nth}}^{(\mathrm{lab})}
		= \Gamma\, n_{e,\mathrm{nth}}^{(\mathrm{comv})},
		\label{eq:nth_lab}
	\end{equation}
	is used by \code{calculateOpticalDepth} to form the \emph{scattering}
	optical depth for non-thermal electrons
	(\code{nonthermal\_n\_dens\_lab = nonthermal\_dens[i] * gamma[i]}
	in \code{optical\_depth.c}, cf.\ Eq.~\eqref{eq:kappa_nth_k}). This is a
	\emph{different} mechanism from SSA: for SSA, $\Gamma$ is \emph{not}
	used to boost the electron density into the lab frame before calling
	\code{synchAlphaNu}. Instead, \code{synchAlphaNu} is evaluated at the
	raw \emph{comoving}-frame density
	$n_{e,\mathrm{nth}}^{(\mathrm{comv})}$, and $\Gamma$ is multiplied
	directly onto the resulting absorption \emph{coefficient} inside
	\code{calculateOpticalDepthSSA}, as shown in
	Eq.~\eqref{eq:abs_od_full}. The two mechanisms are algebraically
	distinct even though both ultimately introduce a single factor of
	$\Gamma$: one rescales a number density, the other rescales an
	opacity. Table~\ref{tab:callchain_abs} and the summary in
	Section~\ref{sec:callchain} describe the SSA-specific mechanism only;
	Eq.~\eqref{eq:nth_lab} above documents the separate, scattering-specific
	mechanism for completeness.
\end{keyresult}


\paragraph{Implementation in \texttt{calculateOpticalDepth}}
\label{sec:calc_od}

Whenever a photon enters a new cell or scatters
(\code{recalc\_properties}$=1$), \code{calculateOpticalDepth}
(\code{optical\_depth.c}) recomputes all photon-transport coefficients.
The fluid factor \eqref{eq:fluid_factor_code} is computed once and
applied to both the scattering opacity and the SSA absorption coefficient
within the same function call:
\begin{equation}
	\mathrm{fluid\_factor}
	= 1 - \beta \,
	\frac{\mathbf{v}_{\rm fluid} \cdot \mathbf{p}_{\rm ph}}
	{|\mathbf{v}_{\rm fluid}||\mathbf{p}_{\rm ph}|}.
	\label{eq:fluid_factor_calc}
\end{equation}
\begin{implementationnote}
	The code variable \code{fluid\_factor} contains only
	\begin{equation}
		\code{fluid\_factor}
		=
		1-\beta\cos\theta.
	\end{equation}
	It does not include the bulk Lorentz factor \(\Gamma\).
	
	For scattering, \(\Gamma\) enters through the lab-frame electron density,
	for example
	\begin{equation}
		n_{e,\mathrm{nth}}^{(\mathrm{lab})}
		=
		\Gamma n_{e,\mathrm{nth}}^{(\mathrm{comv})}.
	\end{equation}
	For synchrotron self-absorption, the coefficient is first evaluated at
	the comoving density and \(\Gamma\) is then multiplied directly onto the
	coefficient:
	\begin{equation}
		\code{ph->absorption\_opacity}
		=
		\Gamma\,\code{fluid\_factor}\,
		\alpha_{\nu_f}^{(f)}.
	\end{equation}
\end{implementationnote}

The SSA coefficient is then computed via:
\begin{equation}
	\code{calculateOpticalDepthSSA(ph,\;hydro\_data,\;fluid\_factor,\;fPtr);}
\end{equation}
The result is stored in \code{ph->absorption\_opacity}
\eqref{eq:abs_od_full} and held there until the photon moves to a new
cell or scatters.  

\begin{keyresult}
	A stale comment in
	\code{optical\_depth.c} itself, stated that
	\code{calculateOpticalDepthSSA} only acts on packets of type
	\code{SYNCH\_PHOTON}, with \code{ph->absorption\_opacity} set to zero
	for all other types. In the current implementation this type check is
	explicitly disabled:
	\begin{verbatim}
		void calculateOpticalDepthSSA(...)
		{
			ph->absorption_opacity = 0.0;
			
			//this can operate on all photon types
			//if (ph->type != SYNCH_PHOTON)
			//    return;
			...
		}
	\end{verbatim}
	SSA absorption is therefore now computed and applied to \emph{every}
	photon type (\code{INJECTED\_PHOTON}, \code{COMPTONIZED\_PHOTON}, etc.)
	that passes through a cell with $B>0$ and non-thermal electrons present,
	not only synchrotron-seeded packets. This has a direct consequence for
	Russian roulette (Section~\ref{sec:roulette}): because
	\code{INJECTED\_PHOTON} and \code{COMPTONIZED\_PHOTON} packets can now
	also accumulate continuous SSA weight loss, they are separately
	rouletted in addition to \code{SYNCH\_PHOTON} (see
	Section~\ref{sec:rr_impl}).
\end{keyresult}

\paragraph{Continuous weight attenuation (\texttt{applyabsorption})}
\label{sec:applyabs}

During photon transport, \code{applyAbsorption} is called at each
sub-step of length $dl$ within \code{updatePhotonPosition}.  Because the
complete frame correction $\Gamma(1-\beta\cos\theta)$ is already folded
into \code{ph->absorption\_opacity} \eqref{eq:abs_od_full}, the weight
update requires no additional frame arithmetic:
\begin{equation}
	w_{\rm new} = w_{\rm old}
	\times \exp\!\left(
	-\,\code{ph->absorption\_opacity} \times dl
	\right).
	\label{eq:weight_update_simple}
\end{equation}
Expanding \code{ph->absorption\_opacity} using \eqref{eq:abs_od_full}
recovers the full \citet{abramowicz1991} expression:
\begin{equation}
	w_{\rm new} = w_{\rm old}
	\times \exp\!\Bigl(
	-\,\Gamma\left(1 - \beta\cos\theta\right)
	\,\alpha_{\nuf}^{(f)}\!\left(n_{e,\mathrm{nth}}^{(\mathrm{comv})}\right)
	\,dl
	\Bigr).
	\label{eq:weight_update}
\end{equation}
Two numerical guards are applied before the weight update, exactly as
implemented in \code{applyAbsorption}:
\begin{verbatim}
	double tau = ph->absorption_opacity * dl;
	
	if (tau > 200.0 || ph->weight < FLT_MIN)
	{
		ph->weight = DBL_MIN;
		ph->nearest_block_index = -1;
		ph->time_to_scatter     = FLT_MAX / C_LIGHT;
		ph->recalc_properties   = 1;
		return;
	}
	ph->weight *= exp(-tau);
\end{verbatim}
\begin{itemize}
	\item If $dl \le 0$ or \code{ph->absorption\_opacity}$\,\le 0$,
	the function returns immediately (no-op); this guard is checked
	earlier in the function and is unchanged from the previous
	description.
	\item If $\tau \equiv \code{ph->absorption\_opacity}\times dl > 200$
	\emph{or} the packet's weight has already fallen below
	\code{FLT\_MIN}, the packet is not multiplied by
	$\exp(-\tau)$ (which would risk floating-point underflow for large
	$\tau$). Instead its weight is set to the sentinel value
	\code{DBL\_MIN} ? a small but strictly positive value, chosen so the
	packet can still be distinguished from a true \code{NULL\_PHOTON}
	and, if desired, still be written to output ? rather than being set
	to exactly zero.
	\item In the same branch, the packet is also marked as having left
	the active transport domain: \code{nearest\_block\_index} is set to
	$-1$, \code{time\_to\_scatter} is set to the sentinel
	$\mathrm{FLT\_MAX}/c$, and \code{recalc\_properties} is set to 1.
	This mirrors the sentinel scheme used elsewhere in \mcrat{} for
	photons that leave the hydro grid (Section~\ref{sec:calc_od}),
	ensuring the packet is skipped by \code{photonEvent} and
	\code{calcMeanFreePath} for the remainder of the current frame.
\end{itemize}

\begin{keyresult}
	The implemented deep-absorption guard triggers at $\tau > 200$ (not at
	the na\"ively large value one might expect from pure underflow
	avoidance), sets the weight to the sentinel \code{DBL\_MIN} rather than
	to exactly zero, additionally triggers on an independent
	$\code{weight}<\code{FLT\_MIN}$ condition, and invalidates the packet for
	further transport within the current frame (\code{nearest\_block\_index}
	$=-1$, \code{time\_to\_scatter} $=\mathrm{FLT\_MAX}/c$,
	\code{recalc\_properties} $=1$), exactly as detailed above and in
	\code{applyAbsorption} (\code{mc\_synchrotron.c}).
\end{keyresult}

\begin{knownissue}
	Packets that trigger the deep-absorption guard are assigned the exact
	sentinel weight \code{DBL\_MIN}. The Russian-roulette weight-collection
	pass includes only packets satisfying
	\begin{verbatim}
		ph->weight > DBL_MIN
	\end{verbatim}
	and therefore excludes packets whose weight is exactly
	\code{DBL\_MIN} when calculating the population median.
	
	If at least one ordinary packet of the same photon type is present, the
	later roulette pass still sees the \code{DBL\_MIN} packet and will almost
	certainly kill it. If all remaining packets of that type have weight
	exactly \code{DBL\_MIN}, however, the collection pass finds no eligible
	weights and returns without removing them. Consequently,
	\code{DBL\_MIN} packets are not unconditionally converted into
	\code{NULL\_PHOTON} packets by the current implementation.
\end{knownissue}

SSA absorption is applied \emph{only} during transport ? never at the
birth of a photon packet ? preserving the physical interpretation of the
packet weight as the number of real photons at the moment of emission.

\subsubsection{Hot Scattering Cross Sections}
\label{sec:hot_xsection}
% ??????????????????????????????????????????????????????????????????????????????

\paragraph{Why the Thomson cross section is not enough}

In the simplest treatment of Compton scattering, every electron presents
the same target area to every photon regardless of their energies: the
Thomson cross section $\sigma_T = 6.65 \times 10^{-25}$\,cm$^2$.  This
is valid only when both the photon energy $h\nu$ and the electron kinetic
energy $(\gamma - 1) m_e c^2$ are much smaller than the electron rest-mass
energy $m_e c^2 = 511$\,keV.  In the hot, relativistic plasmas modelled by
\mcrat{} neither condition is generally satisfied:

\begin{itemize}
	\item \textbf{Hot thermal electrons} in a fluid with dimensionless
	temperature $\Theta = k_B T / (m_e c^2) \gtrsim 0.01$ have significant
	relativistic bulk motion.  At sufficiently low photon energy in every relevant electron rest frame,
	the effective cross section approaches $\sigma_T$. Relativistic electron
	motion can Doppler-boost the photon into the Klein--Nishina regime in the
	electron rest frame, reducing the distribution-averaged cross section
	below the Thomson value.
	
	\item \textbf{Energetic photons} with $h\nu \gtrsim m_e c^2$ experience
	Klein--Nishina suppression of the cross section even for cold electrons.
	
	\item \textbf{Non-thermal power-law electrons} with $\gamma \gg 1$
	interact with photons through the Klein--Nishina cross section in the
	electron rest frame, which differs substantially from $\sigma_T$ for
	most photon--electron energy combinations of interest.
\end{itemize}

\begin{keyresult}
	Using $\sigma_T$ in a hot or relativistic plasma over- or under-estimates
	the scattering rate, biasing both the energy exchange and the escape of
	radiation.  \mcrat{} uses a tabulated \emph{hot cross section} that
	correctly accounts for the full Klein--Nishina energy dependence and the
	relativistic electron distribution.
\end{keyresult}

\paragraph{Definition of the hot cross section}

The effective scattering cross section for a photon with comoving-frame
energy $\epsilon = h\nu_f / (m_e c^2)$ propagating through a plasma with
electron distribution $f(\gamma, \mu)$ is obtained by averaging the
Klein--Nishina cross section over the electron distribution and over the
angle $\mu = \cos\theta_{e\gamma}$ between the photon and electron momenta
\citep{dolence2009,kawashima2023,canfield1987}:
\begin{equation}
	\sigma(\epsilon,\,T) =
	\frac{1}{2}
	\int_1^{\gamma_{\max}} \int_{-1}^{1}
	f_{\rm MJ}(\gamma,\,\Theta)\,
	\sigma_{\rm KN}(\epsilon')\,
	(1 - \mu\beta)\,
	d\mu\, d\gamma,
	\label{eq:hot_xsection}
\end{equation}
where:
\begin{itemize}
	\item $f_{\rm MJ}(\gamma,\,\Theta)$ is the Maxwell--J\"{u}ttner
	distribution of thermal electrons at dimensionless temperature
	$\Theta = k_B T / (m_e c^2)$,
	\item $\beta = \sqrt{1 - 1/\gamma^2}$ is the electron speed,
	\item $\epsilon' = \epsilon\,\gamma(1 - \mu\beta)$ is the photon energy
	in the electron rest frame,
	\item The total Klein--Nishina cross section used by the code is written in
	normalized form as
	\begin{equation}
		\frac{\sigma_{\rm KN}(\epsilon')}{\sigma_T}
		=
		\frac{3}{4}
		\left[
		\frac{2}{\epsilon'^2}
		+
		\left(
		\frac{1}{2\epsilon'}
		-
		\frac{1+\epsilon'}{\epsilon'^3}
		\right)
		\ln(1+2\epsilon')
		+
		\frac{1+\epsilon'}{(1+2\epsilon')^2}
		\right],
		\label{eq:kn}
	\end{equation}
	where $\epsilon'$ is the photon energy in the electron rest frame in
	units of $m_ec^2$ \citep{dolence2009}.
	
	Direct evaluation of Eq.~\eqref{eq:kn} suffers from cancellation at very
	small $\epsilon'$. The implementation therefore uses the low-energy
	approximation
	\begin{equation}
		\frac{\sigma_{\rm KN}}{\sigma_T}
		\simeq
		1-2\epsilon'
	\end{equation}
	when
	\begin{equation}
		\epsilon'
		<
		\code{THOMSON\_LIMIT\_ENERGY\_RATIO}
		=
		10^{-3}.
	\end{equation}
	The same transition energy is used by the total-cross-section evaluator
	and the differential scattering sampler. And
	\item the factor $(1-\mu\beta)$ is the relative velocity of the photon
	and electron in the fluid frame.
\end{itemize}
The result \eqref{eq:hot_xsection} is normalised by $\sigma_T$ so that the
code stores $\sigma/\sigma_T$: a dimensionless correction factor that is
multiplied by $\sigma_T$ when computing optical depths.

For nonthermal electrons, \mcrat{} partitions the full electron Lorentz-factor
range into \code{N\_GAMMA} subgroups. The table entry for subgroup \(k\)
is
\begin{equation}
	\frac{\sigma_k(\epsilon)}{\sigma_T}
	=
	\frac{1}{2}
	\int_{\gamma_k^{\min}}^{\gamma_k^{\max}}
	d\gamma
	\int_{-1}^{1}
	d\mu\,
	f_{\rm nth}(\gamma)
	\frac{\sigma_{\rm KN}(\epsilon')}{\sigma_T}
	\left(1-\mu\beta_e\right),
	\label{eq:hot_xsection_nth}
\end{equation}
where \(f_{\rm nth}(\gamma)\) is normalized over the full interval
\([\gmin,\gmax]\). It is not renormalized independently within each
subgroup.

Consequently, \(\sigma_k/\sigma_T\) already includes the fractional
abundance of electrons that lies in subgroup \(k\). At runtime it is
multiplied by the total nonthermal electron density. The sum of the
subgroup contributions therefore reconstructs the full nonthermal
scattering opacity.

\paragraph{Table construction and interpolation}
\label{sec:table_construction}

The double integrals \eqref{eq:hot_xsection} and \eqref{eq:hot_xsection_nth}
are expensive to evaluate at runtime, so \mcrat{} precomputes them once on a
grid and uses bilinear interpolation during the simulation.

\paragraph{Thermal table.}
The thermal cross section is tabulated on a 2D grid of
(\code{N\_PH\_E}$+1$) $\times$ (\code{N\_T}$+1$) points:
\begin{itemize}
	\item Photon energy axis: $\log_{10}(\epsilon)$ uniformly spaced
	over $[\code{LOG\_PH\_E\_MIN},\,\code{LOG\_PH\_E\_MAX}]$.
	\item Temperature axis: $\log_{10}(\Theta)$ uniformly spaced
	over $[\code{LOG\_T\_MIN},\,\code{LOG\_T\_MAX}]$.
\end{itemize}
Each table entry is $\log_{10}(\sigma/\sigma_T)$.  The double integral is
evaluated using the GSL plain Monte Carlo integrator with $5\times10^5$
calls per point.  The resulting table is stored to a file
(\code{HOT\_THERMAL\_X\_SECTION\_FILE}) so it can be reused across
simulation runs without recomputation.

\paragraph{Non-thermal table.}
When \code{NONTHERMAL\_E\_DIST} $\ne$ \code{OFF}, a second table of
dimension (\code{N\_PH\_E}$+1$) $\times$ \code{N\_GAMMA} is built, where
\code{N\_GAMMA} is the number of Lorentz-factor subgroups.  Each entry
$[i][k]$ is $\log_{10}(\sigma_k/\sigma_T)$ for photon energy grid point
$i$ and subgroup $k$, evaluated with $10^6$ Monte Carlo calls.  The gamma
axis of the table is placed at the log-space midpoint of each subgroup's
Lorentz-factor range.  A sufficiently large value of \code{N\_GAMMA} is
required to ensure that the interpolation across subgroup boundaries is
accurate; with too few subgroups the cross section is poorly sampled near
the boundary between adjacent subgroups, producing artefacts in the
scattered spectrum at the corresponding photon frequencies.

\paragraph{MPI distribution.}
Table construction is performed by MPI rank 0 only.  The tables are then
broadcast to all other ranks via \code{broadcastInterpolationData} before
the simulation begins.  This avoids redundant computation and ensures all
ranks use identical tables.

\paragraph{Runtime interpolation.}
During the simulation, \code{interpolateThermalHotCrossSection} and
\code{interpolateSubgroupNonThermalHotCrossSection} use the prebuilt GSL
\code{gsl\_spline2d} bilinear interpolation objects to evaluate
$\sigma/\sigma_T$ at the photon's comoving energy and the cell temperature
in $O(1)$ time.  Thread safety is ensured by the same per-thread
\code{ThreadLocalAccel} pattern used for the synchrotron tables
(Section~\ref{sec:thread}).

\subsubsection{Scattering Bias and Importance Sampling}
\label{sec:bias}
% ??????????????????????????????????????????????????????????????????????????????

\paragraph{The problem: rare scatterings in low-optical-depth regions}

In optically thin regions, a photon packet may travel many mean free paths
before scattering.  If the simulation is run for a fixed time interval
$\Delta t_{\rm fps} = 1/\text{fps}$, most packets in such regions will
never scatter, contributing nothing to the scattering statistics.  Meanwhile,
optically thick regions produce enormous numbers of scatterings that are
individually unimportant statistically.  This imbalance makes the unbiased
estimator \eqref{eq:estimator_extensive} very high-variance.

The solution is \emph{importance sampling} of the scattering interaction:
force photon packets to scatter more often than they naturally would, then
correct for this artificial enhancement by adjusting the weight.  This is
the scattering bias scheme used in \mcrat{}, following
\citet{kawashima2023,dolence2009}.

\paragraph{Opacity versus optical depth}
\label{sec:opacity_notation}

The photon fields
\code{scattering\_opacity[k]},
\code{total\_scattering\_opacity}, and
\code{absorption\_opacity} store coefficients with dimensions of
inverse length. They are opacities, not dimensionless optical depths.

We denote the unbiased scattering opacity of electron population \(k\)
by
\begin{equation}
	\kappa_k
	=
	n_{e,k}\sigma_k
	\left(1-\beta\cos\theta\right)
	\qquad
	[\mathrm{cm^{-1}}],
	\label{eq:chi_k}
\end{equation}
with any required bulk Lorentz factor already included through the
lab-frame density. The optical depth accumulated over a path \(dl\) is
\begin{equation}
	d\tau_k
	=
	\kappa_k\,dl.
	\label{eq:dtau_k}
\end{equation}

The total biased scattering opacity is
\begin{equation}
	\kappa_{\rm tot}^{(b)}
	=
	\sum_k b_k\kappa_k,
	\label{eq:chi_total_biased}
\end{equation}
and the sampled propagation distance is
\begin{equation}
	\lambda
	=
	\frac{-\ln u}{\kappa_{\rm tot}^{(b)}},
	\qquad
	u\sim\mathcal{U}(0,1).
	\label{eq:mfp_total}
\end{equation}

\paragraph{Scattering bias for thermal electrons}
\label{sec:thermal_bias}

The thermal scattering opacity is
\begin{equation}
	\kappa_{\rm th}
	=
	n_{e,\mathrm{th}}^{(\mathrm{lab})}
	\sigma_{\rm th}(\epsilon,T)
	\left(1-\beta\cos\theta\right)
	\qquad
	[\mathrm{cm^{-1}}],
	\label{eq:chi_thermal}
\end{equation}
where the bulk Lorentz factor is already included in the lab-frame
electron density. The optical depth accumulated across a path $dl$ is
\begin{equation}
	d\tau_{\rm th}
	=
	\kappa_{\rm th}\,dl.
\end{equation}

Without biasing, the mean free path (MFP) to the next scattering is:
\begin{equation}
	\lambda = \frac{-\ln u}{\tau_0/l}, \qquad u \sim \mathcal{U}(0,1),
	\label{eq:mfp_unbiased}
\end{equation}
which in a thin cell may greatly exceed $c\,\Delta t_{\rm fps}$, meaning
the packet never scatters.

The thermal scattering bias parameter $b_{\rm th}$ is defined so that
the effective MFP used for sampling is reduced by a factor $b_{\rm th}$:
\begin{equation}
	\lambda_{\rm biased} = \frac{\lambda}{b_{\rm th}},
	\label{eq:mfp_biased}
\end{equation}
forcing scatterings to occur $b_{\rm th}$ times more frequently.
The bias parameter is computed by \code{calculateThermalScatteringBias}
\citep[\raikou{} Eq.~37]{kawashima2023}:
\begin{equation}
	b_{\rm th} = \max\!\left(1,\;
	\frac{\alpha\,\Theta_{\rm cell}^2}
	{\bar{\Theta}^2\,\tau_{\max}}
	\right),
	\label{eq:thermal_bias}
\end{equation}
where:
\begin{itemize}
	\item $\alpha$ = \code{SCATTERING\_BIAS\_SCALING} is a dimensionless
	tuning parameter set by the user,
	\item $\Theta_{\rm cell} = k_B T_{\rm cell}/(m_e c^2)$ is the
	dimensionless temperature of the current cell,
	\item $\bar{\Theta}$ is the simulation-averaged dimensionless
	temperature \code{average\_dimless\_theta},
	\item $\tau_{\max} = \tau_0 \times c\,\Delta t_{\rm fps}$ is the
	maximum optical depth the photon could accumulate before the next
	hydro frame is loaded.
\end{itemize}
The $\max(1,\ldots)$ ensures that $b_{\rm th} \ge 1$: the bias can only
increase the scattering rate, never decrease it below the physical rate.
Hot cells (large $\Theta_{\rm cell}$) and optically thin regions (small
$\tau_{\max}$) receive the largest bias.

\begin{keyresult}
	The bias \eqref{eq:thermal_bias} is proportional to $\Theta_{\rm cell}^2 /
	(\bar{\Theta}^2\,\tau_{\max})$.  Hot, optically thin cells are biased
	strongly (many forced scatterings); cool, optically thick cells approach
	the natural rate ($b_{\rm th} \to 1$).
\end{keyresult}

\paragraph{Scattering bias for non-thermal electron subgroups}
\label{sec:nonthermal_bias}

When non-thermal electrons are present (\code{NONTHERMAL\_E\_DIST}
$\ne$ \code{OFF}), the non-thermal electron population is divided into
\code{N\_GAMMA} Lorentz-factor subgroups $k = 1,\ldots,\code{N\_GAMMA}$.
For nonthermal subgroup $k$, the corresponding opacity is
\begin{equation}
	\kappa_k
	=
	n_{e,\mathrm{nth}}^{(\mathrm{lab})}
	\sigma_k(\epsilon)
	\left(1-\beta\cos\theta\right).
	\label{eq:kappa_nth_k}
\end{equation}
where $\sigma_k(\epsilon)$ is the non-thermal cross section for subgroup
$k$ from the precomputed table \eqref{eq:hot_xsection_nth}.

The goal of the per-subgroup bias scheme is to ensure that every
subgroup ? including rare, high-energy subgroups with very small $\tau_k$
? is sampled with comparable frequency in the simulation, while the
scattered photon weights are corrected to preserve the physical scattering
rates.  This is achieved by assigning each subgroup a bias $b_k$ such that
all subgroups contribute equally to the total biased optical depth.

Following \citet[\raikou{} Eq.~48]{kawashima2023}, the bias assigned to
nonthermal subgroup $k$ is
\begin{equation}
	b_k
	=
	b_{\rm ref}
	\frac{\kappa_{\rm ref}}{\kappa_k},
	\label{eq:nonthermal_bias}
\end{equation}
where $\kappa_k$ is the subgroup scattering opacity and the reference
population depends on whether thermal electrons are present.


\begin{knownissue}
	The current packet-splitting implementation requires
	\begin{equation}
		0
		\le
		w_{\rm scatt}
		\le
		w
	\end{equation}
	so that
	\begin{equation}
		w_{\rm unscatt}
		=
		w-w_{\rm scatt}
	\end{equation}
	remains nonnegative. With
	\begin{equation}
		w_{\rm scatt}
		=
		w
		\frac{1-\exp(-\kappa_k dl)}
		{1-\exp(-b_k\kappa_k dl)},
	\end{equation}
	a value $b_k<1$ can produce $w_{\rm scatt}>w$. The current
	\code{photonEvent} implementation detects a negative unscattered weight
	and terminates the simulation.
	
	Thus the raw RAIKOU subgroup-bias ratio is the intended bias definition,
	but its compatibility with \mcrat{}'s current event-driven packet-splitting
	implementation requires either $b_k\ge1$ in all encountered states or a
	revised weight-correction algorithm that remains valid for $b_k<1$.
	Users should monitor the minimum subgroup bias during validation runs.
\end{knownissue}


\paragraph{Mixed thermal and non-thermal case.}
When both thermal and non-thermal electrons are present, the reference
quantities are those of the thermal population:
\begin{equation}
	b_{\rm ref} = b_{\rm th}, \qquad \tau_{\rm ref} = \tau_0.
	\label{eq:ref_thermal}
\end{equation}
This is exactly the \raikou{} prescription \citep[\raikou{}
Eq.~48]{kawashima2023}: each non-thermal subgroup is biased so that its
contribution $b_k \tau_k$ to the total biased optical depth equals the
thermal contribution $b_{\rm th}\tau_0$.  The result is that the thermal
population and every non-thermal subgroup are each selected with equal
probability $1/(1 + \code{N\_GAMMA})$ during a scattering event.

\paragraph{Purely non-thermal case.}
When no thermal electrons are present, there is no natural reference
population.  In this case the reference optical depth is set to the
\emph{equal share} of the total non-thermal optical depth:
\begin{equation}
	\tau_{\rm ref} = \frac{\tau_{\rm nth,total}}{\code{N\_GAMMA}},
	\qquad
	\tau_{\rm nth,total} = \sum_{k=1}^{\code{N\_GAMMA}} \tau_k,
	\label{eq:ref_nonthermal}
\end{equation}
and the reference bias is computed from $\tau_{\rm nth,total}$:
\begin{equation}
	b_{\rm ref} = \max\!\left(1,\;
	\frac{\alpha}{\tau_{\rm nth,total} \times c\,\Delta t_{\rm fps}}
	\right).
	\label{eq:bref_nonthermal}
\end{equation}
Substituting \eqref{eq:ref_nonthermal} into \eqref{eq:nonthermal_bias}
gives:
\begin{equation}
	b_k = \max\!\left(1,\; b_{\rm ref}\,
	\frac{\tau_{\rm nth,total}}{\code{N\_GAMMA}\,\tau_k} \right),
	\label{eq:nonthermal_bias_pure}
\end{equation}
so that $b_k \tau_k = b_{\rm ref}\,\tau_{\rm nth,total}/\code{N\_GAMMA}$
for every subgroup (where the floor is not active), and every subgroup
is again selected with equal probability $1/\code{N\_GAMMA}$.

When the raw equalising bias ratios are used and all denominators are
nonzero, the total biased scattering opacity is
\begin{equation}
	\kappa_{\rm tot}^{(b)}
	=
	\begin{cases}
		\left(1+\code{N\_GAMMA}\right)
		b_{\rm th}\kappa_{\rm th},
		& \text{thermal and nonthermal electrons},\\[6pt]
		b_{\rm ref}\kappa_{\rm nth,total},
		& \text{purely nonthermal electrons},
	\end{cases}
	\label{eq:tau_total_correct}
\end{equation}
where
\begin{equation}
	\kappa_{\rm nth,total}
	=
	\sum_{k=1}^{\code{N\_GAMMA}}\kappa_k.
\end{equation}
The factor \(1+\code{N\_GAMMA}\) applies only in the mixed case,
where the thermal population and all nonthermal subgroups are active.
In the purely nonthermal case, the thermal slot is zero and only
\code{N\_GAMMA} populations contribute.

\begin{keyresult}
	The per-subgroup bias \eqref{eq:nonthermal_bias} equalises the selection
	probability across all electron populations, boosting the sampling of
	rare high-energy subgroups. The weight correction at each scattering event (Section~\ref{sec:weight_bias_modification})
	then ensures that the statistically enhanced scatterings carry correctly
	reduced weights, so that the simulation remains unbiased.
\end{keyresult}

\paragraph{Photon weight modification due to biased scattering}
\label{sec:weight_bias_modification}

Because biased sampling forces scatterings to occur more frequently than
they physically should, the photon packet weight must be adjusted at each
forced scattering event to preserve the unbiasedness of the estimator
\eqref{eq:estimator_extensive}.  The key insight is that a single packet travelling
through the biased medium must be split into two components at the moment
of scattering:

\begin{enumerate}[leftmargin=2em]
	\item A \textbf{scattered component} that has physically interacted
	with an electron and carries the weight corresponding to the true
	probability of scattering over the path traversed.
	
	\item An \textbf{unscattered component} that has not physically
	interacted and continues propagating with the remaining weight,
	representing the fraction of real photons that would have passed
	through unaffected.
\end{enumerate}

The true probability of scattering off subgroup $j$ over a path of
optical depth $\tau_j \cdot dl$ is:
\begin{equation}
	P_{\rm scatt,j} = 1 - e^{-\tau_j \cdot dl},
	\label{eq:p_scatt}
\end{equation}
while the forced (biased) scattering probability for subgroup $j$ over
the same path is:
\begin{equation}
	P_{\rm biased,j} = 1 - e^{-b_j\,\tau_j \cdot dl}.
	\label{eq:p_biased}
\end{equation}
The scattered packet should carry the fraction of the total weight that
corresponds to the \emph{true} scattering probability of subgroup $j$,
corrected for the \emph{biased} sampling rate of that same subgroup.
This is implemented in \code{scatteredPhotonWeight}
(\code{mcrat\_scattering.c}):
\begin{equation}
	w_{\rm scatt} = w \times
	\frac{1 - e^{-\tau_j \cdot dl}}
	{1 - e^{-b_j\,\tau_j \cdot dl}},
	\label{eq:w_scattered}
\end{equation}
where $\tau_j \cdot dl = \tau_j \times c\,\Delta t_{\rm scatt}$ is the
true optical depth of the scattering subgroup $j$ over the time step, and
$b_j\,\tau_j \cdot dl$ is the biased optical depth of that same subgroup.

\begin{keyresult}
	The denominator of \eqref{eq:w_scattered} uses the biased optical depth
	of the \emph{specific subgroup that scattered}, $b_j\,\tau_j \cdot dl$,
	not the total biased optical depth $\tau_{\rm total} \cdot dl$.  This is
	the critical distinction from a naive implementation: using
	$\tau_{\rm total}$ in the denominator would incorrectly mix the
	contributions of different subgroups and produce systematically wrong
	weights.  Each subgroup's scattering rate was artificially enhanced by
	its own factor $b_j$, so each must be corrected by its own $b_j$
	independently.
\end{keyresult}

In the optically thin limit ($\tau_j \cdot dl \ll 1$), the exponentials
in \eqref{eq:w_scattered} expand as $1 - e^{-x} \approx x$, and the
expression simplifies to:
\begin{equation}
	w_{\rm scatt} \approx \frac{w}{b_j},
	\label{eq:w_scattered_thin}
\end{equation}
which is the form used in the \citet{dolence2009} grmonty code.  The
full expression \eqref{eq:w_scattered} is used in \mcrat{} since it
remains valid in both optically thin and thick regimes.

The unscattered component retains the remaining weight:
\begin{equation}
	w_{\rm unscatt} = w - w_{\rm scatt}.
	\label{eq:w_unscattered}
\end{equation}

In practice, the original photon struct is first updated to carry
$w_{\rm unscatt}$ and a copy is made with $w_{\rm scatt}$.  The copy
is then added to the photon list as a new packet and its 4-momentum is
updated by the Compton scattering kinematics.  The original packet
continues propagating unscattered with the reduced weight, representing
the fraction of real photons that did not interact.

\begin{keyresult}
	The split conserves the parent packet weight algebraically:
	\begin{equation}
		w_{\rm scatt}+w_{\rm unscatt}=w.
	\end{equation}
	When $b_j\ge1$, the scattered weight also satisfies
	$0\le w_{\rm scatt}\le w$, so both child weights are nonnegative.
	
	The intended statistical correction follows the RAIKOU importance-sampling
	prescription. Exact unbiasedness of the complete implementation additionally
	requires consistency among the sampled total biased opacity, subgroup
	selection probability, and subgroup-specific weight correction. This should
	be verified with convergence tests, particularly for mixed populations and
	for any state in which $b_j$ approaches or falls below unity.
\end{keyresult}

Note that when the scattering bias equals 1 for a given subgroup (i.e.\
the MFP has not been artificially reduced for that subgroup, as occurs in
optically thick regions where the $\max(1,\ldots)$ floor is active), the
packet is scattered without splitting: the weight is unchanged and the
unscattered component has zero weight.  This is checked explicitly in
the code to avoid unnecessary packet proliferation.

\paragraph{Electron subgroup selection}
\label{sec:subgroup_select}

When a scattering event occurs, \code{generateSingleElectron}
(\code{electron.c}) must determine which electron population ? thermal or
one of the \code{N\_GAMMA} non-thermal subgroups ? interacts with the
photon.  The selection probability for each population $j$ is proportional
to its contribution to the total biased optical depth:
\begin{equation}
	P(j) = \frac{b_j\,\tau_j}{\tau_{\rm total}},
	\label{eq:subgroup_prob}
\end{equation}
where $\tau_{\rm total} = \sum_j b_j\,\tau_j$ \eqref{eq:tau_total_correct}.
By construction of the per-subgroup biases, $b_j\,\tau_j$ is the same
constant for every population (where the $\max(1,\ldots)$ floor is not
active), so \eqref{eq:subgroup_prob} gives equal selection probability
across all populations.

The selection is implemented via a forward CDF scan: a uniform random
variate $u \sim \mathcal{U}(0,1)$ is drawn and the cumulative sum
$\sum_{j'=0}^{j} b_{j'}\tau_{j'} / \tau_{\rm total}$ is accumulated
until it exceeds $u$.  The subgroup $j$ at which the threshold is crossed
is the selected population.  
The numerator of the selection sum, $\sum_{j'=0}^{j} b_{j'}\tau_{j'}$,
is accumulated locally inside \code{generateSingleElectron} from the
per-subgroup opacities and biases stored on the photon struct. The
denominator, however, is \emph{not} recomputed locally: it is read
directly from the field \code{ph->total\_scattering\_opacity},
\begin{verbatim}
	double total_tau = (ph->total_scattering_opacity);
	double cumulative = 0.0;
	for (int i = 0; i < N_GAMMA + 1; i++)
	{
		cumulative += (ph->scattering_bias)[i] * (ph->scattering_opacity)[i];
		if ((result == -1) && (random_num <= cumulative / total_tau))
		result = i;
	}
\end{verbatim}
which was itself populated earlier by \code{calculateOpticalDepth} via
Eq.~\eqref{eq:tau_total}.

\begin{keyresult}
	A subtle but important implementation detail: only
	the numerator of the subgroup-selection CDF is computed locally; the
	denominator is read from \code{ph->total\_scattering\_opacity}, which
	must therefore have been correctly (re-)computed by a prior call to
	\code{calculateOpticalDepth} for the selection probabilities
	\eqref{eq:subgroup_prob} to be consistent. Any code path that mutates
	\code{ph->scattering\_opacity} or \code{ph->scattering\_bias} without
	also updating \code{ph->total\_scattering\_opacity} risks a numerator/
	denominator mismatch in this function.
\end{keyresult}

Once the subgroup is selected, an individual electron is sampled from
the appropriate distribution: the Maxwell--J\"{u}ttner distribution for
thermal electrons via \code{singleThermalElectron}, or the power-law
distribution restricted to the Lorentz-factor range of the selected
subgroup via \code{singleNonThermalElectron} and
\code{calculateGammaSubgroup}.

\paragraph{The total optical depth and photon storage}
\label{sec:total_tau}

The total effective optical depth used to sample the next scattering
event is the sum over all components, each weighted by its bias:
\begin{equation}
	\tau_{\rm total} = \sum_{j=0}^{\code{N\_GAMMA}} b_j\,\tau_j,
	\label{eq:tau_total}
\end{equation}
where $j = 0$ is the thermal component (zero if no thermal electrons are
present) and $j = 1,\ldots,\code{N\_GAMMA}$ are the non-thermal subgroups.
This biased total optical depth is stored in
\code{ph->total\_scattering\_opacity} and used to compute the MFP via:
\begin{equation}
	\mathrm{mfp} = \frac{-\ln u}{\tau_{\rm total}}, \qquad
	u \sim \mathcal{U}(0,1).
	\label{eq:mfp_total_opacity}
\end{equation}

\begin{implementationnote}
	Two indexing conventions coexist and must not be confused. The
	\emph{hot cross-section table} \eqref{eq:hot_xsection_nth} has exactly
	\code{N\_GAMMA} nonthermal columns, indexed $k=1,\ldots,\code{N\_GAMMA}$,
	with no thermal entry. The \emph{photon-struct opacity and bias arrays}
	(\code{ph->scattering\_opacity}, \code{ph->scattering\_bias}) have
	$1+\code{N\_GAMMA}$ slots, indexed $j=0,\ldots,\code{N\_GAMMA}$, where
	slot $j=0$ is the thermal population (zero when no thermal electrons are
	present) and $j=1,\ldots,\code{N\_GAMMA}$ map onto nonthermal subgroup
	$k=j$. Hence the selection and total-$\tau$ loops run to $\code{N\_GAMMA}+1$
	entries, as in the quoted \code{generateSingleElectron} code.
\end{implementationnote}

The individual optical depths \code{ph->scattering\_opacity[j]} and bias
parameters \code{ph->scattering\_bias[j]} are stored on each photon struct
so that when a scattering event occurs, the correct subgroup can be
selected via \eqref{eq:subgroup_prob} and the weight correction
\eqref{eq:w_scattered} can be applied using the correct per-subgroup
quantities.

\paragraph{Summary of the optical depth calculation}
\label{sec:tau_summary}

The full optical depth calculation in \code{calculateOpticalDepth}
(\code{optical\_depth.c}) proceeds as follows each time
\code{recalc\_properties}$=1$:

\begin{enumerate}[leftmargin=2em]
	\item Compute
	\(\code{fluid\_factor}=1-\beta\cos\theta\)
	from the lab-frame photon and fluid directions. The factor \(\Gamma\)
	is not included in this variable: it enters through the lab-frame
	electron density for scattering and is multiplied separately in
	\code{calculateOpticalDepthSSA} for absorption.
	
	\item Look up the normalised cross section $\sigma/\sigma_T$ from
	the precomputed table via \code{getCrossSection}, which calls
	\code{getThermalCrossSection} and (if applicable)
	\code{getNonThermalCrossSection}.
	
	\item \textit{If thermal electrons are present:} compute the thermal
	optical depth $\tau_0 = n_{e,\mathrm{th}}^{(\mathrm{lab})}\,\sigma_T\,
	(\sigma/\sigma_T)\,\mathrm{fluid\_factor}$; compute the thermal bias
	$b_0 = b_{\rm th}$ via \eqref{eq:thermal_bias} using $\tau_0$ as
	$\tau_{\rm max}$; store in \code{ph->scattering\_opacity[0]} and
	\code{ph->scattering\_bias[0]}.  Set $\tau_{\rm ref} = \tau_0$ and
	$b_{\rm ref} = b_{\rm th}$ for use in step 4.
	
	\item \textit{If no thermal electrons are present:} compute
	$\tau_{\rm nth,total} = \sum_k \tau_k$ \eqref{eq:ref_nonthermal};
	compute $b_{\rm ref}$ from $\tau_{\rm nth,total}$ via
	\eqref{eq:bref_nonthermal}; set $\tau_{\rm ref} =
	\tau_{\rm nth,total}/\code{N\_GAMMA}$ \eqref{eq:ref_nonthermal}.
	Set \code{ph->scattering\_opacity[0]} $= 0$ and
	\code{ph->scattering\_bias[0]} $= 0$.
	
	\item For each non-thermal subgroup $k = 1,\ldots,\code{N\_GAMMA}$,
	compute $\tau_k$ \eqref{eq:kappa_nth_k} and bias $b_k$
	\eqref{eq:nonthermal_bias} using $b_{\rm ref}$ and $\tau_{\rm ref}$
	from the appropriate branch above; store in
	\code{ph->scattering\_opacity[k]} and \code{ph->scattering\_bias[k]}.
	
	\item Compute $\tau_{\rm total}$ \eqref{eq:tau_total} and store in
	\code{ph->total\_scattering\_opacity}.
	
	\item Compute the SSA absorption coefficient and store in
	\code{ph->absorption\_opacity} \eqref{eq:abs_od_full}
	(Section~\ref{sec:calc_od}).
\end{enumerate}

All seven steps are triggered by a single flag
\code{recalc\_properties}$=1$, which is set whenever the photon enters
a new cell or undergoes a scattering event.  After a biased scattering,
the scattered copy of the packet has \code{recalc\_properties}$=1$ set
so that its optical depths and bias parameters are freshly computed in
the new cell it finds itself in after the scattering event.

\subsubsection{Russian Roulette for Low-Weight Packets}
\label{sec:roulette}
% ??????????????????????????????????????????????????????????????????????????????

\paragraph{The problem: exponentially small weights}

As a \code{SYNCH\_PHOTON} packet propagates through an optically thick
region, the continuous absorption in \code{applyAbsorption} reduces its
weight exponentially:
\begin{equation}
	w(l) = w_0 \exp\!\left(-\int_0^l \Gamma(1-\beta\cos\theta)\,
	\alpha_{\nuf}^{(f)}\,dl'\right).
\end{equation}
After traversing sufficient optical depth the weight may fall many orders
of magnitude below its birth value $w_0$.  Such a packet contributes
negligibly to any observable yet still occupies a slot in
\code{photon\_list} and is processed at every scattering and transport
step ? a waste of computational resources.

\paragraph{Russian roulette: theory}

Russian roulette is the standard Monte Carlo technique for culling
low-weight particles while preserving the statistical unbiasedness of
the simulation.  The essential constraint is:

\begin{keyresult}
	The expected total weight of the photon population must be conserved by
	the roulette procedure: $\mathbb{E}[w_{\rm after}] = w_{\rm before}$.
\end{keyresult}

Given a weight threshold $w_{\rm thresh}$, for any packet with
$w < w_{\rm thresh}$ we define the survival probability:
\begin{equation}
	P_{\rm surv} = \frac{w}{w_{\rm thresh}} \in (0,\,1).
	\label{eq:p_surv}
\end{equation}
A uniform random variate $u \sim \mathcal{U}(0,1)$ is drawn:
\begin{itemize}
	\item If $u < P_{\rm surv}$: the packet \textbf{survives} and its
	weight is boosted to $w_{\rm thresh}$.
	\item If $u \ge P_{\rm surv}$: the packet is \textbf{killed} and
	removed from the simulation.
\end{itemize}
The expected weight after the procedure is:
\begin{equation}
	\mathbb{E}[w_{\rm after}]
	= P_{\rm surv} \cdot w_{\rm thresh}
	+ (1 - P_{\rm surv}) \cdot 0
	= \frac{w}{w_{\rm thresh}} \cdot w_{\rm thresh}
	= w. \quad \checkmark
	\label{eq:rr_unbiased}
\end{equation}
This is exactly unbiased for any choice of $w_{\rm thresh}$.  All
surviving packets emerge with weight exactly $w_{\rm thresh}$, producing a common weight among packets that survive that roulette pass.
The procedure trades a reduced packet count for additional sampling
variance while preserving the expected packet weight.

\paragraph{Adaptive threshold via the median weight}

Rather than using a fixed threshold, \mcrat{} computes $w_{\rm thresh}$
adaptively from the current population of live \code{SYNCH\_PHOTON}
packets.  The \emph{median} weight $w_{\rm median}$ of all live
\code{SYNCH\_PHOTON} packets is computed, and the threshold is set as:
\begin{equation}
	w_{\rm thresh} = \varepsilon_{\rm RR} \times w_{\rm median},
	\label{eq:w_thresh}
\end{equation}
where $\varepsilon_{\rm RR}$ = \code{RR\_WEIGHT\_FRACTION} is a small
dimensionless parameter set at compile time (typical value $10^{-2}$).

The median is chosen over the mean for two reasons:
\begin{enumerate}
	\item It is \textbf{robust to outliers}: rebinning events (see
	Section~\ref{sec:rebin}) produce a small number of high-weight
	packets that would inflate the mean but do not shift the median.
	\item It is \textbf{self-adapting to the absorption history}: in
	strongly absorbed regions the median weight is already depressed, so
	the threshold is correspondingly lower and fewer packets are culled
	than in weakly absorbed regions.
\end{enumerate}

The threshold $w_{\rm thresh}$ is computed \emph{once} from a snapshot
of the current population before any packet is modified, so it is a
fixed constant for the entire roulette pass.  This is essential for
unbiasedness: if $w_{\rm thresh}$ were updated during the pass, the
expected weight conservation \eqref{eq:rr_unbiased} would no longer hold.

\paragraph{Relationship to rebinning}
\label{sec:rebin}

The \code{photon\_list} structure has a fixed capacity.  When the
number of live packets approaches a user-set maximum, the existing
rebinning mechanism merges groups of packets into fewer representative
packets by computing weighted averages of their momenta and positions,
with the merged packet carrying the sum of the original weights.
Rebinning is a many-to-one operation that controls the list size but
introduces discretisation error in the phase-space distribution.

Russian roulette is complementary: it is a one-to-zero operation that
removes individual low-weight packets, freeing slots for future
injections without any reallocation.  The two mechanisms operate on
opposite ends of the weight distribution:

\begin{center}
	\renewcommand{\arraystretch}{1.3}
	\begin{tabular}{lll}
		\toprule
		& \textbf{Russian roulette} & \textbf{Rebinning} \\
		\midrule
		Targets      & Low-weight packets           & All active packets \\
		Operation    & Kill or boost individually   & Merge groups \\
		Statistical bias & None (exactly unbiased)  & Small (phase-space error) \\
		Triggered by & $w < w_{\rm thresh}$        & List near capacity \\
		\bottomrule
	\end{tabular}
\end{center}

\vspace{0.5em}
Russian roulette is applied \emph{before} the rebinning check at the
same checkpoint (every 1000 scatterings).  By continuously removing
low-weight packets, roulette reduces the pressure on the list capacity,
meaning the rebinning trigger is reached less frequently or not at all in
strongly absorbed regions.

\paragraph{Implementation (\texttt{applyRussianRoulette})}
\label{sec:rr_impl}

The per-population roulette logic (median computation, threshold, and
kill/survive decision) is implemented in
\code{applyRussianRouletteByType}, located in \code{mclib.c} alongside
the \code{global\_thread\_rng} pool it uses for OpenMP-parallel random
number generation:

\begin{verbatim}
	int applyRussianRouletteByType(struct photonList *photon_list,
	double             epsilon_rr,
	char               photon_type,
	FILE              *fPtr);
\end{verbatim}

This function implements exactly the three-step procedure described
below (weight collection, median/threshold computation, and the
roulette pass) for a single, caller-specified \code{photon\_type}, and
returns the number of packets of that type killed.

The wrapper function actually invoked from the main transport loop,
\code{applyRussianRoulette}, calls
\code{applyRussianRouletteByType} \emph{three times}, once for each of
the photon types whose weight can be driven to very small values by
continuous SSA absorption or by scattering into low-weight populations:

\begin{verbatim}
	int applyRussianRoulette(struct photonList *photon_list,
	double             epsilon_rr,
	FILE              *fPtr)
	{
		#if SYNCHROTRON_SWITCH == ON
		int n_killed=0;
		n_killed = applyRussianRouletteByType(photon_list, epsilon_rr,
		SYNCH_PHOTON, fPtr);
		n_killed = applyRussianRouletteByType(photon_list, epsilon_rr,
		INJECTED_PHOTON, fPtr);
		n_killed = applyRussianRouletteByType(photon_list,
		1e-8*epsilon_rr,
		COMPTONIZED_PHOTON, fPtr);
		return n_killed;
		#endif
	}
\end{verbatim}

\begin{itemize}
	\item \code{SYNCH\_PHOTON} packets are rouletted with the
	user-supplied threshold fraction $\varepsilon_{\rm RR} =
	\code{RR\_WEIGHT\_FRACTION}$, as described throughout this section.
	\item \code{INJECTED\_PHOTON} packets are also rouletted with
	$\varepsilon_{\rm RR}$: these can acquire very small weights after
	Compton scattering off the non-thermal power-law electron
	population (Section~\ref{sec:bias}), independent of SSA.
	\item \code{COMPTONIZED\_PHOTON} packets are scattered child packets created
	during biased Compton scattering. This type includes SSC photons but is
	not limited to synchrotron-seeded packets. These packets are rouletted with a threshold
	fraction reduced by an additional factor of $10^{-8}$ relative to
	$\varepsilon_{\rm RR}$. This deliberately more permissive threshold
	prevents the roulette procedure from prematurely culling the
	high-energy SSC spectral tail, which is astrophysically important
	but statistically underpopulated; the specific factor was tuned
	against the broken-power-law SSC test case described in
	\citet[Fig.~11]{kawashima2023}.
\end{itemize}

\begin{keyresult}
	\code{applyRussianRoulette} is a thin wrapper
	around three separate calls to \code{applyRussianRouletteByType}
	(for \code{SYNCH\_PHOTON}, \code{INJECTED\_PHOTON}, and
	\code{COMPTONIZED\_PHOTON}), and the local variable \code{n\_killed} is
	\emph{overwritten} rather than accumulated on each call. The function's
	return value therefore reflects only the kill count from the
	\emph{last} call, i.e.\ the \code{COMPTONIZED\_PHOTON} pass ? which is
	also the value used by the caller to decide whether SSC-photon
	rebinning is required ? not a cumulative kill count across all three
	photon types.
\end{keyresult}

With this clarification, the remainder of this subsection describes the
internal three-step procedure of \code{applyRussianRouletteByType} for
a single photon type and a single threshold $\varepsilon_{\rm RR}$.

\paragraph{Step 1 (parallel): collect weights.}
Each OpenMP thread fills its own local weight sub-array by scanning its
assigned portion of \code{photon\_list}.  After the parallel region the
sub-arrays are merged serially into a single flat array.  Using
per-thread sub-arrays avoids any shared-write contention on a single
array.

\paragraph{Step 2 (serial): compute median and threshold.}
The merged weight array is sorted in ascending order using
\code{gsl\_sort}.  The median is:
\begin{equation}
	w_{\rm median} = \begin{cases}
		\mathrm{weights}[n/2] & n \text{ odd}, \\
		\tfrac{1}{2}\bigl(\mathrm{weights}[n/2-1]
		+ \mathrm{weights}[n/2]\bigr) & n \text{ even},
	\end{cases}
	\label{eq:median}
\end{equation}
where $n$ is the number of live \code{SYNCH\_PHOTON} packets.  The
threshold is then $w_{\rm thresh} = \varepsilon_{\rm RR} \times
w_{\rm median}$ \eqref{eq:w_thresh}.

\paragraph{Step 3 (parallel): roulette pass.}
Each thread processes its assigned portion of the photon list.  For each
\code{SYNCH\_PHOTON} packet with $w < w_{\rm thresh}$, a uniform variate
is drawn from the thread-local RNG \code{global\_thread\_rng[thread\_id]}
and the kill/survive decision \eqref{eq:p_surv} is applied.  Surviving
packets have their weight boosted to $w_{\rm thresh}$.  Killed packets
are removed via \code{setNullPhoton}, which frees the slot for future
injections.  The photon list counters
(\code{num\_photons}, \code{num\_null\_photons}) are updated inside a
\code{\#pragma omp critical} section to prevent race conditions from
concurrent kills by different threads.

\paragraph{Implementation properties and current limitations}

\begin{enumerate}
	\item The physical photon production rate $\Lambda_i$ \eqref{eq:W_cell}
	is computed exactly via $K_{\rm phys}$ \eqref{eq:Kphys}, with no free
	proportionality constants.
	
	\item The full relativistic frame correction $\Gamma(1-\beta\cos\theta)$
	\citep{abramowicz1991} is assembled consistently for both scattering and
	SSA absorption within \code{calculateOpticalDepth}, but via two
	distinct mechanisms: for \emph{scattering}, the $\Gamma$ factor is
	absorbed into the lab-frame electron density
	\eqref{eq:nth_lab} before the cross-section lookup; for \emph{SSA},
	$\Gamma$ is instead multiplied directly onto the absorption
	coefficient $\alpha_{\nuf}^{(f)}$, which is itself evaluated at the
	comoving-frame density \eqref{eq:abs_od_full}. In both cases
	$(1-\beta\cos\theta)$ is applied via the shared \code{fluid\_factor}
	\eqref{eq:fluid_factor_code}, keeping the Doppler-factor arithmetic
	in one place even though the two processes distribute the $\Gamma$
	factor differently.
	
	\item The per-subgroup bias scheme is \emph{designed} to assign each
	electron population a bias $b_j$ such that all populations contribute
	equally to $\tau_{\rm total}$ \eqref{eq:tau_total_correct}, giving equal
	subgroup selection probability. In the mixed thermal and non-thermal
	case the thermal optical depth serves as the reference anchor
	\eqref{eq:ref_thermal}; in the purely non-thermal case the equal-share
	optical depth $\tau_{\rm nth,total}/\code{N\_GAMMA}$ serves as the
	reference \eqref{eq:ref_nonthermal}. The $\max(1,\ldots)$ floor in
	\eqref{eq:nonthermal_bias} is \emph{intended} to prevent any subgroup
	bias from falling below unity, which would produce unphysical negative
	unscattered weights; however, as detailed in the erratum in
	Section~\ref{sec:nonthermal_bias}, this floor is currently disabled in
	\code{calculateNonthermalScatteringBias}, so this guarantee does not
	hold for the default runtime behaviour as shipped.
	
	\item The scattered photon weight is corrected using only the
	per-subgroup biased optical depth $b_j\,\tau_j\,dl$
	\eqref{eq:w_scattered}, not the total biased optical depth.  This
	ensures that the weight correction is precisely matched to the
	artificial enhancement applied to each subgroup independently,
	preserving the unbiasedness of the estimator \eqref{eq:estimator_extensive}
	across all electron populations simultaneously.
	
	\item The Russian roulette procedure is exactly unbiased
	\eqref{eq:rr_unbiased} and uses an adaptive threshold
	\eqref{eq:w_thresh} that self-calibrates to the absorption history of
	the live photon population. The wrapper \code{applyRussianRoulette}
	applies this procedure independently to three photon types
	(\code{SYNCH\_PHOTON}, \code{INJECTED\_PHOTON}, and
	\code{COMPTONIZED\_PHOTON}, the last with a $10^{-8}\times$ reduced
	threshold to protect the SSC spectral tail; Section~\ref{sec:rr_impl}),
	and is invoked at two points per hydro frame: every 1000 scatterings, and at the end of eligible intermediate hydro
	frames. The end-of-frame pass is skipped for the initial scattering frame
	of a packet batch and for the final hydro frame. SSA absorption acts only during transport,
	never at photon birth, preserving the physical interpretation of the
	packet weight as the number of real photons at the moment of emission.
\end{enumerate}

\section{User-Defined Injection and Outflows}\label{custom}
\mcrat{} provides two hooks that allow a user to override the default behaviour of the code without modifying the core radiation-transfer routines. The first, contained in \texttt{custom\_spectrum.c}, lets the user inject photons with an arbitrary spectrum, 4-momentum, and polarization state instead of the built-in Wien or Blackbody spectra. The second, contained in \texttt{custom\_outflow.c}, lets the user impose an arbitrary analytic outflow onto the fluid quantities of each hydro frame, in the same spirit as the spherical and cylindrical test outflows described in Section \ref{algorithm}. Both capabilities are production-ready and are enabled through the switches described below.

\subsection{Custom Photon Injection (\texttt{custom\_spectrum.c})}\label{custom_spectrum}
The \texttt{custom\_spectrum.c} file provides the hook that \mcrat{} uses when the user wishes to inject photons drawn from a spectrum other than the built-in Wien or Blackbody spectra. It contains two functions: \texttt{custom\_spectrum} and \texttt{custom\_photon\_sampler}.

\subsubsection{How \mcrat{} Uses These Functions}
During photon injection, \mcrat{}'s \texttt{photonInjection} routine (in \texttt{mclib.c}) selects which spectrum to sample for each photon based on the spectrum type read from the \texttt{[MCRaT Photon Block]} of the \texttt{mc.par} file (see Section \ref{mc.par}). When the requested spectrum is neither Wien nor Blackbody, \mcrat{} falls through to the custom-spectrum branch and calls
\begin{quotation}
	\texttt{initialized\_photon = custom\_photon\_sampler(hydro\_data, i, rand, fPtr);}
\end{quotation}
for the $i^\mathrm{th}$ hydro element that photons are being injected into. The returned \texttt{photon} structure is then handed to the internal \texttt{saveUserDefinePhoton} routine, which performs all of the frame transformations, positioning, and bookkeeping that the user does \emph{not} need to supply. The number of photons to inject into each hydro element, and their positions, are still determined by \mcrat{} exactly as described in Section \ref{inj}; the custom sampler only governs the energy, direction, and polarization of each injected photon.

\subsubsection{The \texttt{custom\_photon\_sampler} Function}
The function has the signature
\begin{quotation}
	\texttt{struct photon custom\_photon\_sampler(struct hydro\_dataframe *hydro\_data, int hydro\_index, gsl\_rng *rand, FILE *fPtr);}
\end{quotation}
and its arguments are:
\begin{itemize}
	\item \texttt{hydro\_data} --- a pointer to the \texttt{hydro\_dataframe} structure for the current frame, giving the user access to all fluid quantities (temperature, density, velocity, pressure, magnetic field, coordinates, etc.) of every hydro element.
	\item \texttt{hydro\_index} --- the index of the hydro element that the photon is being injected into. The user accesses a fluid quantity for this element as, for example, \texttt{(hydro\_data->temp)[hydro\_index]}.
	\item \texttt{rand} --- the GSL random number generator that the user should use for any Monte Carlo sampling, so that the sampling is consistent with the rest of \mcrat{}'s (thread-safe) random number generation.
	\item \texttt{fPtr} --- the log file pointer for the calling MPI process, which the user may write diagnostics to.
\end{itemize}

The function must return a \texttt{struct photon}. The user should always begin by calling the provided helper
\begin{quotation}
	\texttt{struct photon custom\_photon = createPhoton();}
\end{quotation}
which returns a \texttt{photon} structure with every field initialized to \texttt{NaN} (with the exception of a few internal bookkeeping fields). Initializing every physical field to \texttt{NaN} is deliberate: it allows \mcrat{} to detect precisely which fields the user has overwritten and to fill in the remaining fields appropriately. The user then overwrites only the fields they wish to control, and returns the structure.

\subsubsection{What the User May Set, and the Contract with \mcrat{}}
The user may set \emph{any one} of the following, and \mcrat{} will consistently compute everything else:
\begin{itemize}
	\item \textbf{Energy only.} Setting only the comoving photon energy, \texttt{custom\_photon.comv\_p0}, (or the lab-frame energy, \texttt{custom\_photon.p0}) fixes the photon energy while allowing \mcrat{} to assign the angular direction of the 4-momentum using its default isotropic-in-the-comoving-frame prescription (Section \ref{inj}). This is the most common use case and is what the example implementation does.
	\item \textbf{Full 4-momentum.} Setting either the full comoving 4-momentum (\texttt{comv\_p0}, \texttt{comv\_p1}, \texttt{comv\_p2}, \texttt{comv\_p3}) or the full lab-frame 4-momentum (\texttt{p0}, \texttt{p1}, \texttt{p2}, \texttt{p3}) fixes both the energy and direction of the photon.
	\item \textbf{Polarization.} Setting the Stokes parameters (\texttt{s0}, \texttt{s1}, \texttt{s2}, \texttt{s3}) fixes the initial polarization state of the photon.
\end{itemize}

\mcrat{} honours the following contract when processing the returned photon:
\begin{itemize}
	\item If the user specifies the 4-momentum in \emph{either} the lab frame or the comoving (fluid) frame, \mcrat{} automatically computes the 4-momentum in the other frame by performing the appropriate Lorentz boost using the velocity of the fluid element indexed by \texttt{hydro\_index}. The user therefore only needs to supply the 4-momentum in whichever frame is most convenient.
	\item The 4-momentum must use the normalizations and units expected by \mcrat{}, namely components of \texttt{p0}, \texttt{p1}, \texttt{p2}, and \texttt{p3} in units of erg/c, consistent with the saved quantities described in Section \ref{algorithm}.
	\item For the Stokes parameters, \mcrat{} expects the normalized convention described in Section \ref{pol}, with $\mathtt{s0}=I/I=1$ and $\mathtt{s1}=q=Q/I$, $\mathtt{s2}=u=U/I$, $\mathtt{s3}=v=V/I$. \mcrat{} additionally validates that the supplied Stokes vector is physical by requiring
	\[
	\mathtt{s0}^2 \ge \mathtt{s1}^2 + \mathtt{s2}^2 + \mathtt{s3}^2.
	\]
	If the user does not set the Stokes parameters, the photon is injected unpolarized, with $s=(1,0,0,0)$, exactly as for the built-in spectra.
\end{itemize}

\subsubsection{The \texttt{custom\_spectrum} Helper Function}
The \texttt{custom\_spectrum.c} file also provides a convenience function
\begin{quotation}
	\texttt{double custom\_spectrum(double frequency);}
\end{quotation}
that evaluates the \emph{shape} of a user-defined spectrum at a given frequency (in Hz). The example implementation provided in the file returns a Gaussian line profile centred at 6.4 keV, i.e.
\[
f(\nu) \propto \exp\!\left(-\frac{(\nu-\nu_0)^2}{2\sigma^2}\right),
\]
with the profile set to zero outside $\pm 6\sigma$ of the line centre $\nu_0$. The function returns the \emph{unnormalized} spectral shape (i.e.\ it omits the $1/(\sigma\sqrt{2\pi})$ prefactor), since only relative probabilities are required for sampling. The user is expected to replace the body of this function with their own desired spectral shape and to call it from within \texttt{custom\_photon\_sampler} using an acceptance--rejection Monte Carlo sampling scheme (as is used throughout \mcrat{}; see Section \ref{inj}) in order to draw a frequency, convert it to an energy via $E=h\nu$, and assign it to the returned photon.

\subsubsection{A Minimal Example}
The default implementation shipped with \mcrat{} samples a frequency from a fixed-temperature Blackbody photon-number spectrum by acceptance--rejection sampling and assigns only the comoving energy:
\begin{quotation}
	\texttt{custom\_photon.comv\_p0 = fr\_dum * PL\_CONST / C\_LIGHT;}
\end{quotation}
where \texttt{fr\_dum} is the sampled frequency in Hz. Because only \texttt{comv\_p0} is set, \mcrat{} assigns the photon's direction using its default prescription and computes the lab-frame 4-momentum by boosting with the fluid velocity of the element. A user wishing to inject, for instance, the 6.4 keV Gaussian line described above would instead sample \texttt{custom\_spectrum} within the acceptance--rejection loop and set \texttt{comv\_p0} to the corresponding energy.

\subsubsection{Enabling Custom Photon Injection}
To use the custom photon sampler, the user sets the spectrum type in the first line of the \texttt{[MCRaT Photon Block]} of the \texttt{mc.par} file to \texttt{c} (or, in fact, to any character other than \texttt{w} for Wien or \texttt{b} for Blackbody: \mcrat{}'s \texttt{photonInjection} routes every non-Wien, non-Blackbody spectrum code to \texttt{custom\_photon\_sampler} through its fall-through branch). This causes \texttt{photonInjection} to route photon generation through \texttt{custom\_photon\_sampler}, as described above. The minimum and maximum numbers of photons and all other \texttt{mc.par} entries behave exactly as described in Section \ref{mc.par}.

\subsection{Custom Analytic Outflows (\texttt{custom\_outflow.c})}\label{custom_outflow}
The \texttt{custom\_outflow.c} file allows the user to impose an arbitrary analytic outflow onto the fluid quantities of each hydro frame. This mechanism is identical in spirit to the spherical and cylindrical outflow test problems described in Section \ref{algorithm}: \mcrat{} reads a hydro frame into memory and then overwrites the fluid quantities (in memory only, never in the hydro file on disk) with the values dictated by the user's analytic prescription. This lets the user explore idealized outflow structures, or impose a known analytic solution for validation, without needing a dedicated hydro simulation.

\subsubsection{The \texttt{customOutflowPrep} Function}
The file provides a single function with the signature
\begin{quotation}
	\texttt{void customOutflowPrep(struct hydro\_dataframe *hydro\_data, FILE *fPtr);}
\end{quotation}
whose arguments are:
\begin{itemize}
	\item \texttt{hydro\_data} --- a pointer to the \texttt{hydro\_dataframe} structure for the current frame. On entry, this structure has already been populated by \mcrat{} with the coordinates (\texttt{r0}, \texttt{r1}, \texttt{r2}), the spherical radius \texttt{r}, and the cell sizes of every hydro element, as read from the hydro file. The number of hydro elements is available as \texttt{hydro\_data->num\_elements}. On exit, the function is expected to have overwritten the fluid quantities of every element with the user's desired values.
	\item \texttt{fPtr} --- the log file pointer for the calling MPI process, which the user may write diagnostics to.
\end{itemize}The function loops over every hydro element, from \texttt{i=0} to \texttt{hydro\_data->num\_elements}, and, for each element, assigns the fluid quantities required by the rest of \mcrat{}. The fields that the user \emph{must} set for each element are:
\begin{itemize}
	\item \texttt{(hydro\_data->gamma)[i]} --- the bulk Lorentz factor of the fluid element.
	\item \texttt{(hydro\_data->dens)[i]} --- the comoving (fluid-frame) mass density of the element, in g cm$^{-3}$.
	\item \texttt{(hydro\_data->dens\_lab)[i]} --- the lab-frame mass density of the element. For a flow with bulk Lorentz factor $\Gamma$, this is $\rho\_\mathrm{lab}=\Gamma\rho$, where $\rho$ is the comoving density.
	\item \texttt{(hydro\_data->pres)[i]} --- the comoving pressure of the element. Consistent with the assumptions described in Section \ref{algorithm}, the pressure is taken to be radiation dominated, so it is related to the comoving temperature $T'$ by $p=\frac{1}{3}aT'^4$, where $a$ is the radiation density constant.
	\item \texttt{(hydro\_data->temp)[i]} --- the comoving temperature of the element, in Kelvin.
	\item \textbf{The velocity components.} The user must set the fluid three-velocity, normalized by the speed of light, in the components \texttt{(hydro\_data->v0)[i]}, \texttt{(hydro\_data->v1)[i]}, and (in 2.5D and 3D) \texttt{(hydro\_data->v2)[i]}. The components correspond to the coordinate directions of the chosen \texttt{GEOMETRY} (see the coordinate table in Section \ref{mc.par}). In the 2.5D case, the third velocity component must be explicitly set to zero.
\end{itemize}

\subsubsection{Consistency Requirements}
Because \mcrat{} builds the injected photon spectrum and the scattering physics directly from these fluid quantities, the user must ensure that the prescription is internally consistent:
\begin{itemize}
	\item The temperature and pressure must satisfy the radiation-dominated relation $p=\frac{1}{3}aT'^4$, since \mcrat{} assumes this throughout (Section \ref{algorithm}). The example implementation enforces this automatically by computing the pressure from the chosen comoving temperature.
	\item The lab-frame density \texttt{dens\_lab} must be consistent with the comoving density \texttt{dens} and the bulk Lorentz factor \texttt{gamma} via $\rho\_\mathrm{lab}=\Gamma\rho$.
	\item The velocity components, once normalized by $c$, must yield a speed $\beta<1$ that is consistent with the assigned \texttt{gamma}, i.e.\ $\Gamma=1/\sqrt{1-\beta^2}$.
	\item All velocities are expressed in units of $c$, matching the first assumption \mcrat{} makes about the hydro simulation (Section \ref{algorithm}).
\end{itemize}

\subsubsection{Interaction with the Magnetic Field, Non-Thermal Electrons, and Scattering Bias}\label{custom_outflow_nonthermal}
A critical intricacy arises when a custom outflow is combined with the non-thermal synchrotron/scattering machinery (i.e.\ when \texttt{NONTHERMAL\_E\_DIST} is set to a power-law or broken power-law distribution, and/or \texttt{SCATTERING\_BIAS\_SWITCH} is enabled). For every \emph{other} simulation type, \mcrat{} automatically derives the quantities needed by the non-thermal physics immediately after a hydro frame is read. For a custom outflow, however, part of this automatic derivation is deliberately \emph{skipped}, and the user's \texttt{customOutflowPrep} function becomes responsible for supplying the skipped quantities. Specifically, after reading (or, for a custom outflow, synthesizing) each frame, \mcrat{} executes the following logic in its \texttt{getHydroData} routine:
\begin{quotation}
	{\small
		\begin{verbatim}
			#if NONTHERMAL_E_DIST != OFF && SIMULATION_TYPE != CUSTOM_OUTFLOW
			calculateElectronDistSubgroupDens(hydro_data->electron_dens_subgroup, fPtr);
			calculateNonthermalElectronDens(hydro_data, fPtr);
			#endif
			#if SCATTERING_BIAS_SWITCH != OFF
			calculateAverageDimlessTheta(hydro_data, fPtr);
			#endif
		\end{verbatim}
	}
\end{quotation}

The key observation is that the first conditional block carries the additional guard \texttt{SIMULATION\_TYPE != CUSTOM\_OUTFLOW}, whereas the scattering-bias block does not. The consequences, which the user must account for, are as follows.

\paragraph{Non-thermal electron density is \emph{not} auto-populated.}
For all non-custom simulation types, \texttt{calculateNonthermalElectronDens} fills the per-cell non-thermal electron number density \texttt{hydro\_data->nonthermal\_dens} by equating a user-specified fraction (\texttt{NONTHERMAL\_CONVERSION\_FACTOR}) of the local magnetic energy density $B^2/8\pi$ to the rest-mass energy density of the non-thermal electron population; it also enforces a baryonic-loading sanity check that aborts the run if \texttt{NONTHERMAL\_CONVERSION\_FACTOR} is so large that the non-thermal electrons would carry more rest-mass energy than the magnetic field energy density. \textbf{For a custom outflow this routine is not called.} Therefore, if the user intends to use the non-thermal synchrotron emission or non-thermal scattering physics with a custom outflow, the user's \texttt{customOutflowPrep} function \emph{must itself} populate \texttt{hydro\_data->nonthermal\_dens[i]} for every hydro element \texttt{i}, in units of cm$^{-3}$ and in the comoving frame. If this field is left unset, it will retain whatever value it held previously (or its allocation default) and the non-thermal physics will produce meaningless results. The user is free to adopt the same prescription that \mcrat{} uses internally,
\[
n_{e,\mathrm{nth}}=f_e\,\frac{B^2/8\pi}{\langle\gamma\rangle m_e c^2},
\]
where $f_e$ is the fraction of magnetic energy density placed into the non-thermal electrons and $\langle\gamma\rangle$ is the mean Lorentz factor of the chosen distribution, or any other prescription appropriate to their problem.

\paragraph{The magnetic field must be provided by the user.}
Because the custom outflow bypasses the automatic non-thermal density calculation, and because that calculation is where \mcrat{} ordinarily evaluates the magnetic field via \texttt{getMagneticFieldMagnitude}, the user must ensure that whatever magnetic field their physics requires is consistent with how \texttt{B\_FIELD\_CALC} is set:
\begin{itemize}
	\item If \texttt{B\_FIELD\_CALC} is set to \texttt{INTERNAL\_E} or \texttt{TOTAL\_E}, \mcrat{} derives the magnetic field from the fluid internal/total energy density (see Section \ref{cyclo-synch}). In this case the user only needs to ensure that the fluid quantities they set in \texttt{customOutflowPrep} (in particular \texttt{pres}, \texttt{dens}, and \texttt{gamma}) are physically consistent, since the field is computed from them together with \texttt{EPSILON\_B}.
	\item If \texttt{B\_FIELD\_CALC} is set to \texttt{SIMULATION}, \mcrat{} expects the magnetic field components \texttt{hydro\_data->B0[i]}, \texttt{hydro\_data->B1[i]}, and (in 2.5D/3D) \texttt{hydro\_data->B2[i]} to be populated. Since a custom outflow has no underlying magnetohydrodynamic field to read, the user's \texttt{customOutflowPrep} function \emph{must} assign these components explicitly for every element, in Gaussian units, exactly as the PLUTO and FLASH readers do when \texttt{B\_FIELD\_CALC == SIMULATION}. The example \texttt{customOutflowPrep} shipped with \mcrat{} does \emph{not} set these components; this is a deliberate gap that the user must fill for their own outflow.
\end{itemize}

\paragraph{The non-thermal subgroup fractions are \emph{not} auto-populated.}
The companion routine \texttt{calculateElectronDistSubgroupDens} computes the array \texttt{hydro\_data->electron\_dens\_subgroup}, which holds the \emph{fraction} of the non-thermal electron distribution that lies within each of the \texttt{N\_GAMMA} Lorentz-factor subgroups (these fractions are later multiplied by the per-cell \texttt{nonthermal\_dens} to obtain the physical subgroup densities used in the scattering cross sections). This routine depends only on the compile-time distribution parameters (\texttt{POWERLAW\_INDEX}, \texttt{GAMMA\_MIN}, \texttt{GAMMA\_MAX}, etc.) and not on the hydro frame, so it is computed once per frame alongside the density. Because it sits inside the same guarded block, it too is skipped for a custom outflow. A user who requires the non-thermal subgroup densities with a custom outflow must therefore also populate \texttt{hydro\_data->electron\_dens\_subgroup} themselves, most conveniently by calling \texttt{calculateElectronDistSubgroupDens(hydro\_data->electron\_dens\_subgroup, fPtr)} from within \texttt{customOutflowPrep}, which reproduces exactly the behaviour that \mcrat{} applies for the non-custom simulation types.

\paragraph{The scattering-bias temperature average \emph{is} still computed.}
By contrast, the volume-averaged dimensionless temperature $\bar{\Theta}$, stored in \texttt{hydro\_data->average\_dimless\_theta} and used in computing the thermal scattering bias (Section \ref{cyclo-synch}), is computed by \texttt{calculateAverageDimlessTheta} under a guard that depends \emph{only} on \texttt{SCATTERING\_BIAS\_SWITCH} and carries \emph{no} custom-outflow exclusion. It is therefore evaluated normally for a custom outflow, using the temperatures that \texttt{customOutflowPrep} assigns. The user does not need to populate \texttt{average\_dimless\_theta} manually, but must ensure that the comoving temperatures they assign to \texttt{hydro\_data->temp} are physical, since the scattering bias (and hence the sampling of rare, high-energy scatterings) depends on them through $\bar{\Theta}$.

\paragraph{Summary of the user's additional responsibilities for a custom outflow.}
When using a custom outflow \emph{together with} the non-thermal and/or scattering-bias machinery, the user's \texttt{customOutflowPrep} function should, in addition to the standard fluid quantities listed above, set the following for every hydro element:
\begin{itemize}
	\item \texttt{hydro\_data->nonthermal\_dens[i]} --- the comoving non-thermal electron number density (never auto-populated for a custom outflow);
	\item \texttt{hydro\_data->B0[i]}, \texttt{B1[i]}, and (in 2.5D/3D) \texttt{B2[i]} --- the magnetic field components, \emph{only} if \texttt{B\_FIELD\_CALC == SIMULATION};
	\item \texttt{hydro\_data->electron\_dens\_subgroup} --- the per-subgroup distribution fractions, if the non-thermal scattering physics is used (most easily by calling \texttt{calculateElectronDistSubgroupDens} from within \texttt{customOutflowPrep}).
\end{itemize}
The quantity \texttt{hydro\_data->average\_dimless\_theta} is handled automatically and should \emph{not} be set by the user. Note also that, because \texttt{calculateNonthermalElectronDens} is skipped, the baryonic-loading sanity check on \texttt{NONTHERMAL\_CONVERSION\_FACTOR} that it performs is likewise skipped for a custom outflow; the user is responsible for ensuring that their chosen non-thermal electron density is physically sensible relative to the local magnetic energy density.

\subsubsection{The Example Implementation}
The implementation shipped with \mcrat{} provides a template analytic outflow and should be adapted by the user to their problem of interest. It defines a radial outflow characterized by a small number of parameters: an outflow slope parameter, a fixed comoving temperature corresponding to 3 keV, a mass-outflow normalization, an initial optical depth $\tau\_0$, and a base radius $r\_0$. From these it constructs, for each element, a radius-dependent velocity profile, a radius-dependent density profile, the corresponding bulk Lorentz factor $\Gamma=1/\sqrt{1-\beta^2}$, the radiation-dominated pressure from the fixed temperature, and the lab-frame density.\begin{quotation}
	\noindent \emph{Note on the slope parameter.} In the example template, the parameter named \texttt{beta} in the source is the \emph{density/velocity profile exponent}, and is \emph{not} the relativistic $\beta=v/c$. The relativistic velocity is computed separately from the velocity profile. A user adapting this template should take care not to conflate the two.
\end{quotation}The user is strongly encouraged to use this example as a starting point, replacing the analytic profiles with those appropriate to their science case, while retaining the overall structure of looping over every hydro element and assigning each of the required fluid quantities listed above.\subsubsection{Enabling the Custom Outflow}
To use a custom outflow, the user sets the \texttt{SIMULATION\_TYPE} parameter in the \texttt{mcrat\_input.h} file to \texttt{CUSTOM\_OUTFLOW} and recompiles the code. When this simulation type is selected, \mcrat{} calls \texttt{customOutflowPrep} immediately after reading each hydro frame into memory, so that the user's analytic fluid quantities replace those read from the hydro file before any photon injection, propagation, or scattering takes place. Because the geometry and coordinates of the underlying hydro frame are preserved, any hydro simulation file (for example, the same files used for the spherical or cylindrical test outflows) may be used as the coordinate scaffold onto which the custom outflow is imposed. All other aspects of running \mcrat{} --- the \texttt{mc.par} file, the parallelism, the output files, and the post-processing --- behave exactly as described in the preceding sections.
